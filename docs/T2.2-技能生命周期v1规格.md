# T2.2 · 技能生命周期 v1 规格（skill-registry 插件）

> 上游：《需求描述》v2.1 §3.3.3（自成长闭环：生成[元技能先验]→验证[rehearsal 回放+至少一次真实业务复用才晋升]→维护[registry+版本+写时冲突检测]→退役[连续N失败/被替代/N天未用+容量强制淘汰]；Elo 式能力评分；双环）、§3.6（技能行脏信号表+统一主生命周期）、§3.3.5（召回双路：能力召回走 L3 能力索引）、《T0.0》（DSH `ctx.skills` 底座判断：发现/rank/热更/渐进披露全有，缺验证晋升与退役）、T1.2（治理管道第四实例预埋）、T1.4（rehearsal 协议同款）、T0.7（fork seam）、T2.1（coach 候选 skill 通道 U5 履约方）。

## 1. 设计裁定

| # | 裁定 | 理由 |
|---|---|---|
| J1 | **技能 = 统一治理管道第四种资产实例**：lifecycle 全部登记 `ctx.governance`（assetKind=`'skill'`，兑现 T1.2 J1/T1.4 J1 预埋），本服务只定义技能特有 schema 与验证机制，**不造第二治理服务、不存第二 lifecycle**；实现时 `memory_gov_states` 并为 `gov_states` 按 kind 分区（T1.4 U6） | §3.6 明文"所有资产共享一条统一治理管道"；memory→meta-thinking→skill 三实例同构即管道通用性的持续验证； Ratchet 教训（LLM 自生成技能提升 +0.0）的解法在治理不在生成 |

| J3 | **双通道可见性**（§3.3.5 能力召回最小落地）：`validating`=能力召回注入池可见（带"验证中"标注，经 T0.4 injection 区由 Harness 提议使用）；`consolidated`=DSH skills 物化（模型可直接调用，渐进披露）；`draft`/`retired` 双通道均不可见。**与 T1.4 J6"未验证零注入"的差异裁定**：技能晋升判据本身要求一次真实业务复用（§3.3.3），复用前必须可见——rehearsal 已过+显式标注使该可见性安全（是提议非自动执行，结果回流 Elo/退役信号） | §3.3.3"至少一次真实业务复用后才晋升"与"未验证不可见"表面冲突；解法=可见性分级（召回提议通道 vs 调用通道），而非二选一；§3.3.5"能力召回走 L3 能力索引"的落地形态 |
| J4 | **外部验证阀双条件**（§3.3.3 验证行）：`consolidated` ⇔ ① rehearsal pass ∧ ② ≥1 次真实业务复用成功（任务终态 success 且该技能被 skill_usage_log 记录）；服务端断言缺一拒绝。**adopted-external 例外**：人类采纳 DSH 已安装技能的动作本身即外部验证阀（user-original 凭证、免 rehearsal、Elo 零起）——人类在环是阀的原始形态 | §3.3.3+横切"外部验证阀（固化不能靠 LLM 即时判断，须一次真实复用或评测回放）"；用户亲手安装的技能已过人工阀，与模型自产/coach 提炼区别对待（防把人类动作也机器怀疑=过度设计） |
| J5 | **rehearsal 协议复用不新造**：fork 到任务边界（T0.7 J6 seam）→ 子会话注入该技能试跑 → 判定 `outcome=success ∧ stepCoverage≥θ_cov`（skill 步骤在子会话 transition 链的覆盖率，transition 抽取复用 T1.3 extract）→ `skill_rehearsal_runs` 落盘（childSessionId/boundary/coverage/seq，判定可复算，同 T1.4 J5 协议）；**连续 rehearsal fail≥N（默认 3）→ 自动 retire[rehearsal-fail]**（受控实验证伪=直接证据，同 T1.4 J8，区别于记忆弱归因保守纪律） | §3.3.2/§3.3.3"回放验证才缓存/通过才允许固化"；T1.4 已立同款协议与判定确定性，技能侧 coverage 语义不同（procedure 步骤 vs 拓扑步骤）故独立落表、协议不复制第二套 fork 逻辑 |
| J6 | **真实复用记账走旁路**（append-only `skill_usage_log`，同 T1.1 recall_log 模式）：每次真实使用记 skillId/taskId/outcome/Elo 前后值；治理 scan、容量排名、unused-days 信号全部聚合自此表，**不动任何权威表** | 复用信号是治理输入不是事实（同 T1.1 J7 纪律）；Elo 复算与退役归因都需要使用史 |
| J7 | **Elo 简化在线评分**（§3.3.3"Elo 式能力评分，通过才进入正式能力库"）：R 初值 1500，`R' = R + K·(S − E)`，`E = 1/(1+10^((baseline−R)/400))`，S∈{1, 0.5, 0}（success/partial/failure），K 可配默认 24；v1 = win-rate 平滑版（诚实标注），**完整两两对赌（同任务多技能对比/跨模型对比）与跨资产统一评分归 T2.3**（U3）；Elo 归一化后进治理分（容量淘汰排名项） | §3.3.3 原文要求能力评分；无对手对赌时退化为在线评分是工程诚实（不装完整 Elo）；评分必须可复算（不变量 7） |
| J8 | **退役四信号+manual**（§3.6 技能行原文）：`rehearsal-fail`（连续 N 次 rehearsal 失败，自动）/`use-fail`（连续 N 次真实复用失败，**中途一次 success 清零连续计数**，滞回防误杀）/`superseded`（消费 supersede 链，同 T1.2 J7）/`unused-days`（usage_log 无记录超 N 天）/`capacity`（活跃数超帽强制淘汰最低治理分）+`manual`（人工/coach）；**退役必须实际承重**（G2-① Ratchet：退役触发过 + 退役后双通道不可见） | §3.6"连续N次失败/被替代/N天未用→退役；活跃容量上限强制淘汰"原文；技能失败归因强于记忆（rehearsal 前置验证+受控判定），故 use-fail 可自动判（区别于 T1.2 J7 记忆保守口径） |
| J9 | **写时冲突检测三型 + 前置依赖 DAG**（Voyager 铁律 1+§3.6 维护行）：①同名 propose 拒绝（name 是稳定标识）②applicability 重叠+procedure 相似 → 标 near-dup ③applicability 重叠+关键动作矛盾（avoid/prefer 互斥）→ conflict 记录；**只检测标记不隐藏裁决**（同 T1.2 J9），收敛经显式 supersede；composite 技能的 prerequisites 必须全部 consolidated 才可 rehearse/consolidate（服务端断言）；退役前置技能时标记 dependents，**不级联删除** | §3.6"写时冲突检测"原文；Voyager"每个前置技能必须已在库中"铁律；级联删=隐藏写路径，破坏可回放 |
| J10 | **技能 ≠ 编排定义**（C3 边界）：`skill.procedure` = 能力单元的**操作序列**（步骤=动作分类+contract 引用），不是任务编排/控制流；目标完成后的**分层流程模板回写归 T2.5** 工作流模板——防 T2.2 长成影子编排器 | §3.1.4"流程抽象为分层模板回写资产库"与 §3.3.3 技能提炼是两条资产线；C3"编排逻辑是持久化可执行定义"归工作流执行器（T2.5），技能只是被执行/被调用的能力单元 |
| J11 | **生成三路**（§3.3.3 生成行+§3.4.5）：①coach 候选（T2.1 `kind='skill'` 通道，T2.1 记 deferred，**本规格履约** propose/rehearse/晋升接口）②人工起草 ③轨迹提炼（`extractFromTrajectory`：成功任务 transition 链→procedure 骨架机械抽取[动作序列+argClass]，coach/人修订——同 T1.4 J4 两段式，保轨迹根基不装全自动） | §3.3.3"技能从执行轨迹提炼（非仅从笔记文本）"；T2.1 J4 已定 skill 候选分流，本规格是落地方 |
| J12 | **容量与多样性**：活跃（consolidated）技能数帽 P0 默认 50；80% 压力区→提议退役（unused-days/低治理分），100%→强制淘汰治理分最低者；治理分 = `eloNorm·0.4 + reuseCount·0.3 + recency·0.3`（P0 权重可配）；同 taskClass 注入候选 Top-K（默认 3）防单一技能垄断注入区（同 T1.4 J10 精神） | §3.6"活跃容量上限强制淘汰"；90 天长程技能增长无帽=能力库复利垃圾（Ratchet）；淘汰可解释（不变量 5） |

## 2. 状态模型

```
propose（coach 候选/人工/轨迹提炼）──► draft ──rehearse──► pass？
                                                   ├─ 否 ─► consecutiveRehearsalFail++（≥N → 自动 retire[rehearsal-fail]）
                                                   └─ 是 ─► validating ──logUse 真实复用成功 ≥1──► requestConsolidate ──► consolidated
                                                            │（召回通道可见·带标注）                        │（DSH skills 物化·模型可调用）
adoptExternal（人类采纳 DSH 技能）────────────────────────────────────────► validating ──(人工即阀)──► consolidated
任何态 ──retire[use-fail/superseded/unused-days/capacity/manual]──► retired ──restore(人工)──► consolidated
supersede ──► 新版 draft + 旧版 retire[superseded]（治理管道，同 T0.3 精神）
```

- **lifecycle 归治理管道**（J1）：本图状态即 §3.6 主生命周期的技能口径（草稿→验证中→已固化/已发布→已退役；consolidated 即发布=DSH skills 物化，J2）；
- rehearsal/真实复用/退役信号全部经 `skill_usage_log`/`skill_rehearsal_runs` 旁路落盘，治理 scan（T1.2）周期消费；
- 回放确定性：Elo 与覆盖率判定输入全落盘，可复算（不变量 7）。

## 3. 数据模型

### 3.1 `Skill`（资产本体）

```ts type-equiv
/** 能力单元。procedure=操作序列（非编排定义，J10）；零原文泄漏（不变量 5）。 */
interface Skill {
  readonly id: SkillId                       // branded，sk-<n>
  readonly name: string                      // 稳定名 kebab-case（同名冲突拒绝，J9）
  readonly summary: string                   // ≤120 字符一句话（DSH 渐进披露 description）
  readonly kind: 'procedure' | 'composite'
  readonly procedure: {
    readonly steps: { action: string; argClass?: string; contractRef?: string }[]   // action=工具/子代理分类，禁参数值
    readonly prerequisites: SkillId[]        // Voyager 铁律 1：前置必 consolidated（J9）
  }
  readonly applicability: { taskClasses: string[]; stages: TaskNode['stage'][]; problemFeatures: string[] }
  readonly source: {
    readonly kind: 'coach-candidate' | 'human' | 'trajectory-extract' | 'external-adopted'
    readonly refs: { sessionId: SessionId; seqFrom: number; seqTo: number }[]       // 来源轨迹（T0.7 audit_index 同模式）
  }
  readonly credential: TimelineEntry['credential']   // §3.6 统一元数据
  readonly stats: {
    readonly rehearsalPass: number
    readonly rehearsalFail: number
    readonly consecutiveRehearsalFail: number
    readonly realUse: number
    readonly consecutiveUseFail: number
    readonly elo: number                     // J7 简化在线评分
  }
  readonly version: number                   // §3.6 统一元数据
  readonly supersedes?: SkillId              // 版本链（同 T0.3 supersede 精神）
  readonly conflict?: { with: SkillId[]; kind: 'near-dup' | 'contradiction'; detectedAt: number }   // J9 只标不裁
  readonly dependents?: SkillId[]            // 被哪些 composite 依赖（退役时标记，J9）
  readonly createdAt: number
  readonly updatedAt: number
}
```

### 3.2 `SkillRehearsalRun` / `SkillUse`（验证史+使用史，append-only）

```ts type-equiv
/** 一次 rehearsal 试跑记录。判定输入全落盘=可复算（J5，同 T1.4 协议）。 */
interface SkillRehearsalRun {
  readonly id: RehearsalId                   // reh-<n>
  readonly skillId: SkillId
  readonly taskId: TaskId
  readonly childSessionId: SessionId         // T0.7 fork 子会话
  readonly boundary: { sessionId: SessionId; eventKind: string; seq: number }
  readonly verdict: 'pass' | 'fail'
  readonly coverage: number                  // skill 步骤在子会话 transition 链覆盖率
  readonly outcome: 'success' | 'failure'
  readonly at: number
}

/** 一次真实复用记账。Elo 复算依据（J6/J7）。 */
interface SkillUse {
  readonly id: SkillUseId                    // su-<n>
  readonly skillId: SkillId
  readonly taskId: TaskId
  readonly sessionId: SessionId
  readonly outcome: 'success' | 'failure' | 'partial'
  readonly eloBefore: number
  readonly eloAfter: number
  readonly k: number                         // 当时 K 值（复算必需）
  readonly at: number
}
```

### 3.3 SQLite schema（`ctx.storage` sqlite domain，DomainSpec）

| 表 | 键 | 值 | 说明 |
|---|---|---|---|
| `skills` | SkillId | Skill 全量 | 资产本体；append-only 语义（supersede 不改旧版） |
| `skill_rehearsal_runs` | RehearsalId | SkillRehearsalRun | append-only 验证史 |
| `skill_usage_log` | SkillUseId | SkillUse | append-only 使用史（Elo/退役信号源） |
| `skill_params` | `'singleton'` | { thetaCov, maxConsecutiveRehearsalFail: 3, maxConsecutiveUseFail, unusedDays, maxActiveSkills: 50, eloK: 24, eloBaseline: 1500, promoteMinRealUse: 1, govWeights: { elo: 0.4, reuse: 0.3, recency: 0.3 }, topKInject: 3 } | 参数权威；layout `single` |

- domain version=1；**四表全 `invalidRecords:'backup-and-skip'`**——技能是认知资产非权威：skills/rehearsal 可经轨迹+治理日志重建，usage 可经 taskPool 终态+session log 重建（J6），Elo 按 usage 复算；
- **lifecycle/退役不在本 domain**：治理状态单一权威在 `ctx.governance`（J1，assetKind='skill'）。

## 4. 不变量与服务 API

### 4.1 不变量（加载即校验 / 运行时强制）

1. **回放入职铁律**（Voyager）：非 external-adopted 技能未经 rehearsal pass 不得进 validating（服务端断言；J4 例外仅限人类采纳）；
2. **晋升双条件**：`consolidated` 必满足 rehearsalPass≥1 ∧ realUse≥`promoteMinRealUse`（∧ outcome=success）∨ 人类采纳（服务端断言，J4）；
3. **前置依赖在库**：composite 技能 rehearse/consolidate 前断言 prerequisites 全部 consolidated（J9）；
4. **零原文泄漏**：`skills` 字段白名单断言（steps=动作分类+contractRef，禁参数值/正文/文件内容）；grep 自检：库内无构造注入的原文句；
5. **写时冲突只标不裁**：同名拒绝；near-dup/contradiction 只落 `conflict` 标记，不改其他技能定义；收敛必经显式 supersede（J9）；
6. **退役可逆**：retired→consolidated 恢复只能人工触发（同 T1.2 J6）；退役即双通道不可见（召回过滤+DSH skills 物化移除）；
7. **Elo 单调可解释**：每次评分更新必落 skill_usage_log（eloBefore/eloAfter/k/outcome），可逐条复算；
8. **治理单一**：本服务无 lifecycle 字段、无 retire 本地实现——一切状态迁移经 `ctx.governance`（J1，同 T1.4 不变量 6）；
9. **留痕对账**：技能全动作双写 log-only session event `skill/change`（P2 扩展事件族，承 T0.7 J2：log-only/JSON 无损/稳定业务 id=skillId/rehearsalId/useId）+ 入 `audit_index`（entityKind='skill'）；DSH skills 物化/移除与 registry 状态可交叉对账（§5.5）。

### 4.2 `ctx.skillRegistry` 服务方法

```ts type-equiv
interface SkillService {
  propose(draft: SkillDraft): Skill                                  // coach/人 → draft（写时冲突检测 J9）
  adoptExternal(ref: { name: string; dshSkillRef: string }): Skill   // 人类采纳 DSH 技能 → validating（J4 例外）
  extractFromTrajectory(refs: TrajectoryRef[]): SkillDraft          // 辅路：成功任务 transition 链 → procedure 骨架（J11）
  rehearse(skillId: SkillId, taskId: TaskId): SkillRehearsalRun     // fork+试跑+判定（J5）
  logUse(skillId: SkillId, taskId: TaskId, outcome: 'success'|'failure'|'partial'): SkillUse   // 真实复用记账+Elo（J6/J7）
  requestConsolidate(skillId: SkillId): GovAction                   // 双条件过 → 提请治理固化（含 DSH skills 物化）
  supersede(oldId: SkillId, draft: SkillDraft): Skill               // 版本替代（经治理 retire[superseded]）
  injectCandidates(session: Session, round: number): Skill[]        // L3 能力召回：validating（带标注）+consolidated，Top-K（J3/J12）
  skills(filter?: { lifecycle?; taskClass?; stage? }): Skill[]
  history(skillId: SkillId): readonly Skill[]                       // supersede 链
  params(): SkillParams
  setParams(patch: Partial<Omit<SkillParams,'revision'>>): SkillParams
}

interface SkillDraft = Omit<Skill, 'id' | 'stats' | 'version' | 'createdAt' | 'updatedAt'>
```

- `rehearse` 内部序：读技能（draft）→ 断言前置依赖（J9）→ `ctx.sessions.fork(source=任务会话, boundary=任务边界)` → 子会话注入技能定义执行 → 抽子会话 transition 链（T1.3 extract）→ 算 coverage+outcome → verdict → 落 skill_rehearsal_runs → 更新 stats → 达阈值动作（validating/自动退役）；
- `logUse` 内部序：断言技能态∈{validating, consolidated} → 记 SkillUse（Elo 前值/新值）→ 更新 stats（realUse/consecutiveUseFail/Elo）→ use-fail 达阈移交治理 scan；
- `requestConsolidate`：断言不变量 2 → `ctx.governance.consolidate(assetKind='skill')` → 成功后物化 SKILL.md 进 TDA 技能源目录（DSH skills 发现生效）；
- `injectCandidates`：按 applicability 匹配 + Elo 排序取 Top-K，validating 技能注入文本带"验证中"标注（J3）；与 T1.1/T1.3/T1.4 候选同池进 T0.4 injection 区（预算统一裁决）。

## 5. 与 DSH 的对接点

| 对接面 | 机制 |
|---|---|
| 技能底座 | `ctx.skills`（T0.0）：多源 rank 发现/chokidar 热更/渐进披露全复用；consolidated → 物化 SKILL.md bundle（frontmatter 归一调用策略）写入 TDA 技能源目录；**TDA 不写 DSH skills 的其他源**（sandbox 边界，U5） |
| rehearsal fork | `ctx.sessions.fork(source, boundary, childSessionId?)`（T0.7 J6：显式 boundary 禁开放轮次前缀、seed 不变量）；判定数据=子会话 log 的 transition 链（T1.3 extract 复用） |
| 持久化 | `ctx.storage` sqlite domain（skills/skill_rehearsal_runs/skill_usage_log/skill_params），同 T0.1–T0.6 模式 |

## 6. 验收标准（对 Gate G2 的贡献项）

1. **G2-① 回放+真实复用才晋升（主项）**：构造/coach 候选技能 → draft → rehearse pass → validating（召回注入池可见带"验证中"标注、DSH skills 尚不可调用）→ logUse 一次真实任务 success → requestConsolidate → consolidated → SKILL.md 物化、DSH 渐进披露可见可调用；**零真实复用时 consolidate 被服务端拒绝**（不变量 2 自检）；
2. **Voyager 两铁律**：①composite 技能前置未 consolidated → rehearse/consolidate 拒绝；构造前置在库场景全通过 ②未过 rehearsal 的技能任何路径不进 validating（不变量 1 自检）；
3. **退役承重（Ratchet）**：连续 3 次 rehearsal fail → 自动 retire[rehearsal-fail]；连续 N 次真实复用失败 → retire[use-fail]（中途一次 success 清零连续计数自检）；superseded/unused-days/capacity 三信号各构造触发一次；退役后召回注入池与 DSH skills 双通道均不可见；
4. **写时冲突检测**：同名 propose 被拒；构造近似重复与矛盾对 → conflict/near-dup 标记落盘、两技能定义均不变、可经显式 supersede 收敛（不变量 5）；
5. **Elo 可解释**：构造 success/failure/partial 使用序列 → 按 K 值逐条复算 Elo 一致（不变量 7）；容量超 100% 时按治理分（含 Elo 归一）淘汰最低者且带排名证据明细；
6. **零原文泄漏**：grep skills 全表无构造注入的原文句（白名单断言+步骤分类自检）；
7. **重建等价**：删 skill 四表 → 轨迹+治理日志+taskPool 重建 skills/rehearsal_runs/usage_log/Elo 逐字段一致；
8. **治理一致性**：consolidate/retire 在 gov_actions（assetKind='skill'）可查，与 memory/meta-thinking 同管道同判据（T1.2 不变量 8 的重放扩展第三分区）。
