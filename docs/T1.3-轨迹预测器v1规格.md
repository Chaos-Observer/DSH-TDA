# T1.3 · 轨迹预测器 v1 规格（predictor 插件）

> 上游：《需求描述》v2.1 §3.4.5（轨迹三态消费之"预测"：相似 transition 检索→预测下一步状态/工具结果/风险；mismatch 是 coach 核心信号；低置信不注入）、§3.4.2（替代不确定性源 seam）、《T0.7》（transition 抽取 schema U3 关闭点/audit_index/log 抽取面）、《T0.4》（injection 区/static gate 替代不确定性源）、《T0.3》（检索基底）。
> 本规格是施工依据；实现后回填验收结果。

## 1. 设计裁定

| # | 裁定 | 理由 |
|---|---|---|
| J1 | **transition 抽取 schema**（T0.7 U3 关闭）：一个 transition = **决策点 → 实际结果**对，四类：`tool-call`（工具调用+成败+errorClass）、`dispatch`（子代理派发+角色+结论成败）、`task-transition`（taskPool phase×stage 迁移+原因）、`turn-close`（轮次结束原因）；**`context/assemble` 不计 transition**（每轮必有、无决策性，抽取即噪声） | §3.4.5"预测下一步状态/工具结果/风险"要求转移单位带动作与结果两元；三类决策动作覆盖 Agent 全部可观测行为；注入类排除是信噪比裁定 |
| J2 | **抽取是确定性本地过程，不经模型**：从 session log 轮次结构 + TDA 事件族时序机械抽取（哪个工具/角色/状态迁移、成败分类、seq 范围）；语义嵌入经 EmbeddingProvider seam（承 T0.3 U1），P1 v1 退化路径=结构化键匹配（goal/task 分类 + tool 名 + stage）+ T0.3 FTS | 世界模型训练数据管线必须可重建、可审计（T0.7 replay-equivalence 精神）；模型抽取=引入不确定性且无法回放校验；seam 保证 v1 可施工、v2 可深化 |
| J3 | **零原文泄漏**：transition 只存**脱敏分类与摘要**——`argClass`（参数模式分类：路径类/查询类/写操作类/派发类…，不存参数值）、`errorClass`（失败类别）、`stateBefore/After`（任务态+结果类别摘要）；一切原文经 `source{sessionId,seqFrom,seqTo}` 引用 session log（T0.7 audit_index 同模式） | 承 T0.6"文件正文零泄漏"同族纪律：预测库若囤原文=把敏感上下文搬进注入面的旁路，且与 §5.5 溯源（原文在 log 可查）重复；引用即溯源 |
| J4 | **预测 = 相似 transition 检索 + 聚合**（单步，不做 rollout）：当前上下文（焦点任务分类 + stage + 最近动作序列）→ top-K 相似 transition → 聚合出 `nextAction`（最可能动作）+ `outcomeDist`（成败分布）+ `riskFlags`（历史失败模式：errorClass 频率）；多步 rollout 与外部世界状态模拟留 P2+（U3） | §3.4.5"检索相似 transition 预测下一步"是 v1 原文；单步可验证；Hybrid-WM/MCP-Cosmos 完整世界模型的复杂度 P1 不付 |
| J5 | **低置信不注入、但 mismatch 全记录**（双轨制）：`confidence≥θ_pred` 的预测经 T0.4 injection 区进主上下文（预算内，与 T1.1 竞争同份额）；`<θ_pred` 只落 `predictions` 旁路不注入。**无论注入与否，凡生成过预测的轮次必做 observe 比对并记 mismatch**（含 deltaKind='none'） | §3.4.5 两条明文同时成立："低置信预测不注入主上下文"+"mismatch 是 coach 核心信号"——若低置信连记录都跳过，coach 信号密度塌陷；双轨是唯一同时满足的解法 |
| J6 | **预测凭证 = execution-verified，但注入必带"推断"标注**：transition/prediction 源自真实 log（执行验证级）；注入文本显式标注"基于历史的预测，非既成事实" | 凭证分级（T0.3）管来源真实性；预测的语义是或然的——模型若把预测当事实=自我实现的错误（防"预测污染"）；U4 标定标注形态 |
| J7 | **派生库 + 回放确定性**：`transitions`/`predictions`/`mismatches` 全部可从 log 重建（幂等 extract、确定性 predict——同 log 前缀+同 params ⇒ 同预测同分）；`invalidRecords='backup-and-skip'` | 同 T0.7 J4/T1.2 J10 的 replay-equivalence 模式；预测器是认知资产不是权威，丢了不阻断系统 |
| J8 | **预测即 T0.4 static gate 的"替代不确定性源"**（seam 落地）：`riskFlags` 与预测 confidence 作为 T0.4 `gate.mode='static'` 路径的优先级输入（高不确定段=历史 mismatch 高发区→保留；高可推断段→候选遮蔽）；perplexity 路径就绪后两者叠加（U2） | §3.4.2 明文"替代不确定性源=轨迹预测器 mismatch 信号"、T0.4 J6 已留 seam——本规格是履约方；完成 §3.4.2 降级策略的闭环 |
| J9 | **与 T1.1 分工不合并**：recall 答"什么记忆相关"，predictor 答"接下来会发生什么"；两者同为 injection 区候选，预算竞争由 T0.4 统一裁决（各经 registerScorer 同族计分输入） | 关注点分离；合并=引力场完整版（T2.4）的主动策略范畴，P1 不做 |
| J10 | **extract 增量水位 + 吞吐帽**：`extract_state` 记录已扫 log seq 水位，周期增量抽取（常驻调度宿主同 T1.2 J11，单批 transition 数有帽）；抽取失败不影响主链路（预测器是可选增强，fail-open 至"无预测"） | 90 天长程全量重扫不可行；预测器降级=无预测（机制不失效，承 T0.4 J6 同款纪律） |

## 2. 状态模型

预测器无 phase 状态机；其"状态"= **预测-观测循环**（每轮次边界）：

```
log 增量 ──extract──► transitions 库（派生，可重建）
                          │
轮次边界 ──predict(ctx)──►┤ 相似检索+聚合
                          ▼
                    Prediction{ nextAction, outcomeDist, riskFlags, confidence }
                       ├─ confidence≥θ_pred ──► T0.4 injection 区（预算内）+ predictions 落盘
                       └─ confidence<θ_pred ──► 仅 predictions 落盘（旁路，不注入）
轮次结束 ──observe(actual)──► MismatchRecord{ deltaKind } ──► coach 信号流（T2.1）
```

- `deltaKind`：`action`（预测动作≠实际动作）/ `outcome`（动作同结果异）/ `risk-materialized`（风险信号命中：预测的 errorClass 实际发生）/ `none`（吻合）；
- observe 的"实际"从 log 机械抽取（同 J2 确定性），无隐藏状态；
- 回放确定性：predictions/mismatches 可用同 log+同 params 重算复现（不变量 5）。

## 3. 数据模型

### 3.1 `Transition`（派生记录）

```ts type-equiv
/** 决策点→结果对。零原文泄漏（J3）：只存分类/摘要/seq 引用。 */
interface Transition {
  readonly id: TransitionId               // branded，tr-<n>
  readonly kind: 'tool-call' | 'dispatch' | 'task-transition' | 'turn-close'
  readonly goalId?: GoalId                // 决策时焦点（弱引用）
  readonly taskId?: TaskId                // 决策时焦点任务（弱引用）
  readonly taskStage: 'planning' | 'executing' | 'waiting' | 'verifying'
  readonly action: {
    readonly tool?: string                // kind=tool-call：工具名（公开名，非参数）
    readonly argClass?: string            // 参数模式分类（J3 脱敏）
    readonly role?: 'lead' | 'sidekick'   // kind=dispatch
    readonly fromStage?: string; readonly toStage?: string   // kind=task-transition
    readonly closeReason?: string         // kind=turn-close：结束原因分类
  }
  readonly outcome: {
    readonly status: 'success' | 'failure' | 'partial'
    readonly errorClass?: string          // 失败类别分类（timeout/not-found/rejected/…）
    readonly resultClass?: string         // 结果类别摘要（非正文）
  }
  readonly stateBefore?: string           // 状态分类摘要（任务态+上下文类别）
  readonly stateAfter?: string
  readonly source: { sessionId: SessionId; seqFrom: number; seqTo: number }   // log 引用（溯源/T0.7 audit_index）
  readonly at: number
}
```

### 3.2 `Prediction` / `MismatchRecord`（append-only）

```ts type-equiv
interface Prediction {
  readonly id: PredictionId               // pred-<n>
  readonly sessionId: SessionId
  readonly round: number
  readonly context: { taskId?: TaskId; stage: string; recentActions: string[] }   // 脱敏上下文
  readonly nextAction: string             // 聚合最可能动作（分类串）
  readonly outcomeDist: { success: number; failure: number; partial: number }     // 归一化
  readonly riskFlags: { errorClass: string; freq: number }[]
  readonly confidence: number             // 0–1（相似度×支持度合成）
  readonly injected: boolean              // ≥θ_pred 且进了 injection 区（T0.4 预算裁决后）
  readonly similarTransitionIds: TransitionId[]   // top-K 依据（可解释/可回放）
  readonly at: number
}

interface MismatchRecord {
  readonly id: MismatchId
  readonly predictionId: PredictionId
  readonly actual: { action: string; outcomeStatus: 'success'|'failure'|'partial'; errorClass?: string }
  readonly deltaKind: 'action' | 'outcome' | 'risk-materialized' | 'none'
  readonly at: number
}
```

### 3.3 SQLite schema（`ctx.storage` sqlite domain，DomainSpec）

| 表 | 键 | 值 | 说明 |
|---|---|---|---|
| `transitions` | TransitionId | Transition 全量 | 派生索引；幂等 extract；可重建 |
| `predictions` | PredictionId | Prediction 全量 | append-only；预测快照（mismatch 复算依据） |
| `mismatches` | MismatchId | MismatchRecord | append-only；coach 信号流（T2.1 消费） |
| `predict_params` | `'singleton'` | { thetaPredict, topK, simWeights: {taskCls, actionSeq, state}, mismatchEnabled } | 参数权威；layout `single` |
| `extract_state` | `'singleton'` | { lastSeq, lastAt, batchCap } | 增量水位+吞吐帽（J10） |

- domain version=1；**全表 `invalidRecords:'backup-and-skip'`**——预测器是认知资产，任何表丢失=重扫 log 重建（J7），不阻断权威；
- 不建向量索引：transition 相似检索 P1 走结构化键+FTS（J2），`EmbeddingProvider` 就绪后经同一 seam 升级（T0.3 U1 联动）。

## 4. 不变量与服务 API

### 4.1 不变量（运行时强制）

1. **抽取确定性**：同 log 前缀 extract 结果一致（幂等；重复 extract 同 seq 范围不产重复 transition）；
2. **零原文泄漏**：transitions/predictions 无工具参数值、工具返回正文、用户数据（自动断言：字段白名单外禁写）；
3. **低置信不注入**：`confidence<θ_pred` 的预测不进任何 `deriveMessages` 路径（显式诊断查询带 `debug` 标志除外，生产路径禁用）；
4. **mismatch 全记录**：凡生成过预测的轮次必落 observe 结果（含 `none`）——coach 信号密度不塌陷；
5. **预测可复算**：predictions 落盘的 `similarTransitionIds`+params 足以事后重算同结果（回放确定性）；
6. **推断标注**：注入的预测文本必带"预测非事实"标注（J6）；
7. **fail-open**：extract/predict 任何异常→降级为"无预测"，禁止阻断主任务链路（J10）；
8. **吞吐帽**：单批 extract transition 数 ≤ `batchCap`，余量下批续（不侵蚀主任务，同 T1.2 J11 纪律）。

### 4.2 `ctx.predictor` 服务方法

```ts type-equiv
interface PredictorService {
  extract(session: Session, opts?: { range?: { from: number; to: number } }): ExtractReport   // 增量/定点抽取
  predict(ctx: PredictContext): Prediction | null        // 单步预测（低置信返回 null=不注入）
  observe(predictionId: PredictionId, session: Session): MismatchRecord | null              // 轮次后比对（actual 从 log 抽）
  injectCandidates(session: Session, round: number): Prediction[]   // T0.4 assemble 调用（≥θ_pred 的注入候选）
  similar(query: TransitionQuery, k?: number): Transition[]         // 相似检索（显式诊断/研究面）
  params(): PredictParams
  setParams(patch: Partial<Omit<PredictParams,'revision'>>): PredictParams
}

interface PredictContext { session: Session; round: number; taskId?: TaskId; stage?: string }
interface ExtractReport { scanned: number; extracted: number; skipped: number; watermark: number }
```

- `predict` 内部序：构造脱敏上下文 → `similar()` top-K → 聚合（nextAction=众数；outcomeDist=加权成败；riskFlags=errorClass 频率≥阈值）→ confidence=相似度均值×支持度系数 → 落 predictions（无论置信）→ ≥θ_pred 返回候选；
- `observe` 内部序：读 predictions 记录 → 从 log 抽该轮 actual（J2 同款确定性）→ 比对定 deltaKind → 落 mismatches；
- 与 T0.4 的接合：`injectCandidates` 产出经 T0.4 injection 预算裁决（与 T1.1 候选同池竞争）；`riskFlags`/confidence 同时作为 static gate 的替代不确定性源输入（J8）。

## 5. 与 DSH 的对接点

| 对接面 | 机制 |
|---|---|
| 轨迹读面 | DSH session log（seq 连续/JSON 一行）+ T0.7 `audit_index`（实体→seq 范围，反查某任务全部 transition）；抽取走 log 冷读，不依赖进程内状态 |
| 上下文注入 | T0.4 `ctx.context.assemble` 调 `injectCandidates`，进 injection 区（与 T1.1 同份额竞争）；AssembleRecord 记预测注入（T0.4 J8 双写天然覆盖） |
| gate 联动 | T0.4 `gate.mode='static'` 的不确定性排序输入 = 本插件 riskFlags + mismatch 历史（J8 seam；perplexity 就绪后叠加，U2） |
| 持久化 | `ctx.storage` sqlite domain（transitions/predictions/mismatches/predict_params/extract_state），同 T0.1–T0.6 模式 |
| 审计 | 注入与 mismatch 双写 log-only session event `predict/change`（P1 扩展事件族，承 T0.7 J2 规范：log-only/JSON 无损/稳定业务 id=predictionId） |
| 调度宿主 | extract 周期增量由 L1 Harness 常驻进程驱动（T0.2 J8 daemon 宿主，同 T1.2 J11）；coach 元进程本体归 T2.1（mismatch 流的消费方，本规格只产信号） |
| T1.1/T2.4 | injection 区候选同池；主动策略召回（T2.4）可复用 similar() 作为"我当时怎么做的"轨迹侧检索（§3.4.5 辅助召回态） |

## 6. 验收标准（对 Gate G1 的贡献项）

1. **G1-④ mismatch 可观测可用（主项）**：构造历史轨迹——"stage=executing + 工具 edit（argClass=写操作）→ errorClass=timeout"模式 3 次 → 新任务同 stage 同工具，predict 输出 riskFlags 含 timeout 且 confidence≥θ_pred → 注入含风险提示 → observe 记 deltaKind（实际失败=`risk-materialized`；实际成功=`outcome`）；
2. **低置信不注入**：无相似历史的场景 → confidence<θ_pred → `deriveMessages` 无任何预测内容（自动断言），predictions 仍有记录（双轨自检）；
3. **抽取正确性**：给定构造 log（含 tool-call/dispatch/task-transition/turn-close 各若干），extract 产出的 transition 分类数、seq 范围、成败标注与人工核对一致；context/assemble 事件零抽取（J1 自检）；
4. **重建等价**：删 transitions 表 → 重扫 log → 逐字段一致；predictions 用同 log+同 params 复算一致（J5/J7）；
5. **泄漏自检**：grep transitions/predictions 全表无构造注入的敏感原文（脱敏白名单断言）；
6. **推断标注**：注入预测文本含"预测非事实"标注（J6）；
7. **预算纪律**：预测注入超 injection 份额时被 T0.4 截断且 AssembleRecord 记录；
8. **fail-open**：注入 extract 异常后主任务链路不受影响（预测退化为无，不抛断）。
