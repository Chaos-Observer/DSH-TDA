## 1. 设计裁定

| # | 裁定 | 理由 |
|---|---|---|
| J1 | **T2.4 = T1.1 的计分器扩展 + 主动召回通道，不新建召回服务**：pipeline（query 构造→T0.3 search()→provenance gate→计分→top-K/minScore→injection/显式返回→recall_log）结构不变；v2 只做两件事：① 经 T0.4 `registerScorer` 替换 `parts→score` 映射（履约 T1.1 J8）② 增开主动召回通道。**gate 位置不动**（仍在计分前），v2 只重排 gate 幸存者 | §3.4.3"分阶段实现"原文=P1 最小版可施工、P2+ 叠加动量/情感/主动策略；双召回引擎=双一致性问题（同 T1.1 J1 不为 P2 需求推翻 P1 架构）；安全面：任何"完整版"不得稀释 P1 已硬落地的 gate（§5.3+Sleeper 实证） |
| J2 | **五元计分公式**：`score = w_task·taskRel + w_recency·recency + w_sem·semantic + w_momentum·momentum + w_emotion·emotion`；权重 P0 默认 `0.35/0.15/0.20/0.20/0.10`（和为 1，标定 U1）。**seam 契约：`w_momentum=w_emotion=0` 时严格退化为 T1.1 v1 公式**——v1 是 v2 的特例（`recall_params.scorerVersion:'v1'|'v2'` 可切，降级路径=v1）；回放用当时 scorerVersion+params 快照解释 | 三元可解释传统（T1.1 J6）延续到五元；动量/情感是"叠加增强"不是"替换地基"（§3.4.3"引入动量/情感权重的引力场"是在三元召回之上）；权重和=1 保持分归一到 [0,1] 与 minScore 语义不变 |
| J3 | **动量双尺度（RiverMemo V10 双尺度连续场参数基准）**：`momentum = saturate(w_fast·m_fast + w_slow·m_slow) × (α + (1−α)·attentionProximity)`。`m_fast`=会话尺度指数加权活跃度（τ_fast 默认 2h，近 N_fast 轮注入/使用事件）、`m_slow`=日尺度（τ_slow 默认 7d）；事件权重：注入 1.0、真实使用（`logUse`）2.0；`saturate`=除以滚动上限后 tanh 压缩到 [0,1]（防"越召回越强"富者愈富）；`α` 默认 0.3（邻域是增强非硬过滤——远离当前注意力的高动量 chunk 保留部分引力，避免话题切换后旧线索全盲）。**诚实标注**：RiverMemo V10 的 Ω 可观测泛函/相对拓扑/直接事实锚为研究级构件不复制，只借"双尺度衰减+分类型参数"两点（对方黄金测试 +26% 是 V10 口径，不作为我方验收承诺） | §3.4.3"读取当前注意力潜空间邻域，拉取动量高的 chunk"的工程化：邻域读取得不到模型内部注意力时，用"近期上下文质心邻近度"近似（J4）；双尺度对应"当前会话正热"与"跨天持续热"两种动量语义（单尺度会把昨天的热点和上月的热点混同）；动量纯从 recall_log 确定性重算（无隐藏状态，回放确定，同 T1.1 J7 纪律） |
| J4 | **注意力邻域 = 近期上下文质心近似**（关闭 T1.1 U4 的工程部分）：质心 = 最近 K 轮（默认 8）会话内容的向量均值（EmbeddingProvider 就绪后取真余弦；缺席时降级=FTS 词项分布代理，同 T1.1 U2 降级路径）；`attentionProximity`=chunk 向量与质心余弦，无向量 chunk 取中性 0.5；质心每轮从 session log 现算**不落库**（派生数据，回放确定）。**诚实标注**："潜空间邻域"的真实读取依赖模型内部注意力探针（logprobs/activation 级，研究级），v2 用可施工近似，探针评估留 U4 | §3.4.3 原文"读取当前注意力潜空间邻域"；T0.4 已有 logprobs 契约但那是 gate 用非注意力探针；不落库=遵守旁路层纪律（recall 零新权威，承 T1.1 J10 投影可重建模式）；降级路径必须存在（EmbeddingProvider 选型未定=T0.3 U1） |
| J5 | **情感权重计量口径（关闭 T0.3 U5）**：`emotionWeight ∈ [0,1]` 由写入方 append 时声明（T0.3 J4 schema 已占位，本规格只定计量与消费规则）；**计分资格仅 `user-original`/`execution-verified`**——`model-produced` 的 emotionWeight 落库留痕但计分恒取 0；`w_emotion ≤ 0.2` 参数层硬帽（情感是调味非主菜）；emotion 永远不参与 gate（gate 先行铁律不变）；tool-output/external-content 本就被 quarantine 双保险 | 安全裁定：自产情感权重=自产显著性=投毒面（Sleeper/MINJA 同款"注入方自标高危字段提升召回率"，§5.2/§5.3 的字段级延伸）；user-original 承载用户真实情绪信号（挫败/紧迫=该话题此刻重要）是正当增强源；execution-verified 允许系统按执行结果标注（失败复盘类 chunk 的显著性） |
| J6 | **主动策略召回两路（关闭 T1.1 U3）**：① **工具路**——模型显式调用新工具 `tda_recall`（args: text/taskId?/limit?，无指令字段），Harness 透传 `ctx.recall.recall`，产出同过 gate 同留 recall_log（trigger=`active-tool`）；② **阶段转换路**——任务 stage 迁移时（T0.2 J3：planning→executing→verifying 等）Harness 自动构造战略性召回请求（新阶段 subject+completionCriteria+上一阶段结论摘要），recall 引擎返回 briefing 进 injection 区专用子份额（trigger=`active-stage`）。**两条路都不降低安全标准**（gate/双条件/留痕与被动路完全相同） | §3.4.3"Agent 基于任务状态主动问'我现在需要回忆什么'"：工具路=Agent 自己问；阶段路=任务状态驱动的代理询问（agent 正忙于执行无暇自问时兜底）；拒绝第三条"模型输出字段声明回忆意图"路=那是在数据流里开控制流口子（§5.4 分离纪律），工具调用才是模型→Harness 的 sanctioned 控制通道 |
| J7 | **主动 briefing 的结构与预算**：briefing = top-K（默认 5）+ 每条形由（parts 摘要一句话）+ token 帽（默认 300）+ 专属子份额（injection 份额的 1/3，可配）；与被动 injection 共享总额、超限按"主动优先被动"截断并记 AssembleRecord（T0.4 J8 扩展）；briefing 只进 injection 区不进 pinned（pinned 是约束区 C6 语义， briefing 是易变召回物） | 主动召回的收益是"此刻正需要的旧经验"，但无限 briefing=注意力稀释（承 §3.4.5"低置信不注入"同款纪律+Chroma context rot 实证）；共享总额防两路合计挤爆 injection 区 |
| J8 | **可解释与审计**：`ScoredChunk.parts` 扩展为 `{taskRel, recency, semantic, momentum, emotion}`+`momentumDetail{m_fast, m_slow, attentionProximity}`；`recall_log` 扩展 `trigger`/`used`/`emotionApplied` 字段；emotion 实际参与计分的条目在 AssembleRecord 标注（emotionApplied=true）供投毒审计回溯 | §5.5 审计基线：为什么这条浮现必须可解释（五元逐项可见）；emotionApplied 标注=情感通道的投毒面监控数据面 |
| J9 | **动量不进治理分**：T1.2/T2.3 治理分（reuse/credential/recency）不含动量——动量是召回侧排序信号非资产质量信号（高动量可能只因最近总被想起，≠质量好）；若未来纳入需先解富者愈富（U3） | 治理分驱动退役/淘汰（T1.2 J8），把"召回频次"混入质量分会造成"热者愈热、冷者先死"的偏差；两个信号体系 purposeful 分离 |
| J10 | **tda_recall 工具纪律**：只读查询工具，args schema 白名单（text/taskId/limit）无任务指令字段；返回=结构化候选列表（entryId/score/parts/摘要）——内容引用走 entryId 可溯源（T0.7 audit_index）；工具调用本身写 recall_log（trigger=active-tool，同被动路留痕） | 同 T0.5 tda_dispatch 模式（模型工具最小集+白名单）；§5.4 控制流/数据流分离：工具是受控控制通道，args 不可夹带执行指令 |
| J11 | **边界**：① 不做情感语义判定（NLP 情感分析自动填 emotionWeight）——只计量写入方声明值（U6）；② 不做真实注意力探针（U4）；③ 不碰图谱检索（T3.1）；④ 不改 T0.3/T0.4 任何组件（只消费 seam） | 需求 §3.4.3 P2+ 完整版的边界=动量/情感/主动策略三项；情感语义与注意力探针是开放研究问题，装自动=假精确 |

## 2. 状态模型

recall v2 仍无 phase 状态机；"状态"=每次召回的计分结果（派生，可重放）：

```
主动阶段路（T0.2 stage 迁移事件）
  → briefing query 构造（新阶段 subject+completionCriteria+上阶段结论摘要）
  ↘
主动工具路（模型 tda_recall 调用）──┐
                                    ↓
被动路（T0.4 assemble injection 拉取 / Harness 显式查询）
  → query 构造（T1.1 J2 焦点上下文）
  → T0.3 search() 候选集（credentialMin 预筛）
  → provenance gate 硬闸（位置不变：quarantine/双条件过滤）
  → 五元计分：
      taskRel/recency/semantic（T1.1 J3/J6 原样）
      momentum = saturate(w_fast·m_fast + w_slow·m_slow) × (α+(1−α)·attentionProximity)
        m_fast/m_slow ← recall_log 事件重算（注入 1.0/使用 2.0，指数衰减）
        attentionProximity ← 近 K 轮会话质心（派生，不落库）
      emotion = entry.emotionWeight（资格过滤：model-produced 取 0）
  → top-K + minScore（总分，v1 语义不变）
  → 被动 injection 份额 + 主动 briefing 子份额（J7）
  → recall_log 落盘（trigger/used/emotionApplied）
```

- 回放确定性：同 session log 前缀（含近 K 轮质心）+ 同 recall_log 前缀（动量）+ 同 params+scorerVersion 快照 ⇒ 同候选同分同 briefing；
- 降级路径：`scorerVersion='v1'` ⇒ 严格 T1.1 三元（动量/情感项不存在）；EmbeddingProvider 缺席 ⇒ attentionProximity=0.5 中性，v2 其余项照常（动量不依赖向量）。

## 3. 数据模型

### 3.1 `RecallParams` v2（domain 单行，revision 递增）

```ts type-equiv
interface RecallParams {
  readonly scorerVersion: 'v1' | 'v2'                     // 降级开关（J2）
  readonly weights: { task: number; recency: number; semantic: number; momentum: number; emotion: number }  // 0.35/0.15/0.20/0.20/0.10
  readonly halfLifeDays: Record<'fact' | 'reflection' | 'method' | 'skill', number>  // 14/30/90/180（T1.1 J3 原样）
  readonly modelProducedMinConfidence: number             // θ 0.6（T1.1 J5 原样）
  readonly minScore: number                               // 0.25（T1.1 J6 原样）
  readonly momentum: {
    readonly fastTauHours: number                         // 2（会话尺度）
    readonly slowTauDays: number                          // 7（日尺度）
    readonly wFast: number                                // 0.6（快尺度主导"此刻正热"）
    readonly wSlow: number                                // 0.4
    readonly eventWeights: { injected: number; used: number }  // 1.0 / 2.0
    readonly saturateCeiling: number                      // 滚动上限（动量归一分母，实现定义）
    readonly alpha: number                                // 0.3（邻域混合系数，J3）
    readonly scanWindowDays: number                       // 30（动量重算扫描窗，防 recall_log 全表扫）
  }
  readonly attention: {
    readonly recentRounds: number                         // K=8（质心构造窗）
  }
  readonly strategic: {
    readonly maxItems: number                             // 5（briefing 条数帽）
    readonly tokenCap: number                             // 300
    readonly shareFraction: number                        // 0.34（injection 份额的 1/3）
  }
  readonly emotionWeightCap: number                       // 0.2（w_emotion 硬帽，服务端断言，J5）
  readonly revision: number
}
```

### 3.2 `ScoredChunk` v2 / `StrategicBriefing`

```ts type-equiv
interface ScoredChunk {
  readonly entry: TimelineEntry
  readonly score: number                                  // 0–1（五元加权和）
  readonly parts: { taskRel: number; recency: number; semantic: number; momentum: number; emotion: number }
  readonly momentumDetail?: { mFast: number; mSlow: number; attentionProximity: number }  // 审计/调试（J8）
  readonly gatePassed: boolean                            // v1 语义不变
}

interface StrategicBriefing {
  readonly taskId: TaskId
  readonly toStage: TaskStage                             // 迁移目标阶段（T0.2 J3 词汇）
  readonly items: ScoredChunk[]                           // ≤ strategic.maxItems
  readonly tokensEst: number                              // ≤ strategic.tokenCap
  readonly truncated: boolean                             // 超帽截断标记
  readonly at: number
}
```

### 3.3 `recall_log` 扩展（append-only，兼容追加，无新表）

| 表 | 键 | 值 | 说明 |
|---|---|---|---|
| `recall_log` | 自增 seq | { entryId, at, taskId?, goalId?, score, injected, sessionId, **trigger**: 'passive-assemble'\|'passive-query'\|'active-tool'\|'active-stage', **used?**: boolean, **emotionApplied?**: boolean } | 动量重算的事件源（injected/used 两类）+ 主动路留痕 + 情感审计标注 |

- `injected=true`=进过注入区/briefing；`used=true`=logUse 真实复用（事件权重更高）；
- 旧行无新字段=按缺省解释（trigger='passive-assemble'、used=false），向后兼容。

### 3.4 SQLite schema

| 表 | 键 | 值 | 说明 |
|---|---|---|---|
| `recall_params` | `'singleton'` | RecallParams v2 | 参数权威；layout `single`；version 1→2 迁移=字段扩展+默认值回填 |

## 4. 不变量与服务 API

### 4.1 不变量（加载即校验/运行时强制）

1. **gate 先行不削弱**：provenance gate 仍在计分前；任何参数组合下 quarantine/tool-output/external-content 条目不浮现——含"高 emotion/momentum 主动路"对抗用例自动断言；
2. **情感资格**：`model-produced` 条目的 emotionWeight 计分恒 0（服务端断言，落库值保留可审计）；`w_emotion ≤ emotionWeightCap(0.2)` 参数层硬帽；
3. **动量可复算**：同 recall_log 前缀+同 params ⇒ 同 momentum（纯函数，无隐藏状态；滚动上限本身可从同窗口重算）；
4. **邻域派生**：质心只从 session log 近 K 轮派生，不落任何权威表；无向量环境 proximity=0.5 中性不报错；
5. **退化等价**：`scorerVersion='v1'` 时逐分等于 T1.1 实现（seam 回归，CI 断言）；
6. **主动不降安全**：active-tool/active-stage 两路产出同过 gate、同留 recall_log、同受 minScore 约束；
7. **预算纪律**：briefing 条数/token/子份额三帽，超限按主动优先截断并记 AssembleRecord；被动+主动合计 ≤ injection 区总额；
8. **参数可审计**：params 变更走 revision+双写 log-only session event `recall/change`（v2 扩展字段同样留痕）；
9. **零新权威**：v2 不新增持久化表；recall_log 新字段为兼容追加，旧行可解释。

### 4.2 `ctx.recall` 服务方法（v2 扩展）

```ts type-equiv
interface RecallService {
  recall(query: RecallQuery & { trigger?: 'passive-query' | 'active-tool' }): ScoredChunk[]
  injectCandidates(session: Session, round: number): ScoredChunk[]   // 被动路（T1.1 原样，内部走 v2 计分）
  strategicBrief(taskId: TaskId, toStage: TaskStage): StrategicBriefing  // 主动阶段路（T0.2 stage 迁移事件驱动）
  logUse(entryIds: EntryId[], ctx: { taskId?: TaskId; sessionId: SessionId }): void  // used=true 事件（动量权重 2.0）
  params(): RecallParams
  setParams(patch: Partial<Omit<RecallParams, 'revision'>>): RecallParams   // 治理入口（T1.2）
}
```

- scorer 挂载：v2 scorer 经 T0.4 `registerScorer` 注册（纯函数 `(parts, params) => score`，替换 v1 映射；段结构不变=KV-cache 友好）；
- 模型工具 `tda_recall`：Harness 工具面扩展（同 T0.5 tda_dispatch 模式），args 白名单 `{text, taskId?, limit?}` → `ctx.recall.recall({trigger:'active-tool'})` → 结构化候选返回；
- 阶段迁移订阅：Harness 监听 T0.2 taskPool/change 的 stage 迁移 → 调 `strategicBrief` → 结果挂下一轮 assemble 的 briefing 子份额。

## 6. 验收标准（对 Gate 的贡献项）

1. **动量效应可辨**：构造 chunk A（近 3 次任务被注入/使用）与 B（同龄同类型零召回）对照——v2 下 A 排名高于 B、v1 下持平，证明动量项生效且 v1 无此行为；
2. **邻域拉取**：会话近 K 轮聚焦主题 T 后，任务远但邻域近的 chunk 排名上升（attentionProximity 生效；降级环境下用词项代理复现）；
3. **情感资格分流**：user-original emotionWeight=0.9 的 chunk 排名上升；同值 model-produced chunk 排名不变（计分取 0）且 recall_log 记 emotionApplied=false；
4. **主动阶段召回**：任务 executing→verifying 迁移后，下一轮 assemble 含 verifying 相关 method chunk 的 briefing（形合 J7 三帽）；
5. **主动工具路**：模型调 tda_recall 返回结构化候选（含 parts），recall_log 落 trigger=active-tool；
6. **gate 不削弱（安全主项）**：构造 emotionWeight=1.0+高动量的 quarantine/tool-output 中毒 chunk，被动/主动两路任何参数组合均不浮现；
