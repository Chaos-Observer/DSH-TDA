# T1.5 · 目标漂移检测 v1 规格（drift 插件）

> 上游：《需求描述》v2.1 §3.1.2（四指标：目标持久性/状态一致性/约束保持/行动波动；温和修正四动作不强制重置；外部验证阀兜底安全红线）、《T0.1》（objective_edits/calibrations/constraint_snapshots/goal_history 四表数据面）、《T1.3》（transitions=行动波动数据面）、《T0.4》（injection 区）。
> 本规格是施工依据；实现后回填验收结果。

## 1. 设计裁定

| # | 裁定 | 理由 |
|---|---|---|
| J1 | **检测器是旁路观察者，零目标写权**：`ctx.drift` 只读 goalTree/taskPool/transitions 算指标，校准动作=上下文注入 + calibrations 记录；**不调 goalTree 任何 mutation**（edit/focus/pause/complete/clear 一律不碰） | §5.4 C3：任何检索/观察内容不得改写任务定义——检测器若有目标写权=漂移检测本身成为注入直通路径；目标权威变更只能经 human/模型显式 CAS（T0.1 J4） |
| J2 | **四指标计算口径全部落在 T0.1 四表 + transitions**（v1 可机读口径）：① 目标持久性=`objective_edits` 编辑频率+幅度趋势（v1 幅度=编辑计数/间隔，语义相似度量留 U1）② 状态一致性=goalTree 报告的 phase×stage 与 taskPool 实际执行态的错配（规则式：如报 executing 但无 in_progress 任务超时、报 verifying 但无验证证据）③ 约束保持率=`constraint_snapshots` 基线 vs 约束类 blockedReason（`code` 前缀 `constraint-`）发生与复发（弱代理，诚实标 U3）④ 行动波动性=T1.3 transitions 动作分布的窗口漂移（KL 散度 vs 基线窗口） | 四指标逐一对应需求 §3.1.2 表格；数据面零新增采集（T0.1 建表时即为 T1.5 预备）；语义强度量（embedding/LLM 评判）P1 不装——全部用可回放确定性口径，保 J8 |
| J3 | **三带分级 + 指标→动作路由**：`composite`（四指标加权）与单指标双轨判带——`normal`（仅记录）/`watch`（监督可见+记录）/`drift`（触发温和校准）。路由：persistence↓→`restate`（目标重述注入）、consistency↓→`echo`（报告-实际差异回声）、constraintRetention↓→`reanchor`（约束重锚定提示）、actionVolatility 异常→`nudge`（计划微调提示） | §3.1.2"检测到漂移后温和修正（四动作）"；四动作与四指标一一对应是路由的自然设计；双轨（综合+单指标）防四指标互相抵消掩盖单维漂移 |
| J4 | **校准=上下文层干预，不动权威值**：restate=把初始 objective+completionCriteria 重述进 injection 区（非改目标）；echo=把状态报告与实际行为的差异摘要注入；reanchor=把 constraint_snapshots pinned 约束重新锚定提示注入（T0.4 pinned 数据源不变，提示经 injection）；nudge=计划偏差预算内的轻量调整提示（任务层调整本身留 T2.5，v1 只注入提示） | §3.1.2"温和修正，不强制重置，保护连续性"——四动作全部是"提醒/重述/重锚"性质；唯一能改权威的路径仍是显式 CAS（J1） |
| J5 | **外部验证阀兜底**（§3.1.2 安全红线）：① 每次校准必落 `calibrations` 表（T0.1 已建，外部验证阀兜底证据）② **后验追踪**=校准后下一窗口必出对照 DriftSnapshot，指标回升=有效、未回升=该模式升级人类（注意力配额消费，T3.2 前置）③ 低风险动作（restate/echo）即时执行；中风险动作（reanchor/nudge）滞回——连续 2 窗口 drift 才触发（误报防护） | "漂移校准须有外部验证阀兜底"直译：校准本身要被验证（后验）+ 误判要有人兜（升级）；滞回防单窗口毛刺触发约束重锚这类高干扰动作 |
| J6 | **双触发 + 吞吐帽**：周期评估（Harness 常驻宿主，同 T1.2 J11/T1.3 J10 模式，P0 周期 1h）+ 事件触发（`goalTree/change` 的 objective edit 同步重算 persistence——objective_edits 写入是硬信号点）；单次 evaluate 计算量有帽（transitions 窗口扫描上限） | 事件触发保信号时效（目标被改立即见）；周期触发保趋势面；常驻宿主=DSH schedule session-local 缺口的同一结论（T0.0） |
| J7 | **趋势快照 append-only**：`drift_scores` 表逐周期落四指标+综合+等级+窗口——趋势是"当前行为与初始目标的对齐度**趋势**"（§3.1.2 原文）的 data 面，也是 T3.2 监督仪表盘数据源 | 无快照序列=只有瞬时值无趋势；append-only 同 T0.3 铁律同族纪律 |
| J8 | **回放确定性**：evaluate=纯函数（domain 快照+窗口参数）⇒ 同输入同 DriftSnapshot；校准记录 append-only；注入候选从快照确定性派生 | 同 T0.7 replay-equivalence/T1.2 J10 模式；漂移判断要可审计（§5.5），不可重算的判断不可审计 |

## 2. 状态模型

drift 无 phase 状态机；"状态"= **周期评估循环**（派生）：

```
周期/事件触发 ──► evaluate(goalId)
   ├─ 读 T0.1 四表 + transitions 窗口（J2 口径）
   ├─ 算四指标 → composite → 判带（normal/watch/drift）
   ├─ 落 drift_scores 快照（J7）
   └─ drift 带 ──► 按 J3 路由选校准动作 ──► calibrate()
                 ├─ 注入候选（T0.4 injection 区，≤K token，J4）
                 └─ 落 calibrations（T0.1 domain，J5①）
下一窗口 ──► 后验对照（回升/未回升→升级人类，J5②）
```

- 校准动作与 T1.1/T1.3/T1.4 注入候选**同池竞争** T0.4 预算（各 ≤K token，统一裁决）；
- 无"重置/回滚目标"动作存在——目标权威变更只能显式 CAS（J1，不变量 5）。

## 3. 数据模型

### 3.1 `DriftSnapshot` / `DriftParams`

```ts type-equiv
/** 周期评估快照（append-only）。四指标 1=无漂移，0=完全漂移。 */
interface DriftSnapshot {
  readonly id: DriftSnapshotId               // ds-<n>
  readonly goalId: GoalId                    // 焦点目标（每树一个焦点，承 T0.1）
  readonly scores: {
    readonly persistence: number             // J2① objective_edits 频率/幅度趋势
    readonly consistency: number             // J2② 报告态 vs 实际态错配
    readonly constraintRetention: number     // J2③ 约束类 blockedReason 复发
    readonly actionVolatility: number        // J2④ transitions 分布 KL 漂移
  }
  readonly composite: number                 // 加权综合（params.weights）
  readonly level: 'normal' | 'watch' | 'drift'
  readonly window: { from: number; to: number }
  readonly trigger: 'cycle' | 'objective-edit'
  readonly at: number
}

interface DriftParams {
  readonly weights: { persistence: number; consistency: number; constraintRetention: number; actionVolatility: number }   // P0 默认均 0.25
  readonly windowMs: number                  // 指标窗口（P0 默认 7d）
  readonly baselineWindows: number           // 波动性基线窗口数（P0 默认 4）
  readonly thresholds: { watch: number; drift: number }          // composite 带阈（P0 默认 0.7/0.5）
  readonly perMetricThreshold: number        // 单指标越限即候选（P0 默认 0.6）
  readonly hysteresisWindows: number         // reanchor/nudge 滞回窗数（P0 默认 2，J5③）
  readonly revision: number
}
```

### 3.2 `CalibrationHint`（注入候选，瞬时）

```ts type-equiv
/** 温和校准的注入形态。≤K token（P0 默认 150）。 */
interface CalibrationHint {
  readonly kind: 'restate' | 'echo' | 'reanchor' | 'nudge'
  readonly goalId: GoalId
  readonly text: string                       // 提示文本（重述初始目标/差异摘要/约束清单/微调建议）
  readonly snapshotId: DriftSnapshotId        // 依据快照（可解释+可回放）
  readonly risk: 'low' | 'medium'             // restate/echo=low；reanchor/nudge=medium（J5③）
}
```

### 3.3 SQLite schema（`ctx.storage` sqlite domain，DomainSpec）

| 表 | 键 | 值 | 说明 |
|---|---|---|---|
| `drift_scores` | DriftSnapshotId | DriftSnapshot 全量 | append-only 趋势快照（J7） |
| `drift_params` | `'singleton'` | DriftParams | 参数权威；layout `single` |

- domain version=1；两表 `invalidRecords:'backup-and-skip'`——快照可重算（J8 纯函数）、参数可回默认，均非权威；
- **`calibrations` 不落在本 domain**：归 T0.1 goal-state domain（权威证据，J5①）——需 T0.1 实现时补 `recordCalibration` seam（U7，规格级回写 T0.1 §4.2 API 清单）。

## 4. 不变量与服务 API

### 4.1 不变量（运行时强制）

1. **零目标写权**：drift 服务不调用 goalTree/taskPool 的任何 mutation API（编译期依赖约束+运行时可断言）；
2. **校准不动权威**：任何校准动作执行后，目标 objective/completionCriteria/constraint_snapshots 字节不变（只进 injection 区与 calibrations 表）；
3. **指标确定性**：同 domain 快照+同窗口+同 params ⇒ 同 DriftSnapshot（纯函数，自动断言）；
4. **校准必留痕**：每次校准必落 T0.1 `calibrations`（driftType+action+detail+at），无静默校准；
5. **不强制重置**：不存在任何路径触发目标 clear/reset/强制 complete——漂移响应只有注入提示与记录（§3.1.2 原文纪律）；
6. **后验必达**：校准发生后下一窗口必产出对照快照（未产出=系统缺陷，CI 断言）；
7. **预算纪律**：校准注入 ≤150 token/条，与 T1.1/T1.3/T1.4 同池竞争 T0.4 裁决；
8. **滞回生效**：medium 风险动作（reanchor/nudge）需连续 `hysteresisWindows` 个窗口越限才触发；low 风险（restate/echo）单窗口即可（J5③）。

### 4.2 `ctx.drift` 服务方法

```ts type-equiv
interface DriftService {
  evaluate(goalId?: GoalId): DriftSnapshot                 // 周期/事件触发（J6）
  calibrate(goalId: GoalId, kind: 'restate'|'echo'|'reanchor'|'nudge', snapshotId: DriftSnapshotId): CalibrationHint
  injectCandidates(session: Session, round: number): CalibrationHint[]    // T0.4 assemble 调用（未消费的待执行校准）
  snapshots(goalId: GoalId, range?: { from: number; to: number }): DriftSnapshot[]   // 趋势查询（T3.2 数据面）
  params(): DriftParams
  setParams(patch: Partial<Omit<DriftParams, 'revision'>>): DriftParams
}
```

- `evaluate` 内部序：定窗口 → 取 T0.1 objective_edits/constraint_snapshots/goal_history + taskPool 焦点任务实际态 + transitions 窗口分布 → 四指标纯函数计算 → composite+判带 → 落快照 → 若 drift 带且通过滞回检查 → 生成待执行校准（`calibrate` 由 Harness 在下一轮 assemble 前调用或事件触发即时）；
- `injectCandidates` 只返回已 `calibrate` 生成、尚未被消费（或持续 drift）的提示；
- 事件触发路径：订阅 `goalTree/change`（T0.7 事件族），objective edit 类变更同步跑一次 `evaluate(trigger='objective-edit')`。

## 6. 验收标准（对 Gate G1 的贡献项）

1. **G1-③ 漂移捕获+温和校准（主项）**：构造场景——焦点目标 objective 被 edit 3 次渐偏 + taskPool 报告态与实际态错配超时 → evaluate 出 persistence↓/consistency↓、composite 越 drift 阈 → 触发 restate+echo 校准（注入含初始目标重述+差异摘要）→ calibrations 留痕 → **目标权威值逐字节不变**（不变量 1/2 自检）；
2. **约束保持路径**：构造 `blockedReason.code='constraint-*'` 复发场景 → constraintRetention↓ → 连续 2 窗口后触发 reanchor（滞回自检）；注入含 constraint_snapshots 的 pinned 约束清单；
3. **行动波动路径**：transitions 动作分布人为突变（工具分布 KL 超阈）→ actionVolatility↓ → 连续 2 窗口后触发 nudge；
4. **无强制重置**：全部校准场景跑完后，goalTree 无 clear/reset/强制 complete 记录（不变量 5 断言）；
5. **后验追踪**：校准后下一窗口必出对照快照（不变量 6 CI 断言）；构造"校准无效"场景验证升级人类的路径可达；
6. **确定性**：同 domain 快照+同 params 两次 evaluate 的 snapshot 逐字段一致（不变量 3）；
7. **趋势数据面**：≥N 个周期快照序列可查（T3.2 前置），watch/drift 等级分布合理；
8. **误报防护**：单窗口边界值（composite 在 drift 阈±ε）不触发 medium 风险校准（滞回自检）。
