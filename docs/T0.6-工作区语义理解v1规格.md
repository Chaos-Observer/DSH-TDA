## 1. 设计裁定

| # | 裁定 | 理由 |
|---|---|---|
| J1 | **两层扫描：确定性采集本地做 + 语义标注走 T0.5 Sidekick**：文件清单/元数据/hash/git 跟踪状态由 workspace 插件本地采集（无需 LLM）；显性依赖解析确定性做（import/require/路径引用）；**隐性依赖启发式、版本脉络摘要、可信度初判经 `ctx.subagentDispatch` 派 Sidekick**（read-only sandbox、maxDepth=0、结构化结论 schema） | C2 复用：文件正文只进子代理，主上下文与时间线只见摘要结论；§3.2.2 的"识别"三件事中只有启发式判断需要模型，确定性部分不付 LLM 成本 |
| J2 | **扫描根 = T0.2 `task.localPath`**（规范化 workspace 相对、禁逃逸，承 T0.2 J7）；范围=localPath 子树 + 任务 `writeScopes` 声明路径；上限强制：maxFiles（默认 2000）/maxBytes/skip 规则（`.git`/`node_modules`/`dist` 等可配置），超限产**显式 truncated + unfinished**，不静默截断 | 需求"任务本地路径是起点"；C5 显式终态原则——扫描失败/截断必须可见；防巨型树拖垮执行 |
| J3 | **三层产出**：① `FileInventory`（确定性：路径/大小/mtime/hash/扩展名/gitTracked/ignored）② `SemanticNotes`（LLM：角色 doc/code/config/data/artifact、显性依赖边、隐性 related-to 启发式、版本脉络摘要）③ `CredibilityHints`（权威源 vs 草稿初判） | §3.2.2 识别三事项（显性/隐性依赖、版本演化脉络、可信度层级）逐项落数据面 |
| J4 | **可信度初判 = 提示非裁决**：只产 `credibilityHint: 'authoritative-likely'\|'draft-likely'\|'unknown'`（信号：命名 draft/wip/tmp/old/副本、目录角色 docs/ vs scratch/、git 跟踪状态、mtime 新旧），**任何文件不因扫描自动升格为知识**；知识出库仍需复用/审查，固化走 T1.2 治理 | §3.6 知识行"脱节/无权威源/被覆盖→出库需复用/审查"；防"扫描即信任"——工作区状态是证据不是权威 |
| J5 | **局部知识图谱雏形 = sqlite domain**：文件节点 + 依赖边（`depends-on` 显性/`related-to` 隐性/`supersedes-file` 版本链），边带 confidence+evidence；即 T3.1 分层知识图谱的前置数据面（Graphiti 外的 SQLite 最小形态，同 T0.3 决策点①边界原则） | §3.2.2"从文件系统状态动态构建局部知识图谱"；Wiki 蒸馏/互链归 T3.1，P0 只建不改层 |
| J6 | **扫描结果汇 T0.3 时间线，两条 chunk 分证**：inventory 摘要=`credential:'execution-verified'`（文件系统状态是执行验证过的事实）；语义标注=`credential:'model-produced'`（低凭证，召回侧受 credentialMin 约束）；均 `source='task'`、`relatedTaskId=taskId`、`trajectoryLink=scanRunId/childSessionId`。**文件正文永不进时间线**（工具输出类内容只入子代理结论摘要） | §5.2 凭证分层 + §5.5 审计基线；扫描结果可追溯但不污染主事实流 |
| J7 | **增量扫描**：`scan_cache`（size+mtime+hash 三级）；重复扫描只重采变化文件、只对变化文件集重跑语义标注（每 scan 批注上限 N，防 LLM 成本侵蚀主任务——承 §3.6 维护吞吐上限精神） | "动态构建"的成本可控形态；全量扫描按任务触发或显式 refresh |
| J8 | **事件驱动常驻扫描点**：任务 claim/执行收敛/verifying 三个时点各触发一次增量扫描（Harness 钩子订阅 taskPool/change），扫描是任务生命周期内的常态动作而非一次性快照 | §3.2.2"动态"落地方式；文件状态随任务演进而更新，图谱保持新鲜 |

## 2. 状态模型

scan run 状态机（append-only 历史，无 CAS——记录创建即不可变，同 T0.3 时间线哲学）：

```
requested ──► inventorying ──► annotating ──► recorded
                     │              │
                     └── failed(reason, unfinished) ◄── 任一阶段（显式终态，C5）
```

| 状态 | 含义 |
|---|---|
| `requested` | 建单（任务存在、localPath 有效、无同任务并发 scan——后到者排队） |
| `inventorying` | 本地采集（含 cache 比对、忽略规则、上限检查） |
| `annotating` | 变化文件集经 T0.5 dispatch Sidekick 语义标注（等结论回传） |
| `recorded` | 图谱更新 + 两条 timeline chunk 落库 + ScanRun 终态 |
| `failed` | 带 reason + unfinished（超限 truncate 也记 failed-with-partial：部分成果保留） |

- 并发控制：同任务 scan 串行（进程内队列）；跨任务可并行（受 Sidekick 并发帽约束，T0.5 J10）。

## 3. 数据模型

### 3.1 `FileNode`（domain 记录）

```ts type-equiv
/** 文件节点全量。key = taskId#path。 */
interface FileNode {
  readonly taskId: TaskId
  readonly path: string                    // workspace 相对、规范化、localPath 前缀内
  readonly size: number
  readonly mtime: number
  readonly contentHash?: string            // 小文件算（≤hashMaxBytes），大文件只 size+mtime
  readonly ext: string
  readonly ignored: boolean                // skip 规则命中（仍登记，标注不计入上限）
  readonly gitTracked?: boolean            // 版本线索（U1：P0 只取跟踪状态+HEAD 摘要）
  readonly role?: 'doc' | 'code' | 'config' | 'data' | 'artifact' | 'unknown'   // LLM 判定
  readonly credibilityHint?: 'authoritative-likely' | 'draft-likely' | 'unknown' // J4：提示非裁决
  readonly lastScanId: ScanId              // 最后标注来源
}
```

### 3.2 `GraphEdge`（domain 记录）

```ts type-equiv
/** 局部图谱边。key = taskId#from#to#kind。 */
interface GraphEdge {
  readonly taskId: TaskId
  readonly from: string                    // 文件路径（边尾）
  readonly to: string                      // 文件路径（边头，必存在节点）
  readonly kind: 'depends-on' | 'related-to' | 'supersedes-file'
  readonly confidence: number              // 0–1（隐性边由 LLM 自评，显性边=1）
  readonly evidence?: string               // import 语句/命名约定/版本线索摘要
}
```

### 3.3 `ScanRun` / `ScanCache`

```ts type-equiv
interface ScanRun {
  readonly id: ScanId                      // branded，单调分配 scan-<n>
  readonly taskId: TaskId
  readonly mode: 'full' | 'incremental'
  readonly status: 'recorded' | 'failed'
  readonly startedAt: number
  readonly finishedAt: number
  readonly filesScanned: number
  readonly filesChanged: number            // 本次重标注文件数
  readonly truncated: boolean              // 上限命中（J2）
  readonly unfinished?: string[]           // failed/truncated 时的未完清单（C5）
  readonly inventoryEntryId?: EntryId      // T0.3 timeline chunk（execution-verified）
  readonly notesEntryId?: EntryId          // T0.3 timeline chunk（model-produced）
  readonly childSessionId?: SessionId      // T0.5 dispatch 子会话（轨迹链接）
}
/** cache：key = taskId#path；{ size, mtime, contentHash?, lastScanId }，三级命中跳过标注。 */
```

### 3.4 SQLite schema（`ctx.storage` sqlite domain，DomainSpec）

| 表 | 键 | 值 | 说明 |
|---|---|---|---|
| `ws_file_nodes` | `TaskId#path` | FileNode | 图谱节点权威；layout `single` |
| `ws_graph_edges` | `TaskId#from#to#kind` | GraphEdge | 图谱边；重扫可重写（边是派生视图，非事实历史——与 T0.3 append-only 不同，见不变量 8） |
| `ws_scan_runs` | ScanId | ScanRun | append-only 扫描历史 |
| `ws_scan_cache` | `TaskId#path` | cache 行 | 增量依据 |

- domain version=1；`invalidRecords:'backup-and-skip'`（工作区图谱是派生数据，损坏可重建——与 T0.1/T0.2 权威表的"拒绝打开"区分）。

## 4. 不变量与服务 API

### 4.1 不变量（加载即校验 / 运行时强制）

1. **路径安全**：扫描根=规范化 localPath 前缀；禁 `..`/绝对路径/符号链接 realpath 逃逸；
2. **内容隔离**：文件正文不进主上下文、不进时间线——只以 Sidekick 结论摘要形态出现（C2）；
3. **凭证分层**：inventory=`execution-verified`、notes=`model-produced`；`credibilityHint` 永不作知识固化依据（J4）；
4. **增量正确**：cache 三级全命中跳过标注；任一维变化必重标注并更新 `lastScanId`；
5. **上限强制**：maxFiles/maxBytes/批注上限超限 → `truncated=true` + unfinished 清单，记录仍终态（C5）；
6. **引用完整**：边的 `to` 必存在文件节点；`supersedes-file` 成链无环；
7. **扫描串行**：同任务同时至多一个 scan 进程内执行；
8. **图谱可重建**：file_nodes/edges 可由 scan_runs 历史全量重建（派生数据，损坏 backup-and-skip 后重扫）。

### 4.2 `ctx.workspace` 服务方法

```ts type-equiv
interface WorkspaceService {
  scan(caller, req: { taskId: TaskId; mode?: 'full' | 'incremental'; maxFiles?: number }): ScanRun
  files(taskId: TaskId, filter?: FileFilter): FileNode[]        // role/ignored/hint 维度
  edges(taskId: TaskId, filter?: EdgeFilter): GraphEdge[]      // kind/confidence 维度
  graph(taskId: TaskId): { nodes: FileNode[]; edges: GraphEdge[] }  // 局部图谱视图（T3.1 前置）
  runs(taskId: TaskId): readonly ScanRun[]
  hints(taskId: TaskId): { path: string; credibilityHint: NonNullable<FileNode['credibilityHint']> }[]
}
```

- `scan` 内部序：校验 localPath → inventory 采集（cache 比对）→ 变化集批注（`ctx.subagentDispatch.dispatch(taskId,'sidekick')` 复用——标注结论 schema = T0.5 `sidekick-conclusion` + `fileAnnotations[]` 扩展字段，P0 内嵌）→ 更新图谱 → 两条 timeline append → ScanRun 终态；
- Sidekick 标注 prompt 只含：变化文件清单（路径+头部片段摘要，由插件按 token 预算裁剪）+ 输出 schema；不含主上下文（承 T0.5 J2）；
- 模型可见性：扫描结论**不自动进上下文**；Harness/模型经 `task:state` section 的裁剪视图见 hints 摘要（权威源/草稿计数）；图谱查询走 `workspace` 服务或 T3.1 召回（T1.1 之后）。

## 5. 与 DSH 的对接点

| 对接面 | 机制 |
|---|---|
| 文件采集 | 本地 FS 原语（readdir/stat/realpath/hash）；不走模型——LLM 只见 Sidekick 结论（C2） |
| 子代理标注 | 完全经 T0.5 `ctx.subagentDispatch`（spawn/read-only/maxDepth=0/outputSchema）；subagent/start\|end 观察事件为对账源 |
| 持久化 | `ctx.storage` sqlite domain（同 T0.1/T0.2 模式）；派生数据 `invalidRecords:'backup-and-skip'` |
| 审计 | 两条 timeline chunk 双写 log-only session event `timeline/write`（承 T0.3 J3）；T0.7 replay 可还原扫描时序 |
| 任务层 | 扫描触发钩子订阅 T0.2 `taskPool/change`（claim/verify 时点，J8）；`relatedTaskId` 弱链接解耦（承 T0.3 J8） |
| 上下文层 | hints 摘要视图进 T0.4 memo/injection 区（预算内）；工作区"页"与 T0.4 分页树的对应关系留 U5 |
| 知识层 | `graph(taskId)` 是 T3.1 Wiki 蒸馏的输入；credibilityHint 供 §3.6 知识治理参考（不自动固化，J4） |

## 6. 验收标准（对 Gate G0 的贡献项）

1. 对一个真实任务 localPath 全量扫描：inventory 完整（忽略规则命中正确）；显性依赖边抽样正确（import 解析）；`supersedes-file` 版本链样例（draft→final 命名对）正确；
2. **G0-② 延伸**：kill -9 重启后 file_nodes/edges/scan_cache 完整恢复；cache 损坏时 backup-and-skip 后重扫可重建；
3. 增量：改 1 文件后增量扫描只重标注该文件（cache 命中验证），时间线恰新增两条 chunk（inventory/notes），`relatedTaskId` 正确；
4. **内容隔离自检**：主会话 surface 与时间线中 grep 不到被扫描文件正文片段（零泄漏）；
5. **凭证自检**：inventory chunk 在 `credentialMin='execution-verified'` 可见、notes 为 model-produced；credibilityHint 不触发任何知识固化路径；
6. 上限：超大目录触发 `truncated+unfinished` 显式标记而非静默丢文件；
7. Sidekick 标注经 T0.5 门（read-only/maxDepth=0/outputSchema 校验），结论 schema 失败按 partial 处理；
8. 同任务并发 scan 串行（第二个排队不报错、不双跑）。
