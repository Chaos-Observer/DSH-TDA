## 1. 设计裁定

| # | 裁定 | 理由 |
|---|---|---|
| J1 | **定位=人读呈现层，全项目最轻插件**：无自有 domain、无事件族、无双写——纯投影层。deps 只注入既有只读服务面（goalTree/taskPool/taskGraph/supervision/drift/trajectory/timeline），每次请求实时聚合 | 缺口对账原状："数据原料齐（ConclusionView/timeline/evidence/dashboard/auditView），无呈现层"——缺的只是投影与渲染，不是新存储；呈现层若持 domain=第二展示权威，与 T3.2 J10"仪表盘=只读派生层零写权"同款防腐化 |
| J2 | **UI 形态拍板（关闭 T3.2 U4）= harness daemon 内嵌只读 HTTP 服务**：bind `127.0.0.1`（**禁 0.0.0.0**，fail-loud 断言），端口可配（默认 7391，0=ephemeral），零认证（单用户本地）。备选形态评估：DSH surface 内嵌需 DSH 侧 UI 扩展点证据（真装配前不存在，留 U1）；CLI 无法承载树谱交互（降级为 export 补充面） | 三选一拍板：HTTP 面自包含于 harness 进程——不改 DSH 一行代码（全局建设模式）、跨平台（Node 内置 http，Windows/Ubuntu 同语义）、树谱与状态总览都需要富渲染；本地单用户场景零认证不扩大攻击面（禁 0.0.0.0 是硬边界） |
| J3 | **三视图面**：① **树谱视图**——T4.3 `treeView` 渲染（目标→任务层级+stage 徽章+预算区+焦点标记+预案虚线边），深度/容量帽承 T4.3；② **状态总览**——按目标滚动：phase×stage/任务完成度/预算三区/证据链回链（entryId→timeline）/drift 健康度（T1.5 三带）/注意力曲线（T3.2 attentionStatus）；③ **审批与审计**——pending 队列+whatToShow 摘要+定级理由+auditView 决策链+replayView 入口 | 直接对账缺口⑤⑥：树谱=①，状态与结果=②；③承 T3.2 J10/J11 既有数据面的呈现欠账；三面全部只读 |
| J4 | **展示层零交互写**：HTTP 仅 GET 路由；**批准/激活/重试等人类动作不经本层**——审批交互仍走 DSH User Approval seam（T3.2 模式复制的人类面），UI 只呈现"待你决断"项（whatToShow 摘要+approvalId）。token 禁现于本层（响应体禁含任何审批 token/凭证） | T3.2 J5"监督服务只发票不代跑"的展示面对偶——呈现层若可写=绕过注意力计量与审计链的后门；token 经 HTTP 传递=凭据泄露面（§5.2 凭证隔离） |
| J5 | **服务 API 与传输解耦**：`snapshot(scope)`/`report(scope, range)` 是纯聚合方法（可单测、可 CLI 复用）；HTTP 只是其传输面（路由=薄壳）。v1 静态资源=内联 HTML/JS 单页（零构建依赖、零 CDN） | 聚合逻辑与传输分离=可测性；内联单页=零前端工具链（monorepo 不加前端包）；CDN 禁入（CSP/离线纪律） |
| J6 | **实时性=拉取式**：页面轮询 2s + 手动刷新；SSE/websocket 留 U2（承 T4.3 U5 同款） | v1 数据量与变更频率下拉取足够；长连接=daemon 生命周期管理复杂度，随真装配后实测 |
| J7 | **状态报告产物**：`report(scope, range?)` 生成 markdown 人读报告（目标进展/任务结果+证据回链/预算消耗/drift/注意力），经 `timeline.append` 落时间线（`credential='execution-verified'`、`source='harness'`）——异步消费形态（不听诊页面时的周报/任务完成报告） | §4"决策轨迹可审计"的人读出口；报告内容全部派生自权威域事实故凭证=execution-verified（非模型自产）；补"状态与结果展示"的异步半区 |
| J8 | **安全纪律**：bind 127.0.0.1（J2）；只读 GET；所有文本字段经 HTML/markdown escape 后渲染（label 注入 `<script>` 用例必挡——同 T0.5 诊断消毒/T0.6 消毒纪律的展示面对偶）；原文片段≤3×500 纪律仅在 T3.2 whatToShow 人类面，**不经 HTTP 传输** | 展示面是新增攻击面：XSS（渲染注入口）/越权 bind（网络暴露面）/凭证泄漏（token 面）三面各一条硬纪律 |
| J9 | **fail-open 隔离**：display 故障（HTTP 崩/聚合抛错）不反噬主链路——独立 try/catch 边界 + tick 不依赖 display 存活；daemon kill 重启后 HTTP 无状态自恢复 | 呈现层是观测面不是执行面（同 T1.5 J1 检测器零写权的隔离逻辑）；display 挂掉不该让任务停转 |
| J10 | **验收对 Gate G4-④**（需求进得来 T4.2/任务自动转 T4.1/图谱问得出 T4.3/人看得见本规格） | G4 闭环的最后一面 |

## 2. 状态模型

```
（无自有状态机——纯投影层）
HTTP 服务生命周期：stopped ──startServer()──► listening ──stopServer()/dispose──► stopped
聚合新鲜度：每次请求实时聚合（无缓存；v1 不加 TTL 缓存，数据量级小）
```

- 唯一"状态"=服务监听生命周期（进程内，重启即恢复，零持久化）；
- 视图数据全部实时读权威域——**不存在"展示态与权威态不一致"的可能**（无中间存储）。

## 3. 数据模型

**无自有 domain、无表、无事件族、无双写**（J1）。本节只定义传输契约。

### 3.1 `StatusSnapshot`（聚合投影，非持久化）

```ts type-equiv
/** 三视图合一快照（每次请求实时聚合）。 */
interface StatusSnapshot {
  readonly at: number
  readonly spectrum: TreeSpectrumView            // T4.3 treeView（树谱视图数据源）
  readonly overview: {
    readonly focusGoal?: GoalSummary             // 焦点目标：objective/phase×stage/预算三区
    readonly goals: readonly GoalSummary[]       // 全部目标摘要（按 queuePosition）
    readonly tasks: { ready: number; executing: number; awaitingApproval: number; verifying: number; blocked: number; completedToday: number }
    readonly drift?: { band: 'normal' | 'watch' | 'drift'; trend: readonly number[] }   // T1.5
    readonly attention?: AttentionStatus         // T3.2：三区+digest 深度+units
  }
  readonly approvals: readonly ApprovalDigestItem[]  // pending 队列（whatToShow 摘要+定级理由；零 token）
  readonly audit: { readonly recentDecisions: readonly AuditDigestItem[] }  // T0.7 auditView 摘要
}
interface GoalSummary {
  readonly goalId: string
  readonly objective: string                     // 截断 ≤120
  readonly phase: string
  readonly stage: string
  readonly zone: string                          // 预算三区
  readonly taskCount: number
  readonly completedCount: number
}
/** 报告产物（J7）：markdown，落 T0.3 timeline（execution-verified）。 */
type StatusReport = string
```

### 3.2 HTTP 路由表（只读白名单）

| 路由 | 方法 | 内容 |
|---|---|---|
| `/` | GET | 单页应用（内联 HTML/JS，三视图 tab） |
| `/api/snapshot` | GET | StatusSnapshot JSON（`?scope=` 可选过滤） |
| `/api/report?range=` | GET | markdown 报告（同 `report()` 输出） |
| `/api/export/dot` ・ `/api/export/json` | GET | 透传 T4.3 `export`（树谱导出） |
| `/api/health` | GET | `{ ok, at, version }`（探活） |

- **路由表白名单外一律 404；任何非 GET 方法一律 405**（J4 类型/路由级保证）；
- 响应头：`Content-Type` 按路由；`Cache-Control: no-store`（实时性）。

## 4. 不变量与服务 API

### 4.1 不变量（加载即校验 / 运行时强制）

1. **零写权**：无自有 domain、无事件族、无 `dualWrite*` 调用（类型级：内核工具不进 deps）；唯一写路径=J7 报告经 `timeline.append`（T0.3 服务面，credential 服务端强制）；
2. **bind 127.0.0.1**：`startServer` 拒绝非 loopback host（fail-loud）；禁 0.0.0.0/公网 IP；
3. **只读 HTTP**：路由白名单+方法白名单（J4）；写路由不存在（路由表白名单单测）；
4. **token 禁现**：snapshot/report/HTTP 响应体禁含审批 token/凭证/hash 链正文（响应体 grep 自检用例，同 T3.4 载荷零泄漏纪律的展示面对偶）；
5. **转义**：所有经 HTML/markdown 渲染的文本字段必过 escape（XSS 用例：objective/label 含 `<script>` 被 neutralize）；
6. **实时一致**：snapshot 与权威域当前态逐字段一致（对账单测：随机变更后立即查）；
7. **报告凭证**：report 落时间线时 `credential='execution-verified'` ∧ `source='harness'`（服务端强制，调用方无法指定）；
8. **fail-open**：display 聚合/HTTP 抛错不传播到 tick 或其他插件（隔离边界对账测试）。

### 4.2 `ctx.statusDisplay` 服务方法

```ts type-equiv
interface StatusDisplayService {
  initialize(): Promise<void>
  startServer(opts?: { port?: number; host?: string }): Promise<{ url: string; port: number }>  // host 默认 127.0.0.1（不变量 2）
  stopServer(): Promise<void>
  snapshot(scope?: DisplayScope): StatusSnapshot        // 纯聚合（CLI/HTTP 共用）
  report(scope: DisplayScope, range?: { from?: number; to?: number }): Promise<StatusReport>  // J7：生成+落时间线
  serverStatus(): { listening: boolean; url?: string; port?: number }
}
```

- **装配层接线（harness）**：runtime 把只读柄（goalTree/taskPool/taskGraph/supervision/drift/trajectory/timeline 的只读面）注入 statusDisplay；`startServer` 由 daemon 启动序调用（可配开关，测试环境不起服务只调 snapshot）；
- **CLI 补充面**：`report()` 可经 harness 直出（无 HTTP 的人读出口，补 J2 评估中 CLI 的降级价值）；
- **无模型工具**（全局纪律 3）。

## 5. 与 DSH 的对接点

| 对接面 | 机制 |
|---|---|
| 传输 | Node 内置 `http` 模块自包含于 harness 进程；**零 DSH seam 依赖**（J2：不改 DSH 一行代码） |
| 数据 | 全部 `ctx.*` 只读服务面实时聚合（T4.3 treeView/export、T0.1 focusView、T0.2 list、T3.2 dashboard/attentionStatus/pending、T1.5 趋势、T0.7 auditView） |
| 人类动作 | 不经本层（J4）——审批交互走 DSH User Approval seam（T3.2 模式复制）；UI 只呈现 |
| 审计 | 不产事件（无域）；报告落 T0.3 时间线（J7）经既有 PIPE 与凭证体系 |
| KV-cache | 零父侧工具/schema 增量（无模型工具面），不影响 T0.4 前缀稳定性 |

## 6. 验收标准（对 Gate G4-④ 的贡献项）

> **验收结果（2026-10-14 IT17，全部通过）**：①树谱视图=treeView 透传+层级/徽章/区域/焦点/预案虚线（页面 DOM textContent 构建）✓；②状态总览=目标摘要+任务六计数+drift 三带趋势+注意力三区（与权威域对拍）✓；③审批呈现=pending+whatToShow 摘要+定级理由，**响应体零 token**（grep 自检 + excerpts 剥除）✓；④决策链=events 尾窗 20 条（approved/rejected/cancelled）✓；⑤报告=markdown 落时间线（credential='execution-verified'/source='harness' 服务端强制），/api/report 输出一致 ✓；⑥导出透传=/api/export/dot|json 对拍 T4.3 ✓；⑦安全三纪律=非 loopback fail-loud/404-405 白名单/`<script>` 注入 escape（集成门实证）✓；⑧零写权=快照前后权威域 revision 零变化（集成门对账）✓；⑨fail-open=supervision/drift 抛错降级记名（degraded 列表）+HTTP handler try/catch 不击穿 ✓；⑩kill -9=HTTP 无状态自恢复（stop/start 往返用例）✓。
>
> **实现补记**：页面静态零动态数据（数据全走 JSON API + textContent——比 escape-and-innerHTML 少一类注入面）；`source='harness'` 落地时扩 T0.3 `TIMELINE_SOURCES`（附加值向后兼容）并顺修 4 处窄视图类型（governance/context/dispatch/workspace seam）；display 默认不装配（displayEnabled 开关，测试环境零端口占用）。

1. **树谱视图**：`/` 页渲染目标→任务层级+stage 徽章+预算区+焦点+预案虚线边，与 T4.3 treeView 逐字段对账；
2. **状态总览**：任务状态计数/目标摘要/drift 三带+趋势/注意力三区正确聚合（与各权威域对拍）；
3. **审批呈现**：pending 队列+whatToShow 摘要+定级理由可见；**响应体零 token**（grep 自检用例）；
4. **审计视图**：recentDecisions 摘要链可查（approvalId→audit_index 定位可验）；
5. **报告产物**：`report()` 生成 markdown 落时间线（execution-verified/harness），内容与权威域对账；`/api/report` 输出一致；
6. **导出透传**：`/api/export/dot` 输出可被 Graphviz 渲染（对拍 T4.3 export）；
7. **安全三纪律**：非 loopback host 被拒（fail-loud）；写路由/非 GET 方法 404/405（路由表白名单单测）；`<script>` 注入 label 被 escape（XSS 用例）；
8. **零写权**：display 全生命周期内除报告时间线条目外零权威域变更（对账测试）；
9. **fail-open**：聚合抛错/HTTP 崩不拖垮 tick（对账测试：display deps 注错后 tick 照常）；
10. **kill -9**：daemon 重启后 HTTP 自恢复（无状态），snapshot 即时一致。

## 7. 未决项

- U1：DSH surface 内嵌形态（UI 作为 DSH surface 扩展渲染于会话界面）——需 DSH 侧 UI 扩展点证据；v1 HTTP 自包含；随 DSH 真装配（系统性前置）评估收敛；
- U2：实时推送（SSE/websocket 替代轮询）——v1 轮询 2s；随连接数与实测时延拍板（同 T4.3 U5）；
- U3：多用户/远程访问认证（远程看板需求）——v1 单用户本地零认证；需求出现时连同 token 传输面一并重设计（含 TLS）；
- U4：前端形态深化（v1 内联单页零构建；组件化/框架化随交互深度——树谱点击展开/筛选/时间回放）——随使用反馈；
- U5：报告分发通道（v1 只落时间线+UI/CLI 可读；邮件/Agent Mail 推送随需求）；
- U6：树谱渲染深度策略（v1 全量+深度帽承 T4.3 容量帽；超宽树的懒加载/聚焦裁剪）——随实测规模。
