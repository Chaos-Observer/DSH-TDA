## 2. 状态模型

### 2.1 蒸馏 run 状态机（J6/J10）

```
distill(trigger) → pending → clustering(证据簇, ≤clusterCap) → distilling(Sidekick 子代理, 结构化候选)
                                                                    │
                                                                    ▼
                                              validating(证据存在性+凭证继承+矛盾检测)
                                                                    │
                                                                    ▼
                                              recorded(候选落库 draft; 验证不过的跳过记 reason)
   clustering/distilling/validating 阶段异常 → failed(stage+reason 显式终态)
   部分候选证据不全 → recorded ∧ skipped 清单非空（partial 语义由 skipped 承载）
```

### 2.2 条目生命周期（治理管道第二实例，J5）+ 双时序（J4）

```
propose/distill ──► draft ──validate──► validating ──requestConsolidate(出库阀)──► consolidated ──► ingest Graphiti + 物化 chunk
                     │                      │                                              │
                     └── retire(治理/coach/人工)◄─────────────────────────────────────────────┘
consolidated ∧ 矛盾新条目 ──► invalidate(旧条目 validTo 置位; Graphiti 失效+T0.3 invalidate 双记; 不删除)
invalidated ──re-assert(治理: 人工/coach)──► 新版本 append(supersedes 链; Graphiti 新 episode)   # 版本可回滚
```

- 双时序：`validFrom/validTo`=事件时（知识在世界中为真时段），`ingestedAt`=系统时；TDA 镜像，Graphiti 权威；
- 状态=治理投影镜像（承 T1.2 J10 分层：权威在 gov_states，本 domain 的 status 字段只读镜像）。

## 3. 数据模型

### 3.1 `KnowledgeEntry`（TDA 映射+元数据）/ `KnowledgeCandidate`

```ts type-equiv
interface KnowledgeEntry {
  readonly entryId: KnowledgeEntryId            // 稳定业务 id
  readonly version: number                      // 条目版本（supersedes 链）
  readonly supersedes?: KnowledgeEntryId
  readonly kind: 'moc' | 'concept' | 'method' | 'entity'
  readonly title: string                        // ≤60 字符（MOC/概念名）
  readonly summary: string                      // ≤300 字符陈述（进 Graphiti episode 的内容=此摘要, J3）
  readonly chunkRef?: TimelineEntryId           // consolidated 后物化 chunk（内容权威=时间线, J8）
  readonly graphRef?: string                    // Graphiti 节点/episode 引用（仅 consolidated 后非空, J2）
  readonly status: 'draft' | 'validating' | 'consolidated' | 'retired' | 'invalidated'   // 治理投影镜像
  readonly credential: Credential               // = min(证据 chunk 凭证)（J9）
  readonly authorityHint?: 'authoritative-likely' | 'draft-likely' | 'unknown'   // T0.6 hints 继承（J9）
  readonly validity: { validFrom: number; validTo?: number; ingestedAt: number }  // 双时序镜像（J4）
  readonly evidence: { chunkRefs: TimelineEntryId[]; trajectoryRefs: TrajectoryRef[]; fileRefs?: string[] }
  readonly stats: { reuseCount: number; verifyCount: number; associationSpread: number }   // §3.3.4 提炼评分三信号
  readonly createdBy: 'distill' | 'coach' | 'human'
  readonly createdAt: number
  readonly updatedAt: number
}

interface KnowledgeCandidate {                  // 蒸馏产出（子代理结构化结论）
  readonly kind: KnowledgeEntry['kind']
  readonly title: string
  readonly summary: string
  readonly edges: { toTitle: string; kind: EdgeKind; confidence: number }[]   // 同批候选间互边（按 title 对齐）
  readonly evidenceChunkRefs: TimelineEntryId[]
}

type EdgeKind = 'part-of' | 'relates-to' | 'derives-from' | 'contradicts' | 'exemplifies' | 'supersedes'
```

### 3.2 `KnowledgeEvent`（权威）/ `KnowledgeRun`（投影）

```ts type-equiv
interface KnowledgeRun {
  readonly runId: KnowledgeRunId
  readonly trigger: { kind: 'maintenance' | 'periodic' | 'manual'; clusterRefs?: TimelineEntryId[] }
  readonly status: 'pending'|'clustering'|'distilling'|'validating'|'recorded'|'failed'
  readonly stage?: 'cluster'|'distill'|'validate'
  readonly failureReason?: string
  readonly clusterCount: number
  readonly candidatesProposed: string[]         // entryId 清单（draft 落库）
  readonly skipped: { reason: string; clusterRef: string }[]   // 证据不全/矛盾未决跳过（J6）
  readonly reportChunkIds: string[]             // 时间线回写（run 摘要, model-produced）
  readonly startedAt: number
  readonly endedAt?: number
}

interface KnowledgeEvent {                      // append-only 权威日志
  readonly id: string
  readonly kind: 'distill-begin'|'candidate-proposed'|'entry-consolidated'|'entry-ingested'|'entry-invalidated'|'entry-reasserted'|'link-added'|'link-removed'|'distill-end'
  readonly entryId?: KnowledgeEntryId
  readonly detail: Record<string, unknown>      // JSON 无损（评分输入摘要/边/双时序值/失效原因）
  readonly at: number
}
```

## 4. 不变量与服务 API

### 4.1 不变量（加载即校验/运行时强制）

1. **内容权威在时间线**：Graphiti episode 载荷=summary+证据引用（禁正文）；条目内容变更=chunk supersede 新版本——grep 自检：knowledge domain 与 episode 载荷无 chunk 正文句；
2. **未验证零入图**：graphRef 非空 ⇒ status=consolidated（服务端断言）；draft/validating 条目无任何 Graphiti 写入事件（CI 断言）；
3. **失效不删+回滚有据**：invalidate 只置 validTo+双记（Graphiti+T0.3），无删除路径；re-assert=append 新版本（supersedes 链完整）；
4. **凭证继承**：entry.credential = min(证据 chunk 凭证)（服务端断言；quarantine 证据⇒条目≤model-produced，§5.2 图谱层继承）；
5. **出库阀**：consolidated ⇔（≥1 真实复用 ∧ 证据完备）∨ 人类审查 token（服务端断言，零复用固化拒绝=§3.6"出库需复用/审查"）；
6. **分层有界**：MOC 层级≤depthCap、单条目 MOC 父数≤fanInCap（建边时断言，防 wiki 迷宫）；
7. **治理单一**：本服务无 lifecycle 字段写路径、无 retire 本地实现——一切状态迁移经 `ctx.governance`（J5，同 T1.4 不变量 6）；
8. **可重放可重建**：distill/ingest/invalidate/link 全落 knowledge_events；kill-9 后 knowledge_runs 投影=events 重放结果；Graphiti 态可经 events 全量重摄入复现；
9. **外置降级不伪造**：Graphiti 不可用⇒neighbors 降级 FTS+映射且主链路不阻断；断连期 invalidate 排队（≤invalidateQueueCap）恢复重放；无伪造图态路径。

### 4.2 `ctx.knowledge` 服务方法

```ts type-equiv
interface KnowledgeService {
  // 蒸馏与提议
  distill(trigger: { kind: 'maintenance'|'periodic'|'manual'; clusterRefs?: TimelineEntryId[] }): KnowledgeRun  // J6
  propose(candidate: KnowledgeCandidate, by: 'coach'|'human'): KnowledgeEntry        // 直提候选（ coach/人 → draft）
  validate(entryId: KnowledgeEntryId): ValidationReport                              // 证据存在性+凭证+矛盾（J6）
  requestConsolidate(entryId: KnowledgeEntryId): GovAction                           // 出库阀（J5，经 ctx.governance）
  // 结构
  link(fromId: KnowledgeEntryId, toId: KnowledgeEntryId, kind: EdgeKind, evidence: TrajectoryRef[]): KnowledgeEdge  // J7（双帽断言）
  unlink(edgeId: string, reason: string): void                                       // 软删=记事件，边历史可溯
  reassert(entryId: KnowledgeEntryId, by: 'human'|'coach'): KnowledgeEntry           // 版本可回滚（J4，经治理）
  // 查询与召回集成
  entries(filter?: { kind?; status?; moc? }): KnowledgeEntry[]
  entry(entryId: KnowledgeEntryId): KnowledgeEntry
  neighbors(entryId: KnowledgeEntryId, depth?: number): { entries: KnowledgeEntry[]; edges: KnowledgeEdge[] }  // Graphiti hybrid search（J10 降级路径）
  expand(refs: TimelineEntryId[]): RecallCandidateRef[]                              // 图扩展候选源（J8，供 ctx.recall 消费）
  history(entryId: KnowledgeEntryId): KnowledgeEntry[]                               // supersede 版本链
  params(): KnowledgeParams
  setParams(patch: Partial<Omit<KnowledgeParams,'revision'>>): KnowledgeParams
}
```

- distill 内部序：聚类（确定性）→ 逐簇 dispatch Sidekick（`knowledge-distill` schema=KnowledgeCandidate 白名单，并发≤distillConcurrency）→ validate → draft 落库+事件 →（出库阀在治理侧）consolidated 时：物化 chunk（PIPE append）+ ingest Graphiti + graphRef 回写；
- ingest 时序：物化 chunk 先（内容权威先行），Graphiti ingest 后（结构随后）——崩溃恢复时 chunk 在而 graphRef 空=未入图完成态，按事件日志补 ingest（J11）；
- 治理入口：`ctx.governance` 以 assetKind='knowledge' 实例化（validate/consolidate/retire/invalidate 动作经治理管道留痕 gov_actions）。

## 6. 验收标准（对 Gate G3 的贡献项）

1. **Wiki 蒸馏闭环（P3 里程碑主项）**：构造同任务关联笔记簇（≥3 chunk，reuse/associationSpread 达阈）→distill run→候选条目+边→validate→（模拟一次真实复用：recall 注入+任务 success）→consolidated→物化 chunk 可经 T1.1 召回 + Graphiti neighbors 可检索；零复用 consolidate 被拒；
2. **分层互链**：MOC 条目+part-of 边+relates-to 边落地；超 depthCap/fanInCap 的建边被断言拒绝；MOC 路由 Top-K 注入视图正确；
3. **矛盾 invalidation+回滚**：新 consolidated 条目与旧条目 contradicts→旧条目 validTo 置位（Graphiti 失效+T0.3 invalidate 双记、回放可见）→reassert（人类 token）→新版本 append、supersedes 链完整；
4. **凭证继承+gate**：quarantine 证据簇蒸馏→条目 credential=model-produced→T1.1 gate 下不自由浮现（双条件构造验证）；authorityHint 从 T0.6 hints 正确继承；
5. **外置降级**：停 Graphiti→neighbors 降级（FTS+映射）且主任务链路不阻断（计时断言）；断连期 invalidate 排队≤帽、恢复后按 seq 重放、图态最终一致；
6. **审计回放**：distill/ingest/invalidate/link 全落 knowledge_events+session event；kill-9 后 knowledge_runs 投影=events 重放；Graphiti 经 events 全量重摄入后条目/边集合等价；
7. **G3-② 审计面延伸**：任一条目可反查证据 chunk+trajectoryRefs（§3.3.4 反向追溯）+ 治理动作链（gov_actions）——"每步决策可审计可回放"在知识层的形态；
8. **维护协同对账**：条目 stats 三信号增长→T2.3 维护引擎可见（升格建议/互链建议入口）；矛盾条目的收敛走 reassert/invalidate 而非直接改内容。
