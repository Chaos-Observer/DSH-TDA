## 2. VCPToolBox 深挖（记忆引力场源头）

RiverMemo V10 / TagMemo V10 已到工程化阶段：双尺度连续场 + 相对拓扑 + Ω 可观测泛函 + **直接事实锚**闭合为"有界、可审计的记忆寻址"；黄金测试对比 V9 +26%；Rust/Rayon，热点计算 2.5ms。

可直接借用：
- **分类型时间衰减日记本**：单一事件类记忆可单独设衰减 → 事实时间线按 chunk 类型配衰减参数
- **梦系统**：后台 AI 在"梦中"整理记忆、按任务/日程预学习 → **coach 元进程的先行验证**
- **Gravitational IPC Bridge**：工具调用感知上下文语义引力场 → L2/L3 中介的事件级参考
- **上下文折叠**：遍历 UI 状态不占持久化上下文 → page 按需加载的实证
- **OneRing**：跨客户端单一近期事实流 → 验证"多会话是败笔"

**安全警示**：VCP 自身 npm 依赖大量高危漏洞且权限极大——借鉴记忆架构，不照搬部署形态。

## 5. 轨迹资产：三态消费模式（对蓝图的重要升级）

**轨迹（Trajectory）不只是审计回放材料，它是一态资产、三种消费方式：**

### 5.1 回放（Replay）——审计与 rehearsal
- DSH Trajectory 原生支持 resume/fork/search/replay
- 用途：决策审计（人机监督）、技能 rehearsal（固化前重放验证）、失败归因

### 5.2 预测（Prediction）——世界模型降低不确定性
这正是你"解决任务时要降低不确定性、降低 LLM 迷惑度"的前沿答案：
- **WorldEvolver**（2606.30639）：自进化世界模型，部署时修订上下文而冻结参数。三模块：Episodic Memory（**检索式模拟真实 action transitions**）、Semantic Memory（**从预测-观测 mismatch 中提炼持久启发式规则**）、Selective Foresight（低置信预测过滤后才进推理上下文）
- **MCP-Cosmos**（2605.09131）：执行前用世界模型预测 pseudo-observation，提升工具成功率与参数准确率
- **Hybrid-WM**（2606.27806）：LLM 规划器 + 小参数转移模型预测**动作有效性/状态增量/风险/价值**；consistency gate 比对"想象增量 vs 参数预测"，仅在不一致时触发定向修订——减少幻觉状态传播

**对我们的落地**：
- P1 起建"轨迹预测器"：从历史轨迹检索相似 transition → 预测下一步状态/工具结果/风险，注入 Lead 规划审查
- **预测-观测 mismatch 是 coach 元进程的核心信号**：mismatch 模式 → 提炼启发式规则进元思维库/技能库（WorldEvolver Semantic Memory 机制）
- mismatch 同时是 perplexity gate 的**替代不确定性信号**（不依赖 logprobs 时的降级源）
- Selective Foresight → 低置信预测不注入主上下文（与 §3.4.2 gate 同构）

### 5.3 辅助召回（Assisted Recall）——历史轨迹即情景记忆
- ReAcTree：每个 agent 节点检索**子目标级**历史示例（episodic memory）
- Voyager：新任务嵌入描述 → 检索最相关已存技能并组合
- AppAgentX：从轨迹进化高层"捷径"
- **Chunk Schema 的轨迹链接字段**使技能/知识可从轨迹反向追溯——召回时不只召回"知识块"，还召回"当时怎么做的"

## 6. 技能库先行者：Voyager 的两条铁律（C4 的原始范式）

Voyager（2305.16291，TMLR）：自动课程 + 技能库 + 迭代提示自修复；技能=可执行代码，按 docstring 嵌入索引；3.3× 物品、15.3× 科技树速度、新世界零样本迁移 100%（基线 0%）。

**两条入库铁律，直接对应我们的治理管道**：
1. **每个前置技能必须已在库中**（前置条件检查 = 我们执行单元 contract 的 precondition）
2. **代码必须通过自验证才入库**（环境即单元测试 = 我们的外部验证阀）
> "unverified code never enters——so each new skill stands on solid, tested ground"（防止能力库复利垃圾）

遗留问题（Pebblous 评论一针见血）：**"GPT-4 评判自己的成功"——自主学习的训练数据谁验证？** 这正是我们外部验证阀 + 人类审批节点要回答的。

## 7. 记忆基建格局（细化决策点①）

| 框架 | 架构 | 关键机制 | 基准 |
|---|---|---|---|
| **Graphiti/Zep** | 时序知识图谱 | **双时序模型（事实有效期窗口）+ 矛盾时旧事实失效（invalidation）而非删除 + 混合检索（向量+BM25+图）+ episodic 摄入保 provenance** | LoCoMo 94.7% / LongMemEval 90.2%，<200ms |
| **Mem0** | 提取式事实层 | 单遍提取结构化记忆（事实/偏好/计划/纠正）；**add-only 覆盖**（新记忆显式 override 旧的，不破坏历史）；多信号检索 | LongMemEval 94.4 |
| **Letta（MemGPT）** | OS 式分层 | agent 自编辑 core-memory 块 + archival；自带 agent runtime | 长运行 agent |

**对我们卫生层的直接映射**：
- 单事实时间线 = Graphiti 双时序 + Mem0 add-only 的组合（追加式 + 有效期 + supersede 语义）
- "版本合并/回滚"矛盾协调 = Graphiti invalidation（旧事实标记失效而非删除）
- L0 工作记忆自编辑 = Letta core-memory 块
- **决策点①建议收敛为**：记忆/知识层**基于 Graphiti（OSS）构建或深度借鉴**，而非从零自建图查询；SQLite 仅做任务树/预算等结构化状态

## 8. 上下文工程实证（支撑 L2 设计）

- **Context rot**（Chroma 2025，18/18 前沿模型）：输入增长全部掉 Accuracy，~50% 填充率即明显衰减；"上下文窗口不是免费 RAM"
- **Less Context, Better Agents**：全历史 71% → 剪枝+摘要后 91.6%，token -63%，速度 2.5×
- Anthropic context engineering：**最小高信号 token 集**；四招 offload/reduce/retrieve/isolate（与我们 C2+分页+引力场召回一一对应）
- **SmoothAgent**（2607.00151）：上下文转换是**段可分解**的（前缀转换独立于未来 token）→ 可提前执行并预热 KV cache，TTFT -11.9×
- 行业侧证：阿里"Model/Harness/Context"三层架构与 Context Engine；Gartner 将"企业上下文层"列为独立架构问题

**新增工程约束（进架构文档）**：
1. 我们的上下文旋转/gate/分页转换必须**段可分解且 KV-cache 友好**（否则吃掉 DSH 99.93% 命中的红利，TTFT 爆炸）
2. "预算按百分比而非绝对 token"（各层级配比：pinned 约束/任务状态/召回/历史）
3. Context rot 数据是"单次交互不要给太多分散信息"的量化依据

## 9. 安全面（必须进需求文档的条款）

- **Sleeper Memory Poisoning**（2605.15338）：注入率最高 99.8%；中毒记忆召回后 60–89% 操纵行为；**proximity dependence——目标邻近查询高率召回中毒记忆**，正中我们任务状态相关召回的放大面
- **MemoryGraft**（2512.16962）：植入恶意"成功经验"模板，agent 语义模仿复用之；防御=**密码学溯源 attestation（CPA）**
- **MINJA**（NeurIPS 2025）：仅靠正常对话即可注入记忆
- **Plant-Persist-Trigger**（2605.28201）：1896 实例全部模型中招
- **Governance Decay**（2606.22528）：见 D3

**条款**：① C6 约束钉扎（pinned 豁免压缩）；② 记忆写入检疫（工具输出/外部内容永不直接固化）；③ provenance 链 + 召回侧 provenance gate（低凭证不浮现）；④ 控制流/数据流分离；⑤ 全量落 Trajectory 供投毒溯源。
