## 1. 设计裁定

| # | 裁定 | 理由 |
|---|---|---|
| J1 | **定位=只读聚合层，零新权威**：三种图数据的权威分别在 T0.1 `goal_nodes`（父子）、T0.2 `task_nodes`（parentTaskId/blockedBy/alternativeOf）、T0.6 文件图谱（depends-on/related-to/supersedes-file）。本插件只做投影与查询，deps 类型级只注入**只读**服务面，无任何权威写路径 | 缺口对账原状："图存下了但问不出来"——缺的是聚合面不是新存储；读模型若持有写权=第四处图权威，违背 C1 与"监督服务只发票不代跑"同款防腐化原则 |
| J2 | **物化派生表 + 可整表重建**：`graph_nodes`/`graph_edges` 为派生投影（`invalidRecords: 'backup-and-skip'`，丢失=rebuild，权威在别处）；承 T0.7 audit_index 模式（派生、可重建、不产事件） | 查询性能与导出稳定性需要物化；派生语义保证"删光重建零差异"可证（对账单测） |
| J3 | **增量驱动：总线只是任务侧快速路径，启动必全量重建**：订阅 `taskPool/change`（该族在总线上，IT2 联动面引入）做任务侧增量；`goalTree/change` **不在总线**（IT4 教训：goal-state 从不向总线发布——只订阅会整族漏掉），故 goal 侧走"tick/查询时对账重算"（goal 数量级小，全量便宜）；boot 时无条件 rebuild | 直接复踩 IT4 的坑（"消费全族不能依赖生产者发布总线"）会被集成门抓到——本规格在设计期按该教训裁定，重算路径+快速路径双保险 |
| J4 | **查询 API 六面**：`subtree(rootGoalId?)`（目标→任务贯通树）/ `taskGraph(taskId)`（单任务依赖+替代+文件邻域）/ `blockedChain(taskId)`（传递阻塞链）/ `crossGoalDependencies()`（跨目标依赖视图）/ `fileGraph(taskId)`（桥接 T0.6）/ `export(format, scope)`（json/dot） | 直接对账需求 §3.1.3 三关系：分解=subtree 父子边、依赖=blockedChain、替代=taskGraph.alternatives；跨目标依赖是单工作区任务池的常态形态（goalId 只做归属标记不限制边） |
| J5 | **树谱数据源**：`treeView(rootGoalId?)` 返回层级谱系视图（goal/task 节点+状态徽章+深度），专供 T4.4 树谱展示消费；零写权同 T3.2 J10 仪表盘纪律 | T4.4（树谱展示）的前置数据面；展示层零直写纪律在读模型侧预兑现 |
| J6 | **与 T0.6 的分工与桥接**：T0.6 管文件层（扫描派生、语义标注经 Sidekick），本插件管目标-任务层；唯一关联点=`task.localPath ↔ file nodes`，经 `workspace.graph(taskId)` 现成查询面桥接，**不复制文件图谱数据** | 防两个图谱层互相物化对方数据（双维护=双权威）；T0.6 的图谱查询面 IT3 已就绪，直接消费 |
| J7 | **容量帽 + 显式截断**：`maxNodes`/`maxEdges`（v1=10k/50k，params 可配）；超限返回带 `truncated: true` + `unfinished` 说明，禁静默截断 | 承 T0.6 上限强制纪律（超限 truncated+unfinished 显式终态）；C5 在查询面的形态 |
| J8 | **标签隔离**：节点 label 截断（≤120 字符，仅 objective/subject/路径）；文件节点的语义标注/可信度 hints **只引 id 不进 graph**（展示层按需回查 T0.6）——防 graph 成为内容泄漏面 | 同 T0.5 J5"主上下文只放摘要+引用"在读模型的对应；graph 表是可导出物（dot/json），泄漏面比域内快照更大 |
| J9 | **无环复核 fail-loud**：rebuild/增量后对 goal+task 合并图做环检测；权威域若被外部破坏（注入环），graph 显式报错拒建投影，**不渲染环、不静默跳过边** | T0.1 树五不变量之"树完整"与 T0.2"图无环"在聚合层的复核——读模型是这些不变量的第一个跨域消费者，破坏必须在聚合口暴露而非被吞 |
| J10 | **不立事件族、不产事件**：graph 是纯派生层，走内核 `dualWriteDerived`（仅域写、派生窗不计配对，承 T0.7 audit_index 先例——"必须持久却不能产事件，否则索引事件引发新索引"自指放大） | 事件族编号纪律（未登记族双写即抛）；派生层自指是唯一反例模式，内核已有成法 |

## 2. 状态模型

```
stale ──rebuild()──► rebuilding ──成功──► fresh ──(权威域变更/增量)──► fresh（增量应用）
                         │                    └──(goal 侧重算/tick 对账)──► fresh
                         └──超帽/环检测失败──► failed（显式终态，禁半成品投影）
```

| 状态 | 含义 | 进入 |
|---|---|---|
| `stale` | 初始或权威域变更未同步（goal 侧重算窗口期） | boot 前 / 检测到不同步 |
| `rebuilding` | 全量重建中 | `rebuild()` |
| `fresh` | 投影与权威域对账一致 | 重建/增量成功 |
| `failed` | 重建失败（环/超帽/域损坏），带 reason | 重建抛错 |

- 查询 API 在 `stale` 态可用（返回上次 fresh 投影 + `staleAt` 标记）；`failed` 态查询抛 `GRAPH_UNHEALTHY`（fail-loud，不返回可疑投影）。

## 3. 数据模型

### 3.1 投影类型（派生，非权威）

```ts type-equiv
/** 图谱节点：三源归一（goal/task/file）。ref=权威定位，非副本。 */
interface GraphNode {
  readonly id: string                     // 'goal-3' / 'task-17' / 'file:src/a.ts'
  readonly kind: 'goal' | 'task' | 'file'
  readonly ref: string                    // goalId / taskId / 工作区相对路径
  readonly rootGoalId?: string            // task/file 的归属根目标（goal 节点自身=id）
  readonly label: string                  // 截断 ≤120 字符（J8）
  readonly status: string                 // goal: phase×stage；task: phase×stage×zone；file: 存在性+scanId
  readonly depth: number                  // 子树内深度（root=0）
}
/** 图谱边：六类，advisory 标出不参与环检测与阻塞链（J9/T0.2 J4）。 */
interface GraphEdge {
  readonly from: string
  readonly to: string
  readonly kind: 'parent' | 'blockedBy' | 'alternativeOf' | 'dependsOn' | 'relatedTo' | 'supersedesFile'
  readonly advisory: boolean              // alternativeOf=true；其余 false
}
```

### 3.2 SQLite schema（派生表，backup-and-skip）

| 表 | 键 | 值 | 说明 |
|---|---|---|---|
| `graph_nodes` | node id | GraphNode | 派生；丢失=rebuild |
| `graph_edges` | `from#kind#to` | GraphEdge | 派生；丢失=rebuild |
| `graph_params` | `'singleton'` | GraphParams | 策略权威（容量帽/标签上限/scorerVersion） |

```ts type-equiv
interface GraphParams {
  readonly revision: number
  readonly maxNodes: number                // v1=10000
  readonly maxEdges: number                // v1=50000
  readonly maxLabelChars: number           // v1=120
  readonly rebuildPolicy: 'boot+task-subscribe+goal-reconcile'  // v1 唯一（J3）
}
```

- domain version=1；`invalidRecords: 'backup-and-skip'`（派生可重建）；
- **不立事件族、不产事件**（J10）：派生表写入走 `dualWriteDerived`（派生窗），不进双写配对。

## 4. 不变量与服务 API

### 4.1 不变量（加载即校验 / 运行时强制）

1. **零写权**：deps 只注入 `goalTree(只读: tree/get)/taskPool(只读: list/get)/workspace(只读: graph)`；本插件自有 domain 仅三张派生表；
2. **可重建**：删除全部派生表后 `rebuild()` 从三权威域完整重建，逐节点逐边零差异（对账单测）；
3. **无环复核**：rebuild/增量后合并图（parent+blockedBy+dependsOn 边）无环；检出环 ⇒ `failed` 显式终态，禁渲染环（J9）；
4. **advisory 豁免**：`alternativeOf` 边不参与环检测、不出现在 `blockedChain`（承 T0.2 J4）；
5. **引用完备**：每条 edge 的两端必在 nodes；悬空端 ⇒ rebuild 缺陷 ⇒ `failed`（禁静默丢边）；
6. **容量帽**：节点/边超 `maxNodes`/`maxEdges` ⇒ 查询结果带 `truncated:true` + unfinished 说明；
7. **标签隔离**：label ≤ `maxLabelChars`；文件节点不携语义标注内容（只引 scanId/路径，展示层回查 T0.6）；
8. **fresh 承诺**：`fresh` 态下 `subtree` 结果与权威域当前态逐字段一致（对账单测：随机变更后 reconcile 再查）。

### 4.2 `ctx.taskGraph` 服务方法

```ts type-equiv
interface TaskGraphService {
  initialize(): Promise<void>                              // boot 全量重建（先于不变量注册）
  rebuild(): Promise<RebuildReport>                        // 全量（domain 损坏恢复路径）
  subtree(rootGoalId?: GoalId): SubtreeView                // 贯通树：目标→子目标→任务（含 status 徽章）
  treeView(rootGoalId?: GoalId): TreeSpectrumView          // 层级谱系视图（T4.4 数据源，J5）
  taskGraph(taskId: TaskId): TaskGraphView                // 依赖+替代+文件邻域一元视图
  blockedChain(taskId: TaskId): readonly TaskId[]          // 传递阻塞链（含跨目标边）
  crossGoalDependencies(): readonly CrossGoalEdge[]        // 跨目标 blockedBy 投影
  fileGraph(taskId: TaskId): FileGraphView                 // 桥接 workspace.graph(taskId)（J6）
  export(format: 'json' | 'dot', scope: ExportScope): string  // 导出物（T4.4/人读）
  stats(): { nodes: number; edges: number; state: GraphState; truncated: boolean }
}
```

```ts type-equiv
interface SubtreeView {
  readonly rootGoalId: string
  readonly goals: readonly GraphNode[]                     // 拓扑序（父先子后）
  readonly tasks: readonly GraphNode[]                     // 归属该子树的任务
  readonly edges: readonly GraphEdge[]
  readonly truncated: boolean
  readonly unfinished?: readonly string[]
}
/** 树谱视图=subtree + 谱系标注（每节点的 stage 迁移历史计数/预算区/焦点标记）。 */
interface TreeSpectrumView extends SubtreeView {
  readonly focusGoalId?: string
  readonly annotations: readonly { id: string; stagePath: readonly string[]; zone: string; runCount: number }[]
}
interface TaskGraphView {
  readonly task: GraphNode
  readonly blockedBy: readonly TaskId[]                    // 直接
  readonly blocking: readonly TaskId[]                     // 反向（谁被它挡）
  readonly alternatives: readonly TaskId[]                 // advisory（标注非链）
  readonly children: readonly TaskId[]
  readonly files: FileGraphView                            // 内嵌文件邻域
}
```

- **装配层接线（harness）**：`runtime.tick()` 增加 goal 侧重算阶段（承 T4.1 tick 扩展同款：reconcile 成本 O(goals)，单工作区可忽略）；任务侧订阅 `taskPool/change` 增量（bus 快速路径，J3）；
- **导出格式**：json=上述 view 的无损序列化；dot=Graphviz（节点 shape 按 kind、advisory 边虚线、`truncated` 时附注释头），禁环渲染（`failed` 态 export 抛错）；
- **无模型工具**：本插件不挂工具集（全局纪律 3；观测既有 `task_list`/`task_get` 够用）；
- **实现补记（IT14b）**：① `reconcile()` 与 `rebuild()` 同为幂等全量重算（goal 数量级小全量便宜，v1 不做真增量 diff）；② bus 快速路径回调**必须显式 `.catch`**——dispose 后回声事件仍会触发（domain 已关），旁路失败静默、tick reconcile 兜底（IT14b 收口补记）；③ harness 默认装配**无 opt-in 开关**（零权威写不撞手动流，与 executor/planner 的 opt-in 纪律区分）；④ `setParams` 变更容量帽后需显式 `rebuild()` 生效（v1 不自动触发）。

## 6. 验收标准（对 Gate G4-③ 的贡献项）

> **验收结果（2026-10-13 IT14b，全部通过）**：①贯通树=subtree 深度/归属对账 ✓；②阻塞链=传递闭包+advisory 豁免 ✓；③跨目标依赖对拍 ✓；④文件桥接=零复制对账+未扫描空邻域不致命 ✓；⑤导出=json 无损+dot shape/虚线/截断注释头 ✓；⑥可重建=删光重建零差异+kill -9 后 boot 重建（集成门）✓；⑦零写权=假体调用日志全只读 ✓；⑧fail-loud=注入环 rebuild failed+查询 GRAPH_UNHEALTHY+修复后恢复 fresh ✓。

1. **贯通树**：`subtree(rootGoalId)` 返回 root→子目标→任务的完整层级，节点 status/深度/归属正确；与权威域逐字段对账零差异；
2. **阻塞链**：`blockedChain` 传递闭包正确（跨层、含跨目标边）；`alternativeOf` 标注任务不出现在链中；
3. **跨目标依赖**：`crossGoalDependencies()` 找出全部 blockedBy 跨目标的边（对拍 taskPool 全量）；
4. **文件桥接**：`fileGraph(taskId)` 返回 localPath 锚定的 depends-on/related-to/supersedes-file 邻域，与 `workspace.graph(taskId)` 一致（零复制对账）；
5. **导出**：json 无损；dot 可被 Graphviz 渲染且无环（advisory 虚线）；`truncated` 时附说明；
6. **可重建**：删光三张派生表 → `rebuild()` → 逐节点逐边零差异（对账单测）；kill -9 于重建中→重启后 boot 重建，投影不半成品；
7. **零写权**：graph 全查询面运行前后，三权威域 revision 集合不变（对账单测）；
8. **fail-loud**：向权威域注入环（测试夹具）→ `rebuild` 落 `failed`、查询抛 `GRAPH_UNHEALTHY`，禁渲染环/静默丢边。

## 7. 未决项

- U1：goal 侧精确增量（`goalTree/change` 上总线 publish 或 trajectory ingest 模式二选一）——v1 用 tick 重算（J3）；随 goal-state 是否补 publish 的裁定收敛；
- U2：关键路径分析（CPM：最长依赖链×预算速率→完成预测）——v1 只提供阻塞链深度原语；CPM 留 P5（依赖 T4.1 执行环的真实速率数据回填）；
- U3：图谱规模上限假设（单工作区 10k 节点）——超限后的分页/懒加载/按需子树策略，随 T4.4 展示交互形态拍板；
- U4：与 T3.1 知识图谱的边界（知识图谱=资产层概念关系，本图谱=目标-任务-文件执行结构）——v1 分层明确；互链（knowledgeEntry.relatedTaskId → 本图谱反查）留 P5；
- U5：图谱变更的推送语义（T4.4 展示层如何感知 fresh）——v1 拉取式（查询即对账）；SSE/websocket 随 UI 拍板；
- U6：file 节点的可信度 hints 入谱策略（v1 只引 id 不进内容）——展示层回查 T0.6 hints 的时延与缓存，随 T4.4 实测。
