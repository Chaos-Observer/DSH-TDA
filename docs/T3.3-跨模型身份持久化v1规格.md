# T3.3 · 跨模型身份持久化 v1 规格（identity 插件）

> 上游：《需求描述》v2.1 §3.3.3（双环结构：coach 元进程与 athlete 执行进程解耦；**coach 学到的优化跨模型可迁移**）+ §5.2（写入检疫=毒包面）+ §3.6（统一生命周期）、《架构与路线蓝图》（自成长行"coach 优化跨模型可迁移"；§7 对标 Meta HYPERAGENTS：coach/athlete 元进程自进化 SWE 20%→50% 且跨模型迁移；Letta 自编辑核心记忆参照）、《T2.1》（J6 跨模型迁移验证=逐候选 transfer.verified；U2 规则体表达力[结构化保迁移性]；U7 模型覆盖度）、《T1.4》（MetaPath 拓扑非语言内容=可迁移性结构基础；J4 判定确定性）、《T1.5》（calibrations 校准史）、《T0.7》（fork seam+rehearsal 协议+resume 工作状态恢复）、《T0.3》（supersede/invalidate 双更正通道）、《T3.2》（人类审批 token 消费方，新增 kind='identity-migration'）。

## 1. 设计裁定

| # | 裁定 | 理由 |
|---|---|---|
| J1 | **定位=身份持久化服务三层**：身份清单（manifest，当前生效身份=什么）+ 导出（快照=传输载体）+ 带验证迁移（换模型/模型升级时的重判定）。G3-③"跨模型迁移不丢身份"的承接口；**不造第二权威**——身份组件的内容权威永远在各组件域（coach/meta-thinking/校准），本服务只持清单+迁移史 | §3.3.3"coach 学到的优化跨模型可迁移"原文+HYPERAGENTS 实证；同 T3.1 J1/T2.3 J1 一贯纪律：编排/投影层不复制内容权威 |
| J2 | **身份边界裁定**（什么算/什么不算）：**身份=跨模型不丢的学得状态**=①策略集（coach 产出的 transfer-verified 候选，T2.1 J6）②元思维拓扑（consolidated MetaPath，T1.4）③校准史（T1.5 calibrations，范围引用）。**不算身份**：模型权重/系统提示词（模型侧，不序列化）；任务树/时间线/轨迹（工作状态，跨会话恢复归 T0.7 resume——恢复≠迁移）；技能/知识/工作流模板（可迁移资产，归治理管道，身份**引用不拥有**）；Elo/复用统计（随资产走）。参照 Letta 自编辑核心记忆，但**身份不是第二记忆层**：内容权威永在组件域，身份=清单+引用 | 不划边界则"身份"膨胀成整个状态机（把工作状态也迁移=把 T0.7 的活重干）；HYPERAGENTS 的可迁移物恰是"学得的优化"不是"进行中的工作"；同 T3.1 J1"非第二记忆层"同款纪律 |
| J3 | **manifest=引用权威**：只存组件 id/版本/范围+状态标注，**零内容复制**（零泄漏+单一权威双纪律）；可经组件域+迁移史**重建**（`backup-and-skip`，replay-equivalence 自检：删 identity domain⇒同 manifest） | 复制内容=第二权威+二次扩散面；派生可重建=domain 分级既有模式（同 T1.1 J7/T2.3 J10） |
| J4 | **快照=传输载体+完整性**：模型无关结构化格式（zod 校验，formatVersion）+`contentHash` 哈希链（prevHash 串接）；导入字节级校验，断裂拒绝；`identity_snapshots` 表**只存导出审计记录**（snapshotId/hash/manifestVersion/时间），不存正文——正文可随时重导 | 快照要出域（给人审查/换环境），是唯一携带内容的形态，故必须完整性可验（§5.2 毒包面对身份版的映射=批量投毒）；正文入库=第二权威，只存 hash=审计可溯 |
| J5 | **迁移=带验证迁移，不假设兼容**：换模型/升级时逐组件在**当前新 profile** 下 rehearsal 重判定（复用 T0.7 fork seam+T1.4/T2.2 rehearsal 协议，不新造验证机制）→ 三分级：`verified`（独立通过，直接进 active）/`degraded`（通过但边际[如 coverage 刚过阈]，保留+注入带迁移标注，承 T1.4 J7）/`failed`（不通过，**不进 active**，留痕）；新模型能力边界不同，某策略在强模型成立≠弱模型成立 | §3.3.3"可迁移"是目标不是假设；T2.1 J6 已立"跨配置是独立判定只要求通过"，本规格是其批量版+分级；HYPERAGENTS 的迁移有效性恰来自验证非复制 |
| J6 | **导入=重新入管道+人类审批**：快照组件→各资产域 `propose`（draft）→ rehearsal（当前 profile）→ verified 才进 manifest；**快照是材料不是凭证**——快照自述的 verified 状态不被信任（外部验证阀对身份传输的落地）；人类一次性 token 经 T3.2 `request(kind='identity-migration')` | §5.2"工具输出/外部内容进隔离区，永不直接固化"的同款精神：跨环境来的身份包=external-content，必须重验证；毒身份包=记忆投毒的批量版（MINJA/Sleeper 教训的迁移面） |
| J7 | **模型无关格式纪律**：快照 schema 禁模型特定字段（无提示词/权重/模型输出痕迹/模型名依赖逻辑）；规则体=分类键+拓扑 shape（结构化），**禁自然语言规则体**——结构化是迁移性的前提（承 T2.1 U2 纪律倾向）；若 T2.1 U2 最终开放受限自然语言规则体，该类组件标 `language-dependent`，迁移时验证要求升格（必须 verified 禁 degraded） | T2.1 U2 原文张力"全结构化 vs 受限自然语言"；语言内容绑表达模型，跨模型迁移时语义漂移不可机检——零泄漏与保迁移性在此合一 |
| J8 | **迁移期连续性**：旧身份**不冻结不删除**——迁移执行期间旧策略继续生效直至被显式 supersede（append-only+双更正通道，同 T0.3 J2）；在途任务不中断、不静默降级；manifest 版本链（v+1 supersede 旧版） | C5"违反/失败产生显式终态绝不静默继续"；迁移中把旧策略停用=用迁移风险换运行中断，双重损失 |
| J9 | **迁移可回放**：同快照+同当前 profile+同 params⇒同分级结果（rehearsal 判定确定性承 T1.4 J4/T0.7 J6 seed 不变量）；分级依据（rehearsalId/coverage）全落盘可复算 | 同 T2.1 J8/T1.3 J7 replay-equivalence 模式；迁移决策是人类审计对象（G3-②） |
| J10 | **留痕双写**：manifest 变更/导入/迁移双写 `identity/change`（log-only，**第十一事件族**，承 T0.7 J2 规范）+`audit_index`（entityKind='identity'\|'migration'） | §5.5 审计基线；身份变更是最高敏感审计对象（改身份=改 Agent 的"自己"） |
| J11 | **零注入直通**：身份服务无 T0.4 injection 区写权；身份组件浮现只经"资产库治理态 consolidated+注入池既有规则"一条路（同 T2.1 J11）；迁移标注（degraded/language-dependent）随注入结构提示带出 | §5.4 控制流/数据流分离：身份包=数据流，禁直通注入面；防毒身份包经注入面直通执行 |
| J12 | **边界**：会话/工作状态恢复归 T0.7 resume（非本规格）；跨工作区身份共享 v1 单工作区单身份（U3）；换用户是否重置身份=隐私面 v1 单用户不涉及（U4）；迁移报告的人类可视化归 T3.2（U6）；身份膨胀（90 天后策略集增长）与 T2.3 容量淘汰的衔接=组件域职责，身份只反映不裁量（U7） | v1 最小可信配置；防身份服务长成隐私/容量/UI 的杂物抽屉 |

## 2. 状态模型

```
                     ┌──────────────────────────────────────────────┐
                     │               组件域（权威）                  │
                     │  coach_candidates(T2.1) / meta_paths(T1.4) / │
                     │  calibrations(T0.1 域)                        │
                     └───────▲───────────────────────▲──────────────┘
                             │ propose/rehearsal      │ 范围引用
export() → IdentitySnapshot（哈希链，传输载体）
                 │
import(snapshot, humanToken)：                 migrate(toProfile, trigger)：
  完整性校验（hash 链）                          manifest.components 逐组件
        ↓ 失败→拒绝                                   ↓ rehearsal(新 profile)
  T3.2 审批（identity-migration）               ┌──────┴──────┐
        ↓ 拒绝→拒绝                             verified    degraded        failed
  逐组件 propose(draft)                            ↓           ↓              ↓
        ↓                                     active      active         不进 active
  rehearsal(当前 profile)                      （直接）    （注入带标注）   （留痕）
        ↓                                          └─────┬─────┘
  verified → manifest v+1（supersede 旧版）◄─────────────┘
        ↓
  MigrationRecord（append-only）+ identity/change 双写
```

- manifest 版本链：`${identityId}#v${n}`，supersede 不改旧版（同 T0.3/T2.2 精神）；
- 组件三态（manifest 内标注）：`verified` / `degraded` /（failed 只在 MigrationRecord 留痕不进 manifest）；
- 迁移与导入共用同一 rehearsal 判定管道（J5/J6），差别只在组件来源（在途 manifest vs 外部快照）。

## 3. 数据模型

### 3.1 `IdentityManifest`（身份清单=引用权威）

```ts type-equiv
/** 当前生效身份=哪些组件+状态标注。零内容复制（J3）：只引用。 */
type ComponentStatus = 'verified' | 'degraded'

interface IdentityManifest {
  readonly manifestId: string                    // ${identityId}#v${version}
  readonly identityId: IdentityId                // branded，idn-<n>
  readonly version: number
  readonly supersedes?: string                   // 上一版 manifestId（版本链，J8）
  readonly userBinding?: { userId: string; since: number }        // v1 单用户占位（U4）
  readonly components: {
    readonly strategies: { ref: CandidateId; status: ComponentStatus; profiles: string[] }[]      // T2.1 HeuristicCandidate（transfer.verified）
    readonly metaPaths: { ref: MetaPathId; status: ComponentStatus; profiles: string[] }[]        // T1.4 MetaPath（consolidated）
    readonly calibrations: { from: number; to: number; ref: string }[]                            // T1.5 校准史范围引用（U5）
  }
  readonly activeModelProfile: string
  readonly createdAt: number
  readonly updatedAt: number
}
```

### 3.2 `MigrationRecord` / `SnapshotRecord`（迁移史+导出审计，append-only）

```ts type-equiv
/** 一次迁移/导入的重判定记录。判定依据全落盘=可复算（J9）。 */
interface MigrationRecord {
  readonly migrationId: MigrationId              // branded，mig-<n>
  readonly direction: 'export' | 'import' | 'migrate'
  readonly fromProfile?: string
  readonly toProfile?: string
  readonly trigger: 'model-swap' | 'model-upgrade' | 'manual'
  readonly verdicts: {
    ref: string; kind: 'strategy' | 'meta-path' | 'calibration'
    verdict: 'verified' | 'degraded' | 'failed'
    rehearsalId?: RehearsalId                    // 判定依据（承 T1.4 rehearsal_runs）
    languageDependent?: boolean                  // J7 升格验证要求的标记
  }[]
  readonly humanTokenRef?: string                // T3.2 approvalId（J6，导入/迁移类必填）
  readonly at: number
}

/** 导出审计记录。正文不存（J4）——可随时经 export() 重导。 */
interface SnapshotRecord {
  readonly snapshotId: SnapshotId                // branded，snap-<n>
  readonly manifestVersion: number
  readonly contentHash: string                   // SHA-256（组件引用+版本+格式版本）
  readonly prevHash?: string                     // 哈希链（J4）
  readonly exportedAt: number
}
```

### 3.3 `IdentitySnapshot`（线上传输格式，zod 校验，模型无关 J7）

```ts type-equiv
/** 导出/导入载体。唯一携带内容的形态；结构化=迁移性前提（J7）。 */
interface IdentitySnapshot {
  readonly formatVersion: 1
  readonly identityId: IdentityId
  readonly manifestVersion: number
  readonly strategies: { candidateId: CandidateId; condition: Record<string, unknown>; rule: Record<string, unknown>; evidence: string[] }[]   // 结构化规则（禁自然语言规则体）
  readonly metaPaths: { id: MetaPathId; topology: Record<string, unknown>; mode: 'convergent' | 'divergent'; applicability: Record<string, unknown> }[]
  readonly calibrationRefs: { from: number; to: number; ref: string }[]
  readonly contentHash: string
}
```

### 3.4 `IdentityParams` / SQLite schema

| 表 | 键 | 值 | 说明 |
|---|---|---|---|
| `identity_manifests` | manifestId（`${identityId}#v${n}`） | IdentityManifest 全量 | 引用权威；版本链 append-only（supersede 不改旧版） |
| `identity_migrations` | MigrationId | MigrationRecord | append-only 迁移史（含导入/导出方向） |
| `identity_snapshots` | SnapshotId | SnapshotRecord | append-only 导出审计（只存 hash 不存正文，J4） |
| `identity_params` | `'singleton'` | { minVerifiedProfiles: 2, degradedCoverageMargin: 0.1, migrationConcurrency: 2, snapshotFormatVersion: 1, languageDependentRequiresVerified: true } | 参数权威；layout `single` |

- domain version=1；**四表全 `invalidRecords:'backup-and-skip'`**——身份全派生：manifests 可经组件域+migrations 重建（不变量 1 自检），migrations/snapshots 与 session log 双写可重放，params 可回默认；
- **组件内容不在本 domain**：strategies/metaPaths 的权威在 T2.1/T1.4 域，校准史在 T0.1 域（J2/J3）。

## 4. 不变量与服务 API

### 4.1 不变量（加载即校验 / 运行时强制）

1. **身份无第二权威**：manifest 只含引用；CI 自检=删除 identity domain 后经组件域+migrations 重建的 manifest 与重建前逐字段相等（replay-equivalence，同 T0.7 J4 模式）；
2. **带验证迁移**：未经当前 profile rehearsal 判定的组件不得进 manifest active（服务端断言；`profiles` 非空且含当前 profile）；
3. **导入即重新入管道**：快照组件必先 propose(draft)+rehearsal；快照自述状态零信任（服务端断言导入路径无"直接标 verified"分支）；
4. **导入人类审批**：import/migrate 类操作必携 T3.2 审批通过的 humanTokenRef（kind='identity-migration'）；`audit_index` 对账零未审迁移；
5. **完整性校验**：contentHash 字节级校验+哈希链断裂拒绝（J4）；
6. **模型无关格式**：zod schema 禁模型特定字段+禁自然语言规则体（CI grep/断言；`languageDependent` 组件必须 verified 禁 degraded，params 可配）；
7. **迁移期连续性**：迁移不删/不停旧组件；替代必经 manifest supersede；在途任务组件集不变（服务端断言）；
8. **零注入直通**：身份服务无 injection 写权；组件浮现只经资产库治理态+注入池既有规则（同 T2.1 J11）；degraded/language-dependent 标注随注入带出；
9. **迁移可回放**：同快照+同当前 profile+同 params⇒同分级（承 T1.4 J4 判定确定性）；verdicts 的 rehearsalId 可回溯复算；
10. **留痕双写**：一切 manifest 变更/导入/迁移双写 `identity/change`（第十一事件族）+`audit_index`。

### 4.2 `ctx.identity` 服务方法

```ts type-equiv
interface IdentityService {
  manifest(): IdentityManifest                                  // 当前生效身份（最新版本）
  export(): IdentitySnapshot                                    // 派生导出（J4，含 contentHash）
  imports(snapshot: IdentitySnapshot, humanTokenRef: string): ImportResult   // 导入=重新入管道（J6）
  migrate(toProfile: string, trigger: MigrationTrigger, humanTokenRef: string): MigrationRecord    // 带验证迁移（J5）
  history(): readonly MigrationRecord[]                         // 迁移史（append-only）
  components(filter?: { status?; kind?; profile? }): readonly ComponentView[]                   // 组件+状态+profile 覆盖
  params(): IdentityParams
  setParams(patch: Partial<IdentityParams>): IdentityParams
}

interface ImportResult { readonly migrationId: MigrationId; readonly accepted: string[]; readonly rejected: { ref: string; reason: string }[] }
interface ComponentView { readonly ref: string; readonly kind: 'strategy' | 'meta-path' | 'calibration'; readonly status: ComponentStatus; readonly profiles: string[]; readonly lifecycle: GovState }
```

- `migrate` 内部序：读 manifest 当前组件 → T3.2 审批（model-swap/upgrade=high 不可逆面）→ 逐组件 rehearsal（新 profile，并发帽 `migrationConcurrency` 默认 2，让位主任务同 T2.1 J9）→ 分级 → manifest v+1（supersede）→ MigrationRecord+双写；
- `imports` 内部序：hash 校验 → T3.2 审批 → 逐组件 propose 到权威域（strategies→T2.1 staging/metaPaths→T1.4 propose/calibrations→范围引用登记）→ rehearsal → verified 才进新 manifest；
- `export` 纯派生：manifest+组件域当前态组装+hash，无写路径（除 SnapshotRecord 审计）；
- 与 T2.1 的分工：T2.1 管候选的产生与单点 transfer 判定（J6），本服务管**身份整包**的清单/传输/批量重判定——不重造 rehearsal（复用 T1.4/T2.2 协议）。

## 6. 验收标准（对 Gate G3 的贡献项）

1. **G3-③ 主项-迁移闭环**：构造策略集（mismatch→coach 候选→rehearsal pass→transfer.verified）+元思维拓扑+校准史 → `export` → 模拟换模型（profile B）→ `migrate`（人类 token）→ 逐组件新 profile rehearsal → 分级 → manifest v+1 → **profile B 配置的会话注入池可见已验证策略**（跨模型不丢身份闭环）；
2. **不假设兼容**：构造 profile A verified / profile B rehearsal fail 的策略 → `failed` 不进 manifest active 且 MigrationRecord 留痕；
3. **degraded 路径**：coverage 刚过阈的组件 → active+注入带迁移标注（承 T1.4 J7）；
4. **毒身份包拦截**：篡改快照字节 → hash 校验拒绝；未携审批 token 的 import → T3.2 拒绝；`audit_index` 对账零未审迁移；
5. **无第二权威**：删 identity domain → 经组件域+migrations 重建 manifest 逐字段相等（replay-equivalence 自检）；
6. **迁移期连续性**：migrate 执行期间在途任务的组件集与注入不变（任务不中断）；旧 manifest 可查；
7. **回放确定性**：同快照+同 profile+同 params⇒同分级结果；verdicts rehearsalId 可复算；
8. **格式纪律+零泄漏**：快照 grep 自检无自然语言规则体/模型特定字段；`languageDependent` 组件禁 degraded（服务端断言）。
