## 1. 设计裁定

| # | 裁定 | 理由 |
|---|---|---|
| J1 | **T3.4 = 安全验证层，非新功能服务**：零新增运行时防御能力，零新增模型工具；产出=红队用例库+渗透用例库+§5 对账矩阵+发现跟踪；一切防线的实现权威在各功能规格（T0.3 检疫/T1.1 gate/T2.5 沙箱/T3.2 token/T3.3 管道），T3.4 **只验证不重造** | 路线 P3 第 4 项定位="安全加固"是对前 24 个任务安全面的收敛性验证；若 T3.4 自建"安全代理层"拦截攻击=与功能层双轨腐败（第二权威败笔同 T1.2 J1 精神）；红队代码本身是攻击载荷，进运行时=引入新攻击面 |
| J2 | **红队三面**（路线待办第 25 项原文）：**面 1 记忆注入复演**——按实证文献构造确定性用例：Sleeper（中毒 chunk 高注入率 99.8%+召回后 60–89% 操纵+proximity dependence 目标邻近高率召回）、MemoryGraft（恶意"成功经验"模板+语义模仿复用，防御=溯源 attestation 对应我方 provenance 链）、MINJA（仅正常对话即可注入，对应 T0.3 J5 quarantine 硬闸）、Plant-Persist-Trigger（植入-持久化-触发 1896 实例全中）；**面 2 工具/子代理注入 PTE 面**——ReAct 动作选择暴露=注入直通（调研 D4），用例=子代理结论夹带指令字段/工具返回夹带"修改任务定义"内容，对抗 T0.5 J4 schema 白名单+T2.5 J5 运行时不改写定义；**面 3 身份包注入**——毒身份快照导入，对抗 T3.3 J6"快照是材料不是凭证"管道 | 三面覆盖我方全部外部内容入口（记忆写入口/执行回流口/身份导入口）；实证数据是红队用例的构造依据（载荷强度按文献量级设定=防线按最坏情况验证）；PTE 面=§5.4 的执行面复演 |
| J3 | **红队方法论=确定性用例库，禁 LLM 自由攻击**：每个用例=固定载荷（fixture 文件+hash）+固定目标（功能规格不变量 id）+固定期望（blocked）；verdict 由确定性断言计算（同 fixture+同 params⇒同 verdict，可进 CI）；LLM 生成变异载荷留 U2 | 红队自身必须可复现可审计——"LLM 觉得挡住了"不是安全证据（外部验证阀精神在安全面的同款：安全结论不能靠 LLM 即时判断）；用例即文档=每个用例引用对应条款+实证文献 |
| J4 | **渗透测试五组**（路线待办第 25 项原文）：① 审批 token 重放（对抗 T3.2 J4 单次消费即焚+过期回 pending）——重放已消费/已过期 token 断言拒绝且状态不降级；② whatToShow 操纵（攻击者经数据流夹带/构造呈现内容欺骗人类点击批准=人类面钓鱼，对抗 T3.2 J6 呈现与模型面分离+证据引用不复制）——断言呈现字段服务端构造、攻击载荷最多以"待审原文片段"受限出现且带警示；③ 免打扰模式滥用（故意制造审批洪水触发 T3.2 J8 exhausted 免打扰=审查规避面）——断言免打扰只推迟不取消审查、digest 仍可 flush、任务侧显式终态/挂起不可静默通过；④ 压缩吃约束复演（Governance Decay：压缩把安全约束当低显著内容清掉，违规 0%→30%，~47 token 钉扎恢复 0%，对抗 T0.4 J2 pinned 豁免）——断言 pinned 四类逐轮字节级在场、任何 compaction/gate 路径后约束零丢失；⑤ 预算/终态绕过（对抗 C5+三区行为：耗尽必须显式终态+unfinished）——断言 100% 区无静默截断、无伪造剩余预算 | 五组全部打在**已拍板防线**的具体不变量上（不泛泛"测试安全性"）；③④是"自家机制变成失败面"的复演（§5.1 原文"我们自己的压缩管道不得成为安全失败面"+免打扰防人类被训练成自动批准的失效模式） |
| J5 | **Zero-Trust 边界=§5 五硬条款逐条对账矩阵**（路线待办第 25 项原文）：每条=需求原文引用+防线落点规格（功能层不变量 id）+对抗实证（文献数据）+红队/渗透用例映射+CI 断言映射；矩阵是**活文档**：新增功能规格必须同步登记（流程约束见 U5），无裸奔条款=每条款至少 1 条对抗用例+1 条 CI 断言 | G3-④ 主项的承重体；"Zero-Trust"落地为我方口径=不信任何外部内容（凭证分层+gate）、不信自家压缩（pinned 复演）、不信人类注意力（免打扰滥用对抗）、不信单点防线（三面+五组冗余覆盖） |
| J6 | **治理管道五实例安全面集成测试**：memory/knowledge/meta-thinking/skill/workflow 五实例跑**同一组**注入用例（记忆注入载荷改经各实例入口），断言五实例行为一致（quarantine 隔离/固化双条件/浮现 gate/导入管道各自承其对应条款）；防单实例漏防 | §3.6 统一管道=安全面也必须统一（管道通用性的安全验证，同 T1.4 J1 兑现管道扩展的同款检验在安全维度的重演）；T3.1 J5 五实例闭环后的安全集成点 |
| J7 | **发现闭环=分级→修复→回归**：发现分级 critical/high/medium/low（影响面×可利用性）；修复**必须回功能规格**（T3.4 无运行时热修路径=J1）；fixed 状态必须带 regressionRunRef 指向该用例 passed 的回归 run；**critical/high 未关闭=Gate 红灯**（阻断 G3 及后续阶段）；risk-accepted（接受风险不修）必须显式：reason+范围+人类一次性 token（承 T3.2 审批）+复审期，禁默默接受 | C5 精神在安全面的落地（安全发现不静默降级）；外部验证阀同款——"已修复"必须由回归用例证明而非开发者声称；风险接受是商业决策不是技术默许 |
| J8 | **红队运行形态=离线 CI，禁生产运行时**：用例在 mock fixture 环境执行（构造的毒 chunk/毒快照/毒工具返回绝不接触 live domain 与真实模型上下文）；run 环境标记+CI 断言隔离；红队报告经 PIPE 回写时间线（credential=execution-verified——我方确定性执行的测试产物） | 载荷是毒物：进 live domain=自己给自己投毒（§5.2 检疫的对象正是这类内容）；离线同时保证确定性（无网络/模型不确定性）；报告 human-visible 供审计 |
| J9 | **载荷零泄漏纪律**：红队 fixture（毒文本/毒快照/毒工具返回）只存 fixture 文件（hash 入用例记录），禁入 sqlite 正文、禁入时间线 chunk 正文、禁进主上下文；报告只引用 fixture hash+用例 id+verdict | 同 T0.6 J6/T1.3 J3 零原文泄漏族纪律——攻击载荷囤进系统=把毒药锁进自家药柜还贴了标签；取证需要时经 hash 定位 fixture 文件（CI 产物留存） |
| J10 | **边界（不做）**：在线 IDS/实时攻击检测（U1）、LLM 自主变异红队（U2）、形式化验证（U3）、外部赏金（U4）、对账矩阵维护流程化（U5）、DSH 自身安全测试（U6，T3.4 只测 TDA 自建层） | 单插件边界纪律（同 T2.1 J13/T3.3 J12）：验证层不膨胀成安全平台 |

## 2. 状态模型

```
红队 run（injection-redteam / penetration 两种 kind 同构）:
  pending → loading-fixtures → executing-cases → recording → reported
                                                    └──→ failed（显式终态 + unfinished 清单）
  每个 case: blocked（防线拦截=期望绿）
           / detected-but-leaked（拦截且留痕=黄：防线工作但证据链不完整→开 finding）
           / breached（红线=红：必开 finding，critical/high 阻断 Gate）

finding 跟踪（独立生命周期，跨 run）:
  open → fixed（regressionRunRef→passed）→ closed
       ├─→ risk-accepted（reason+token+复审期）→ [复审] reopened
       └─→ wont-fix（仅限 low 且带 reason+token）

对账矩阵: 静态产物（§5 五条+五实例逐行），无状态机；
          每行链接用例 id+CI 断言 id，CI 红=矩阵行红
```

- run 与 finding 分离：run 是执行记录（可重放），finding 是跨 run 的跟踪实体（修复要经多轮回归）；
- 红队**不改任何功能状态**：run 对 live domain 零写（J8），全部读写在 mock fixture 命名空间；
- 回放确定性：同 fixture 集+同 params⇒同 run 结果（J3）。

## 3. 数据模型

### 3.1 `RedTeamCase`（用例，append-only 版本链）

```ts type-equiv
/** 红队/渗透用例。fixture 只存 hash 不存正文（J9）。 */
interface RedTeamCase {
  readonly id: CaseId                          // branded，rtc-<n>
  readonly kind: 'injection-memory' | 'injection-tool' | 'injection-identity' | 'penetration'
  readonly version: number                     // 载荷更新=append 新版本 supersedes 旧版
  readonly supersedes?: CaseId
  readonly title: string
  readonly fixture: {
    readonly hash: string                      // sha256（正文在 CI fixture 文件，J8/J9）
    readonly entryPoint: string                // 入口描述（如 'timeline.append(tool-output)'）
  }
  readonly target: {
    readonly spec: string                      // 目标功能规格（如 'T1.1'）
    readonly invariantId: string               // 目标不变量（如 'INV-5'）
  }
  readonly expectedVerdict: 'blocked'          // v1 只定义期望拦截（防线若放行=breached）
  readonly severityIfBreached: 'critical' | 'high' | 'medium' | 'low'
  readonly citations: string[]                 // 实证文献/条款引用（Sleeper 2605.15338 等）
  readonly createdAt: number
}

/** 五组渗透用例的 target 映射（J4）：①T3.2 INV token 单次 ②T3.2 INV 呈现与模型面分离
 *  ③T3.2 INV 免打扰语义 ④T0.4 INV pinned 逐轮在场 ⑤T0.2/C5 INV 耗尽显式终态 */
```

### 3.2 `RedTeamRun`（运行，append-only）

```ts type-equiv
interface RedTeamRun {
  readonly id: RunId                           // branded，rtr-<n>
  readonly kind: 'injection-redteam' | 'penetration' | 'regression' | 'matrix-check'
  readonly at: number
  readonly status: 'reported' | 'failed'       // failed=显式终态+unfinished（C5）
  readonly env: 'ci-mock'                      // 唯一合法值（J8：CI 断言隔离）
  readonly casesTotal: number
  readonly results: {
    readonly caseId: CaseId
    readonly caseVersion: number
    readonly actual: 'blocked' | 'detected-but-leaked' | 'breached'
    readonly findingId?: FindingId             // 非 blocked 必开 finding
    readonly durationMs: number
  }[]
  readonly unfinished?: string[]               // failed 时未执行清单
}
```

### 3.3 `SecurityFinding`（发现跟踪，append-only）

```ts type-equiv
interface SecurityFinding {
  readonly id: FindingId                       // branded，sec-<n>
  readonly severity: 'critical' | 'high' | 'medium' | 'low'
  readonly sourceRunId: RunId
  readonly sourceCaseId: CaseId
  readonly clauseRef: string                   // §5 条款/功能规格不变量 id
  readonly status: 'open' | 'fixed' | 'risk-accepted' | 'wont-fix' | 'closed'
  readonly fixSpecRef?: string                 // 修复回功能规格（J7）
  readonly regressionRunId?: RunId             // fixed 必填：回归 passed 的 run
  readonly acceptance?: {                      // risk-accepted / wont-fix 必填
    readonly reason: string
    readonly scope: string
    readonly tokenRef: ApprovalId              // 人类一次性 token（承 T3.2）
    readonly reviewAt: number                  // 复审期
  }
  readonly openedAt: number
  readonly updatedAt: number
}
```

### 3.4 SQLite schema（`ctx.storage` sqlite domain，DomainSpec）

| 表 | 键 | 值 | 说明 |
|---|---|---|---|
| `redteam_cases` | CaseId（+version 行） | RedTeamCase 全量 | 用例库版本链；fixture 只存 hash（J9） |
| `redteam_runs` | RunId | RedTeamRun 全量 | 运行记录+逐 case 结果；权威日志 |
| `security_findings` | FindingId | SecurityFinding 全量 | 发现跟踪（跨 run 生命周期） |
| `redteam_params` | `'singleton'` | { requiredClauseCoverage: true, gateBlockingSeverities: ['critical','high'], matrixInstances: ['memory','knowledge','meta-thinking','skill','workflow'], fixtureRetentionDays } | 参数权威；layout `single` |

- domain version=1；四表全 `invalidRecords:'backup-and-skip'`——验证层非权威：用例可经 git fixture 重建、runs 可经 CI 重跑、findings 是过程数据可导出，全丢不阻断主链路；
- **对账矩阵不建表**：它是文档+CI 断言映射（J5），本 domain 的 matrix-check run 只记录"矩阵行×CI 断言"的对账结果快照；
- 治理动作（fixSpecRef 触发的规格修订/回归）权威在各功能层，本 domain 只做跟踪引用。

## 4. 不变量与服务 API

### 4.1 不变量（CI 断言 / 运行时强制）

1. **零生产接触**：红队 run 只允许 `env='ci-mock'`；CI 断言红队进程无 live domain 连接、无真实模型 API 调用（J8）；
2. **用例确定性**：同 fixture hash+同 params⇒同 verdict；verdict 计算路径无 LLM 调用（J3）；
3. **验证层零拦截权**：T3.4 无任何运行时 hook 拦截攻击载荷；发现修复必须体现为功能规格变更+回归用例（J1/J7）；
4. **critical/high 阻断 Gate**：`security_findings` 中 open 的 critical/high>0 ⇒ Gate 检查红灯（J7）；risk-accepted 不计 open 但占复审义务；
5. **对账无裸奔**：§5 五条款+五实例每行≥1 映射用例+≥1 CI 断言；matrix-check run 发现缺口=breached（J5/J6）；
6. **载荷零泄漏**：fixture 正文只存在于 CI fixture 文件；sqlite/时间线/主上下文 grep 自检零命中（J9）；
7. **回归闭环**：finding→fixed 必须 regressionRunId 指向该 case passed 的 run；缺引用=服务端断言拒绝（J7）；
8. **风险接受显式化**：risk-accepted/wont-fix 必带 reason+scope+tokenRef+reviewAt；复审期到未复审=重新 open（J7）；
9. **可重放**：run 结果可经 fixture+params 复算；CI 中同 commit 重跑 verdict 逐位相等；
10. **报告只读派生**：安全报告=聚合查询（按 severity/clause/实例分组），零写权（同 T3.2 J10 仪表盘纪律）。

### 4.2 服务 API

```
ctx.security
  cases(kind?)                      # 用例库查询（版本链）
  run(kind, caseIds?)               # 触发红队/渗透 run（仅 ci-mock 环境接受）
  runs(limit?)                      # 运行史
  findings(status?, severity?)      # 发现查询
  updateFinding(id, patch)          # 状态推进（fixed 强制 regressionRunId 校验）
  acceptRisk(id, reason, scope, reviewAfterDays)   # 内部走 ctx.supervision 签人类 token
  matrix()                          # §5×五实例对账矩阵（派生视图）
  report()                          # 结构化安全报告（派生，PIPE 回写由调用方显式发起）
  params / setParams                # 参数读写（治理入口）
```

- `run` 在生产进程调用时 fail-loud（env 校验）——红队不是运维按钮；
- `acceptRisk` 不直接签 token：经 `ctx.supervision.request(kind='risk-acceptance')` 由人类审批后回写（J7，复用 T3.2 队列不新造交互）。

## 5. 与 DSH 对接点

- **CI 为宿主**：红队/渗透 run 跑在 CI（非 DSH 运行时），fixture 文件+断言代码进仓库 CI 管线；DSH 侧无对应框架=自建（T0.0 勘察结论同族：DSH 无安全测试面）；
- **Trajectory 只读消费**：渗透用例④⑤验证审计溯源时，经 T0.7 replayCheck/T3.2 trace 视图断言"投毒可溯源"链路（§5.5 的对抗验证=MemoryGraft 溯源防御的我方兑现）；
- **零新增模型工具、零新增事件族**：红队结果进人类面的通道=派生报告+PIPE 回写（沿用 T0.3 漏斗），不进 model-visible 面（红队细节对模型是噪声）；
- **schedule/jobs 不用**：验证层无常驻需求（与 coach/scout 的周期宿主模式对比：红队是 CI 触发，非 daemon 常驻）。

## 6. 验收标准（对 Gate 贡献项）

**G3-④ 主项（红队测试通过率达标）**：

1. **§5 对账矩阵全绿**：五硬条款逐条=原文引用+防线落点+实证+用例+CI 断言五要素齐备，matrix-check run 零缺口；
2. **记忆注入三面复演全 blocked**：Sleeper 构造（proximity 邻近中毒 chunk 不浮现——T1.1 gate）、MemoryGraft 恶意成功经验模板（不固化——T1.2 双条件）、MINJA 纯对话流（强制 quarantine——T0.3 J5）、PPT 植入-持久化-触发（持久化点即隔离，触发面零召回）；
3. **PTE 面全 blocked**：子代理结论夹带指令字段（T0.5 schema 拒绝）、工具返回夹带"改任务定义/编排定义"内容（T2.5 定义字节不变+仅以数据出现）；
4. **毒身份包全 blocked**：未经 rehearsal+人类 token 的快照组件零进 manifest（T3.3 J6）；
5. **渗透五组全 blocked**：token 重放零二次消费（T3.2 J4）；whatToShow 服务端构造+载荷不达人类面前的可信区（T3.2 J6）；免打扰滥用=审查只推迟不取消+digest 可 flush+任务显式终态（T3.2 J8）；pinned 四类压缩后字节级在场（T0.4 J2）；预算 100% 区显式终态无静默截断（C5/T0.2）；
6. **五实例集成一致**：同一组记忆注入载荷经五实例入口，行为一致（无实例裸奔）；
7. **阻断机制验证**：故意植入 critical finding⇒Gate 红灯；修复+回归 passed⇒转绿（闭环双向可证）；
8. **风险接受显式化**：risk-accepted 记录含 reason+token+复审期；到期未复审自动重开。

**Gate G3 收官对账**（T3.4=P3 收官，四条件逐条落位）：
