## 1. 设计裁定

| # | 裁定 | 理由 |
|---|---|---|
| J1 | **单工作区单时间线**：ctx.storage domain 即工作区级权威；跨会话/跨前端/跨窗口只有一条生命记录，seq 单调全局分配 | 需求 §3.4.1"无论多少前端、多少窗口，Agent 只有一条时间线"（回应"多会话败笔"）；承 T0.2 关闭的 U1 口径（domain 本身即工作区级 scope） |
| J2 | **append-only 为铁律**：无 update/delete API；更正只经两种新记录——`supersede`（Mem0 add-only override：新 chunk 显式取代旧 chunk，旧 chunk 保留可溯）与 `invalidate`（Graphiti 双时序：事实有效期窗口，矛盾/过时标记失效而非删除） | 调研结论（《调研-文献项目前沿》L109-114）：单事实时间线 = Graphiti 双时序 + Mem0 add-only 的组合；删除即毁史，与 C1 机读权威、§5.5 审计基线冲突 |
| J3 | **权威源 = ctx.storage sqlite domain**（决策点③默认"嵌 DSH 存储抽象"，可逆）；每次写入**双写** log-only session event `timeline/write` | 同 T0.1 J2/T0.2 J2 双写模式；§5.5 审计基线硬条款"记忆写入全落 DSH Trajectory，可回放溯源（投毒溯源的基础设施）" |
| J4 | **Chunk Schema 全字段落地**（§3.4.3）：内容/类型/来源/时间戳/情绪权重/置信度/关联任务 ID/语义向量/轨迹链接；P0 `emotionWeight` 占位不计量 | §3.4.3 是 T1.1 引力场召回的数据面；情感/动量归 T2.4 完整版，schema 先占位（同 T0.1 attentionUnits 处理） |
| J5 | **信任分层凭证五级**：`user-original` > `execution-verified` > `model-produced`；`tool-output`/`external-content` 强制 quarantine 标记；P0 落库即标记、检索侧 credentialMin 预筛，检疫治理与完整 provenance gate 归 T1.1/T1.2 | §3.4.4 信任分层 + §5.2 硬条款（工具输出/外部内容永不直接固化，MINJA：仅正常对话即可注入）+ §5.3（provenance gate 低凭证不浮现）——写路径分权是硬条款，不能等 P1 |
| J6 | **PIPE/Channel 单一漏斗**：所有写入经 `ctx.timeline.append(writer, chunk)` 唯一入口（带 WriterRef+credential）；任务执行日志/对话摘要/学习笔记均为上游 producer，无直写通道 | §3.4.1"各写入来源经 PIPE/Channel 汇入统一时间线"；单漏斗才能统一计证与审计 |
| J7 | **检索 v1 = 混合检索**：FTS5（BM25）+ 暴力余弦（float32 blob），`EmbeddingProvider` seam 可插拔；图检索归 T3.1 不做 | 借鉴 Graphiti 混合检索（向量+BM25+图）；决策点①已定 P1 记忆层先用 SQLite+向量最小实现不阻塞，Graphiti 外置在 T3.1；P0 千级数据暴力余弦可接受 |
| J8 | **与任务层解耦**：`relatedTaskId` 是弱链接（非外键、无级联）；时间线只负责"什么信息被记录"，什么浮现归 T1.1；时间线是 T0.4 上下文换页的底层基底（"会话切换=任务切换，底层时间线不变"） | 架构 §2 层间原则：记忆层与任务层解耦、经 L3 中介；§3.4.2 统一上下文分页树的地基 |

## 2. 状态模型

时间线无 phase/stage——它是**事件流不是状态机**。"状态"体现为两个派生视图：

| 视图 | 定义 | 用途 |
|---|---|---|
| `current()` | chunks − (被 supersede 的) − (被 invalidate 的) | 当前有效事实集（召回/T1.1 的输入域） |
| `history(id)` | 某 chunk 的 supersede/invalidation 链（按 seq 正序） | 事实演化追溯、矛盾协调裁决的证据（T1.2） |

- `supersede`：新 chunk 带 `supersedes→旧id`（版本式更正，例：计划改期、结论修正）；
- `invalidate`：独立记录 `kind='invalidation'` 带 `invalidates→目标id`+reason（作废式更正，例：外部事件使事实过期）；**P0 不作废的可逆反转**——需要恢复=append 新 chunk（invalidation 本身也可被 supersede，链路完整）。
- 每条记录不可变；双写 session event 与 domain 记录同 seq 语义对齐（event seq 拥有序，entry 不重复存储它）。

## 3. 数据模型

### 3.1 `TimelineEntry`（domain 记录，权威）

```ts type-equiv
/** 时间线条目（不可变）。chunk=事实/方法/反思/技能记录；invalidation=作废记录。 */
interface TimelineEntry {
  readonly id: EntryId                    // branded，单调分配 tl-<n>
  readonly kind: 'chunk' | 'invalidation'
  readonly content: string                // chunk：内容本体；invalidation：作废原因
  readonly chunkType?: 'fact' | 'method' | 'reflection' | 'skill'  // kind=chunk 必填（§3.4.3）
  readonly source: 'task' | 'conversation' | 'study'              // 写入管道（§3.4.1）
  readonly credential: 'user-original' | 'execution-verified' | 'model-produced' | 'tool-output' | 'external-content'
  readonly quarantine: boolean            // credential ∈ {tool-output, external-content} 时恒 true（J5）
  readonly relatedTaskId?: TaskId         // 弱链接（J8，无外键约束）
  readonly trajectoryLink?: string        // §3.4.5：session/event 引用，支撑技能反查轨迹
  readonly supersedes?: EntryId           // kind=chunk：本记录取代的目标 chunk
  readonly invalidates?: EntryId          // kind=invalidation 必填：作废目标 chunk
  readonly confidence?: number            // 置信度（写入方自评，召回侧参考）
  readonly emotionWeight?: number         // P2 占位（T2.4 引力场动量/情感）
  readonly vector?: number[]              // 语义向量 float32（未嵌入为空，FTS 仍可用）
  readonly writer: WriterRef              // { sessionId, actor: 'agent'|'human'|'coach'|'scheduler', at }
  readonly createdAt: number
}
```

### 3.2 SQLite schema（`ctx.storage` sqlite domain，DomainSpec）

| 表 | 键 | 值 | 说明 |
|---|---|---|---|
| `timeline_entries` | EntryId | TimelineEntry 全量 | 权威；append-only；layout `single` |
| `timeline_fts` | rowid=EntryId | content（外内容 FTS5 虚拟表） | BM25 关键词检索；与 domain 同库同步提交 |

- domain version=1；`invalidRecords` 默认（拒绝打开）——时间线是权威数据；
- FTS5 为**派生索引**：崩溃恢复以 domain 为准重建（写路径同步提交，正常态两者一致）；
- 向量检索 P0 不走索引：`vector` 列 blob 存取，查询期暴力余弦（千级可接受；万级升级见 U2）。

## 4. 不变量与服务 API

### 4.1 时间线不变量（加载即校验，违反拒绝打开）

1. **append-only**：不存在任何改/删路径；更正必产新记录（supersede/invalidate）；
2. **引用完整**：`supersedes`/`invalidates` 必指向存在的 chunk，禁自指、禁指向 invalidation 记录；
3. **字段完备**：chunk 必填 chunkType/source/credential；invalidation 必填 invalidates+reason(content)；
4. **计证强约束**：`tool-output`/`external-content` 写入时 `quarantine` 恒 true（§5.2，服务端强制，不接受调用方指定）；
5. **seq 唯一单调**：EntryId 分配无洞无重（同 T0.2 id 空间耗尽即报错，不复用）；
6. **当前视图自洽**：任意写操作提交后 `current()` 立即反映（supersede/invalidate 即时生效）；
7. **单线唯一**：domain 即全部，无第二时间线（J1）。

### 4.2 `ctx.timeline` 服务方法

```ts type-equiv
interface TimelineService {
  append(writer: WriterRef, chunk: TimelineChunk): TimelineEntry        // 唯一写入口（J6）
  supersede(id: EntryId, chunk: TimelineChunk, reason: string): TimelineEntry
  invalidate(id: EntryId, reason: string): TimelineEntry
  get(id: EntryId): TimelineEntry | undefined
  current(filter?: TimelineFilter): TimelineEntry[]                     // 当前有效事实视图
  history(id: EntryId): readonly TimelineEntry[]                        // 取代/作废链
  search(query: TimelineQuery): TimelineHit[]                           // FTS+向量混合（J7）
}

interface TimelineFilter { chunkType?; source?; credentialMin?; relatedTaskId?; timeRange?; limit? }
interface TimelineQuery extends TimelineFilter { text?: string; vector?: number[]; mode?: 'fts' | 'vector' | 'hybrid' }
```

- 无 CAS（条目不可变、id 寻址）；并发 supersede 同一目标**允许且全记录**，冲突裁定归 T1.2 治理管道（U4）；
- `credentialMin` 是 T1.1 provenance gate 的查询侧预筛（低凭证不浮现的第一道闸）；
- 写入方不限于当前会话：producer 经 WriterRef 声明身份（任务执行器/compaction 摘要器/学习笔记/coach），审计可归因。

## 5. 与 DSH 的对接点

| 对接面 | 机制 |
|---|---|
| 持久化 | `ctx.storage` sqlite domain（同 T0.1/T0.2 模式）+ 同库 FTS5 虚拟表 |
| 审计基线 | 每次 append/supersede/invalidate 双写 log-only session event `timeline/write`（§5.5：记忆写入可回放；T0.7 回放可直接还原写入时序） |
| 模型可见性 | 时间线内容**不自动进上下文**；浮现完全由 T1.1 召回控制（与 T0.4 旋转上下文配合：召回是"放大/降权/换页"的计分输入之一） |
| T0.4 基底 | "会话切换=任务切换，底层时间线不变"（§3.4.2）——compaction 摘要作为 `source='conversation'` 的 producer 汇入 |
| T0.1/T0.2 | `relatedTaskId` 弱链接：任务完成 evidence、目标校准记录可作 chunk 汇入（解耦，无级联） |
| T1.1/T1.2 | `search()`+`current()` 是引力场召回与治理管道（检疫/固化/退役）的挂载面；`quarantine` 标记的消费者 |
| T3.1 | Graphiti 外置后的桥接面：时间线=Agent 自传体情景记忆，图谱=外部知识库，P0 不混层（决策点①边界） |

## 6. 验收标准（对 Gate G0 的贡献项 + 审计基线）

1. **G0-③**（部分）：跨会话连续写入同一条时间线，seq 单调无洞；kill -9 重启后条目/链接/向量/FTS 完整（FTS 可从 domain 重建）；
2. supersede 后 `current()` 不含旧 chunk、`history()` 含完整取代链；invalidate 同理；双写 event 可在 session log 逐一对应；
3. 混合检索可用：FTS 关键词命中 + 向量语义命中（跨语言查询）；`credentialMin` 过滤生效（tool-output 条目在 credentialMin='model-produced' 时不可见）；
4. **§5.2 硬条款自检**：以工具返回内容调用 append 强制落 quarantine=true（服务端强制，调用方无法绕过）；
5. 写入归因：每条记录可追溯到 WriterRef（session/actor），满足"记忆写入可回放溯源"；
6. 与任务/目标解耦验证：删除（tombstone）任务不影响时间线条目读取（弱链接无级联）。

### 验收结果回填（IT1 实现，2026-09-24，tda-timeline 插件）

CI 四门全绿（类型门 6 包 / 不变量门 4 包 / 双写对账门 3 包 / 冒烟门 4 包；tda-timeline 自身：不变量 12 例 + 双写 4 例 + 冒烟 3 例）。逐项对照：

1. **G0-③**：冒烟门 idle-kill 场景——5 op（append×3 含 tool-output、supersede、invalidate）后 kill -9，重启验 5 条目 tl-1..tl-5、quarantine 落盘、tl-4.supersedes/reason、tl-5 invalidation、vector 持久化；log↔domain 配对零差异 + replay-equivalence 通过；第二会话（新进程/新 sink）续写得 tl-6，跨会话 seq 单调无洞；FTS 从 domain 重建后旧条目可检索。
2. **supersede/invalidate 视图与链**：不变量门"服务全路径"例（current 不含旧、history 含完整链）+ 双写门"复合 op"例（3 事件逐一配对、reason 落域、audit_index seqFrom/seqTo 自动延展）；并发双 supersede 全记录（U4：P0 不拒绝）。
3. **混合检索**：不变量门"混合检索"例——fts 关键词命中（'预算' 命中 2 条）+ 向量语义命中（跨语言：查询 [0,1] 命中无关键词交集的"今天天气很好"）并集浮现，双通道居首；credentialMin 预筛例——tool-output 在 model-produced 线下不可见（current 与 search 双侧）。
4. **§5.2 硬条款**：不变量门"计证强约束"例 + 冒烟门"§5.2 硬条款"例——`TimelineChunk` 输入类型级无 quarantine 字段（调用方无从指定），服务端按 credential 恒置 true；注入 quarantine=false 经 put 即拒（schema superRefine）。
5. **写入归因**：冒烟门 WriterRef 归因例——域内每个条目 writer.sessionId/actor/at 完备且域内每个键都有对应事件踪迹。
6. **弱链接无级联**：冒烟门例——relatedTaskId 指向不存在的任务（'task-999'，任务层未建）可正常 append/读取/按 relatedTaskId 过滤。

实现侧两处规格必要超集（均在代码文件头明示）：① supersede/invalidate 签名补 writer 首位参数（§5.5 审计基线与 §108 归因要求新记录可追溯写入方，同 tda-goal-state 先例）；② 条目增 `reason?: string` 字段（§4.2 supersede 的 reason 参数在 §3.1 字段表无处安放，键序与记录构造/事件载荷逐字段对齐，replay-equivalence 不受影响）。

## 7. 未决项

- U1：`EmbeddingProvider` 选型（本地 ONNX 多语言小模型 vs 远程 embedding API）→ 需独立 spike（现状同 logprobs：无 key）；P0 可 FTS5 先行、`vector` 字段占位；

- U4：并发 supersede 同一目标的冲突裁定（多路更正如何收敛）→ T1.2；P0 全记录不拒绝；
- U5：`emotionWeight`/动量计量口径 → T2.4 引力场完整版；
- U6：时间线容量上限与归档策略（90 天长程的条目增长）→ T1.2 退役规则一并设计。
