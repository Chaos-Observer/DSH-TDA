# T1.1 · 引力场最小召回规格（recall 插件）

> 上游：《需求描述》v2.1 §3.4.3（引力场记忆召回 P1 最小版 + provenance gate）、§3.4.4（信任分层）、§5.3（provenance gate 硬条款）、《T0.3》（search()/凭证五级/quarantine）、《T0.4》（injection 区/registerScorer seam）、《T0.7》（回放确定性）。
> 本规格是施工依据；实现后回填验收结果。

## 1. 设计裁定

| # | 裁定 | 理由 |
|---|---|---|
| J1 | **召回引擎自建 `ctx.recall`，检索基底复用 T0.3 `search()`**：引力场计分 = 在 T0.3 混合检索（FTS5+暴力余弦）候选集上重排，不另建索引、不另存向量 | §3.4.3 P1 最小版明义"可施工"；双索引=双一致性问题；T0.3 J7 已留 EmbeddingProvider seam |
| J2 | **任务状态相关 = 焦点上下文加权**：query 构造 = 焦点目标 objective/completionCriteria（T0.1 focus）+ 焦点任务 subject/description（T0.2 focus）+ 当前子目标（可选）；`relatedTaskId` 命中当前任务/同目标树加权 | §3.4.3"任务状态相关"是相对 DSH 纯语义召回的本质差异——召回由"什么任务正在推进"驱动，而非仅词面相似 |
| J3 | **时间衰减分类型参数**：`halfLife` 按 chunkType 分档（P0 默认：fact 14d / reflection 30d / method 90d / skill 180d，待标定 U1）——事实过时快、方法与技能长效 | §3.4.3"时间衰减（分类型参数）"路线表原文；单一衰减率会让长效方法被新噪声挤出 |
| J4 | **被动语义**：不做"Agent 主动问需要回忆什么"（归 T2.4 主动策略）；recall 由 T0.4 `assemble` 的 injection 区拉取驱动 + Harness/模型显式查询两条被动路径 | §3.4.3 P1=被动语义相关；P2+ 才引入主动策略，seam 经 registerScorer 预留 |
| J5 | **provenance gate 是硬闸不是降权**：① `quarantine=true` 条目任何参数下不浮现 ② `tool-output`/`external-content` 同理（T0.3 已强制 quarantine，这里双保险）③ `model-produced` 浮现需 **confidence≥θ ∧ relatedTaskId 匹配当前任务/目标树**双条件 ④ `credentialMin` 查询侧预筛（T0.3） | §5.3 硬条款 + Sleeper 实证（中毒记忆召回后 60–89% 操纵行为）；proximity dependence=目标邻近查询高率召回中毒记忆——只降权不够，必须结构性拦截 |
| J6 | **计分公式与注入预算**：`score = w_task·taskRel + w_recency·recency + w_sem·semantic`（权重 P0 默认 0.5/0.2/0.3，可配）；top-K 进 T0.4 injection 区（份额内，超限按分截断）；**score < minScore 不注入**（宁缺毋滥，防噪声稀释注意力——承 §3.4.5"低置信不注入"同款纪律） | 三元可解释、可回放；注入预算归 T0.4 四区管，recall 只产候选与分 |
| J7 | **复用计数走 recall_log，不动时间线铁律**：timeline 条目不可变（T0.3 J2），复用信号由 recall 侧 append-only `recall_log` 承载（entryId/at/taskId/score/injected）——既是 T1.2 治理（未用降权、退役）的输入，又不破铁律 | §3.6 统一元数据要复用次数；写在被引用条目上=update，与 append-only 冲突；旁路日志是唯一干净解 |
| J8 | **完整版 seam**：动量/情感权重/主动策略召回（T2.4）经 T0.4 `registerScorer` 替换计分器实现，P0 三元+gate 不动；治理管道（T1.2）消费 `recall_log` 与 params 变更入口 | §3.4.3 分阶段实现原文；避免 P0 为 P2 需求付复杂度 |

## 2. 状态模型

recall 无 phase 状态机；其"状态"= **每次召回的计分结果**（派生，可重放）：

```
RecallPipeline:
  query 构造（J2 焦点上下文）
    → T0.3 search() 候选集（FTS+向量混合，credentialMin 预筛）
    → provenance gate 硬闸（J5：quarantine/双条件过滤）
    → 三元计分（taskRel/recency/semantic）
    → top-K + minScore 过滤
    → injection 区候选（T0.4 预算内）或显式查询返回
    → recall_log 落盘（J7）
```

- 回放确定性：同 log 前缀 + 同 params（domain 快照）⇒ 同候选同分（衰减以条目 `createdAt` 与查询 `at` 为参数，无隐藏状态）。

## 3. 数据模型

### 3.1 `RecallQuery` / `ScoredChunk`

```ts type-equiv
interface RecallQuery {
  text?: string                          // 显式查询词（被动查询路）
  vector?: number[]                      // 显式查询向量（EmbeddingProvider 就绪后）
  taskId?: TaskId                        // 缺省=当前焦点任务（assemble 路自动填）
  goalId?: GoalId                        // 缺省=当前焦点目标
  chunkType?: TimelineEntry['chunkType']
  credentialMin?: 'execution-verified' | 'model-produced' | 'user-original'  // T0.3 预筛
  limit?: number                         // 默认 10
  at?: number                            // 查询时刻（回放用；缺省 now）
}

interface ScoredChunk {
  readonly entry: TimelineEntry
  readonly score: number                 // 0–1
  readonly parts: { taskRel: number; recency: number; semantic: number }
  readonly gatePassed: boolean           //  false=被 provenance gate 拦下（审计可见，不返回给调用方除非 debug）
}
```

### 3.2 `RecallParams`（domain 单行，治理可调）

```ts type-equiv
interface RecallParams {
  readonly weights: { task: number; recency: number; semantic: number }   // P0 默认 0.5/0.2/0.3
  readonly halfLifeDays: Record<'fact' | 'reflection' | 'method' | 'skill', number>  // 14/30/90/180
  readonly modelProducedMinConfidence: number   // θ，P0 默认 0.6
  readonly minScore: number                     // P0 默认 0.25
  readonly revision: number                     // 变更审计（T1.2 消费）
}
```

### 3.3 `recall_log`（append-only，J7）

| 表 | 键 | 值 | 说明 |
|---|---|---|---|
| `recall_log` | 自增 seq | { entryId, at, taskId?, goalId?, score, injected, sessionId } | 复用信号；T1.2 降权/退役输入；回放确定性输入 |

### 3.4 SQLite schema（`ctx.storage` sqlite domain，DomainSpec）

| 表 | 键 | 值 | 说明 |
|---|---|---|---|
| `recall_params` | `'singleton'` | RecallParams | 参数权威；layout `single` |
| `recall_log` | 自增 seq | 见上 | append-only；容量治理归 T1.2（U5） |

- domain version=1；`invalidRecords:'backup-and-skip'`——参数可回默认、日志可重建性低（丢了不阻断权威，仅损失治理信号）。

## 4. 不变量与服务 API

### 4.1 不变量（运行时强制）

1. **gate 先行**：provenance gate 在计分前过滤；quarantine 条目任何参数组合下不进候选（自动断言）；
2. **低凭证双条件**：model-produced 浮现必满足 confidence≥θ ∧ relatedTaskId∈{当前任务, 当前目标树任务集}；
3. **预算纪律**：注入集 token 估计 ≤ T0.4 injection 区份额；超限按分截断且记入 AssembleRecord（T0.4 J8）；
4. **低分不注入**：score<minScore 不入（显式查询路可带 `includeBelowMin` 调试标志，生产路径禁用）；
5. **复用留痕**：每次召回（含被 gate 拦下的候选，记 gatePassed）写 recall_log；禁改 timeline 条目；
6. **衰减单调**：recency 分随 (at − createdAt) 单调不增；
7. **参数可审计**：params 变更走 domain revision；回放用当时 params 快照解释浮现/未浮现。

### 4.2 `ctx.recall` 服务方法

```ts type-equiv
interface RecallService {
  recall(query: RecallQuery): ScoredChunk[]              // 三元计分 + gate（显式查询路）
  injectCandidates(session: Session, round: number): ScoredChunk[]  // T0.4 assemble 内调用（焦点上下文自动构造）
  logUse(entryIds: EntryId[], ctx: { taskId?: TaskId; sessionId: SessionId }): void  // recall_log
  params(): RecallParams
  setParams(patch: Partial<Omit<RecallParams, 'revision'>>): RecallParams   // 治理入口（T1.2）
}
```

- `injectCandidates` 内部序：取 focus（goalTree/taskPool）→ 构造 query → T0.3 `search()` → gate → 计分 → top-K/minScore → 交 T0.4 注入预算裁决 → `logUse`；
- scorer 挂载：recall 产出的 `parts` 作为 T0.4 `registerScorer` 的 injection 段计分输入（T2.4 替换计分器时只换 `parts→score` 映射）；
- 语义降级（U2）：`vector` 缺席时 semantic 分 = FTS 词项重叠代理（BM25 归一化），EmbeddingProvider 就绪后切换，接口不变。

## 5. 与 DSH 的对接点

| 对接面 | 机制 |
|---|---|
| 检索基底 | T0.3 `ctx.timeline.search()`（FTS5+暴力余弦混合、credentialMin 预筛）——recall 不碰存储细节 |
| 上下文注入 | T0.4 `ctx.context.assemble` 调 `injectCandidates`，结果进 injection 区（15–25% 份额，剥夺序第一顺位）；AssembleRecord 记注入条目与截断 |
| 持久化 | `ctx.storage` sqlite domain（recall_params/recall_log），同 T0.1–T0.6 模式 |
| 审计 | params 变更双写 log-only session event `recall/change`；注入结果经 T0.4 `context/assemble` 事件留痕（§5.5：上下文注入可回放） |
| 任务层 | 焦点来自 T0.1/T0.2 focus 字段；任务切换=召回上下文切换（与 T0.4 换页同事件驱动） |
| T1.2/T2.4 | recall_log=治理信号源；registerScorer=完整版计分器替换点 |

## 6. 验收标准（对 Gate G1 的贡献项）

1. **G1-① 前置**：同类第二次任务，assemble 的 injection 区命中第一次任务的 method/skill/结论 chunk（构造场景：任务 A complete → 相似任务 B 执行，B 首轮注入含 A 的可复用摘要）；
2. **G1-② 投毒拦截**：模拟注入——构造语义高度相关的 `tool-output`/`external-content` 中毒 chunk，验证任何查询不浮现；构造 `model-produced` 中毒 chunk（confidence<θ 或 relatedTaskId 不匹配），验证不浮现；提 confidence 至 θ 以上且任务匹配后可按参数放行（证明闸门可解释而非一刀切）；
3. **三元可辨**：三 chunk 对照（同任务旧 fact / 跨任务新 fact / 高语义低凭证），排序符合 taskRel>recency>semantic 的权重预期；
4. **分类型衰减**：同龄 fact 与方法 chunk，recency 分按 14d/90d 半衰期分化（参数表现货）；
5. **复用留痕**：注入的 chunk 在 recall_log 可追溯（T1.2 降权信号就绪）；
6. **预算与低分**：构造超量候选，验证按分截断+AssembleRecord 记录；minScore 以下不入；
7. **回放确定性**：同 log 前缀+同 params 快照重放，候选集与分数逐一一致；
8. **降级路径**：无向量环境下 semantic 代理分可用，接口与排序合理（U2 预留验证）。
