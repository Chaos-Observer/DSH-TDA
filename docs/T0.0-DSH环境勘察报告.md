## 1. DSH 架构本质（一句话）

**一切皆插件的事件溯源会话内核**：append-only `SessionEvent` log 是唯一真相源；`deriveMessages()` 把 log 投影为模型可见历史；"Model-visible ⟺ logged"是运行时强断言的不变量。Cordis 提供五种事件分发（`emit`/`parallel`/`serial`/`bail`/`waterfall`），注册即 effect（可逆卸载）。

| 概念 | DSH 现实 | 对我们的意义 |
|---|---|---|
| Session | append-only 事件日志 + surface（有序消息投影层）+ 冻结的 deriveMessages 缓存 | 统一上下文分页树/轨迹回放的**现成底座**，不用新建 |
| Turn/Step | turn/start→pre-step→request→stream→tool/*→turn/end 完整状态机，全 durable | 任务执行记录的天然格式 |
| 事件类别 | session events（durable 事实）/ agent events（live 拦截点）/ capability events（策略挂载） | 三类扩展点分工明确，新行为挂 documented 扩展点，不改 loop |
| Projection seam | `ctx.sessionProjections` 注册 folding units，`stateOf()` 读折叠态 | 任何"从 log 折出状态"的机制都走这条缝（目标/任务/时间线同款） |
| Profile/Bundle | boot 时按层组合插件树；`cordis.yml` patch 可覆盖任何行；HMR | 部署配置化，我们的插件作为 bundle/preset 层叠加入 |

## 2. 已内置 = 复用面（按我们的五层架构映射）

### L4 任务执行层

| DSH 能力 | 实际形态（源码契约） | 复用判断 |
|---|---|---|
| **目标状态机 `ctx.goals`** | 四态 `active/paused/blocked/complete`；`GoalRef{id,revision}` 比较-and-set；每次 durable 变更 `revision+1`；`maxGoalRounds` 轮次预算 + `roundsStarted`；round 编号正序、replay 拒绝 gaps/stale/stopped/cap-overflow；`block(agent,ref,{code,message})` 带机器可路由原因码；durable phase 与 process-local activation 分离 | **T0.1 直接扩展**：单会话单目标（一次一个 current goal），缺目标树/跨会话/漂移记录——在其 CAS+事件模式上加层，不重写 |
| **任务 DAG `ctx.agentTeams`**（experimental） | `TeamTaskSnapshot{id,revision,subject,description,status,ownerId,blockedBy,writeScopes}`；CAS revision；全快照事件；`foldTeam()` 从 root session log 重放 roster/task board/mailbox；`blockedBy` 强制无环、禁引用已删任务；durable mailbox（queued-minus-delivered 恢复语义） | **T0.2 的模式底座**：任务树/DAG/依赖/owner 全部已有；缺跨会话任务池与周期触发——扩展而非新建 |
| **工作流外部化 `ctx.workflowEngine`** | 模型写 orchestration SCRIPT（纯 JS，PTC VM 沙箱执行）→ `agent()` 编排 subagents；`WorkflowMeta{name,description,phases}` 作为**数据**校验（永不 eval 元数据）；`parent` 必需、cwd/lineage/depth 穿透 subagent seam；`maxTotalAgents` 上限 | **T2.5 的执行器候选**：控制流（script）/数据流（args JSON）已分离=注入防线；缺 contract 前后置与硬边界声明 |
| **子代理 `ctx.subagents`** | Provider 静态描述 start-time capabilities，缺能力 `UNSUPPORTED_CAPABILITY` 拒绝（不接受后忽略）；fresh child vs fork-seeded child 双模；`dsh-subagent-fork-in-process` 工具期委派保留 completed-prefix clipping | **T0.5 的隔离底座**：Lead+Sidekick 派发策略与 preset 降噪新建，隔离机制复用 |
| **后台任务 `ctx.jobs`** | `JobKindMap` 声明合并可扩展（内置 bash/subagent）；owner fencing（owner agent 销毁即取消并 await）；output ring buffer + pull sources；`job_*` 工具读写停 | 复用；但**进程退出即失**（无 durable 恢复），常驻调度缺口见 §3 |
| **Schedule** | session-local durable 提醒：`after`（延迟）/`at`（绝对，RFC3339 UTC 规范化）/`every`（固定速率 ≥300s，锚定创建时刻）；cold/busy 时只补最新一次；dispatch=同步入队非模型应答成功 | 周期提醒复用；**无 cron 表达式、无跨会话任务池触发**（缺口见 §3） |

### L1 运行时基座 / 横切

| DSH 能力 | 实际形态 | 复用判断 |
|---|---|---|
| **Compaction `ctx.compaction`** | `compaction/start|summary|end` 事务括号（lock 崩溃可检测 orphan）；**surface 遮蔽式**（append-only 日志永不删，shadowedSeqs 权威集）；`shadowedTokenCount` 估账；触发=`pressure`/`context-overflow` 双档；`ctx.tokenMeter` 独占计量；tool-result pruner 先剪再量可免摘要直进；tool-call/result 配对边界保持 | **T0.4 的基线**：旋转上下文=在其上加 pinned 区（C6）与困惑度降级；现有 retained-tail 策略由 `dsh-compaction-basic` 拥有可 patch |
| **Storage `ctx.storage`** | capability seam：hub（无 IO）+ backends（`json` 单文件原子发布 / `sqlite` 每记录一行）+ domain 层（唯一 Consumer）；`DomainSpec` zod schema + version + compatibleVersions + `invalidRecords:'backup-and-skip'`（派生数据友好）；SCHEMA_VERSION 单调递增 | **记忆/知识/任务池持久化首选**：sqlite backend 适配 Graphiti 外置或自建时间线；决策点③默认"嵌 DSH 存储抽象"成立 |
| **Skills `ctx.skills`** | 多源 rank 发现（project-dsh/project-agents/custom/user/bundled）；`<name>/SKILL.md` bundle 或 flat md；frontmatter `disable-model-invocation`/`user-invocable` 归一化调用策略；chokidar 热观察 + write/edit 同步失效；summary/candidate/definition 渐进披露（模型只见 name+description） | **T2.2 技能库底座**：发现/热更/渐进披露全有；缺"回放验证才入库"（Voyager 铁律）与退役——上层加验证层 |
| **Extensions** | agent 自定义 versioned Cordis 包，host/client 双半运行，写代码前可查 approved runtime metadata | 运行时自修改（自成长）的官方通道；安全边界需我们评估（红队入 T3.4） |
| **Session Persistence** | `SessionPersistence` seam（create/open/stat/list/export）；JSONL `session.vN.jsonl[.zstd]` 代际链，committed 代际永不改名/替换/删除；adjacent migration 包各管一步 `vN→vN+1`；SQLite SCHEMA_VERSION 单调 | 轨迹资产（回放态）的存储层现成 |
| **Fork/Resume** | `SessionStore.fork(source, boundary?, childSessionId?)`：turn 边界显式 fork，拒绝开turn内前缀；`ctx.agents.create({sessionId,seed,meta:{parentSession,seedLength}})`；`Session.create/fromRestore` detached 重放 | **T0.7 轨迹接入**：读写能力已内置，冒烟即可 |
| **Approval / 人机监督** | User Approval 子系统（审批策略独立于 plan mode/sandbox）；`user-questions` seam（exit_plan_mode 即走它）；feedback 子系统 | T3.2 的交互底座 |

## 5. 决策点②结论（关闭）

**DSH 已内置能力边界 = 事件溯源内核 + 目标/任务/技能/压缩/子代理/工作流/存储/调度提醒的全套 seam。** 自建收缩为七项：

1. 跨会话目标树与漂移检测（T0.1 扩展 + T1.5）
2. 跨会话任务池与常驻 cron 调度（T0.2 扩展 + 常驻调度器）
3. 记忆引擎（引力场/检疫/provenance）与知识图谱（T0.3/T1.x/T3.1）
4. pinned 约束钉扎 + 困惑度 gate（T0.4）
5. 轨迹预测与 coach 双环（T1.3/T1.4/T2.1）
6. 技能验证晋升与退役层（T2.2）
7. 人机监督深化与注意力配额仪表盘（T3.2）

**下一步建议**：T0.1/T0.2 按"扩展 DSH 既有模式"重写规格（而非从零 schema）。

## 6. Logprobs Spike 结论（2026-09-23，文档级证据）

无 API key，未能发真实请求；证据来自 DeepSeek 官方 API 文档（api-docs.deepseek.com）：

| 事实 | 说明 |
|---|---|
| Chat Completions 请求参数支持 `logprobs`(boolean) 与 `top_logprobs`(integer, 0–20，须 `logprobs=true`) | 请求侧可用 |
| 响应 `choices[].logprobs.content[]` 每 token 返回 `token`/`logprob`；不在 top-20 内的 token 记 `-9999.0` 哨兵值 | 聚合时须过滤哨兵 |
| Responses API 支持 `top_logprobs`（范围 [0,20]）；`top_p` 思考模式下限 0.95 | 第二条通道 |
| FIM Completion (Beta) 支持 `logprobs`≤20（base_url=/beta） | 第三条通道 |
| 模型面：`deepseek-flash` / `deepseek-v4-pro`，支持 thinking 模式开关 | — |

**结论**：困惑度 gate 的**正式版可行**——缺口只在 DSH llm adapter 不透出，属可办的透出层改造。落地注意：
1. 流式（`stream:true`）与 logprobs 的组合行为文档未明示 → 有 key 后首个实测项；
2. `-9999.0` 哨兵值在困惑度聚合时须过滤或截断，不可直接进均值；
3. `top_logprobs` 上限 20 决定候选分布维度上限，gate 阈值设计受此约束。
