# 任务驱动生产力 Agent · 需求描述文档

> 定位：**WHAT（需求权威源）**。技术选型与实现见《架构与路线蓝图-任务驱动生产力Agent.md》（HOW，跟随本文）。
> 基线：DSH（DeepSeek Harness，已在运行，Cordis 插件体系）
> 方式：以 DSH 为基座**增量改造**，构建目标驱动的自主生产力 Agent
> 版本：v2.1（补充：轨迹三态资产、C6 约束钉扎、安全硬条款、KV-cache 约束、决策点①收敛）

---

## 0. 文档目的与根本需求

**根本需求**：让 Agent **持续自主推进一组任务到可验证完成**，并具备四性：
- **跨会话连续性**（不做"多会话败笔"）
- **长程不漂移**（90 天以上目标不偏）
- **可监督可审计**（人类在环、决策可回放）
- **能力自增长**（越用越强且不失控）

三大正交子系统（贯穿全文）：
1. **目标状态机**（推进什么）——跟踪目标直到可验证完成，而非"执行任务"
2. **记忆治理**（记得什么、忘什么）——质量系统，而非存储堆
3. **认知资产库**（用什么）——能力/知识/元思维的资产化，由治理管道维护

---

## 1. 核心设计原则（硬约束）

| # | 约束 | 含义 |
|---|---|---|
| C1 | **目标状态为权威** | 可机读目标状态机是任务推进的唯一来源，而非对话历史 |
| C2 | **子代理上下文隔离** | 探索/诊断/调研全部走子代理，返回结构化结论；主上下文只留决策与编排。深化形态：**Lead（前沿规划审查）+ Sidekick（廉价执行）**协同 |
| C3 | **工作流外部化** | 编排逻辑是持久化、可执行、可复用的定义，而非 Prompt 描述 |
| C4 | **资产退役优先** | 核心机制是退役与固化管道，不是生成与堆叠 |
| C5 | **约束而非能力（第一性）** | 任务节点携带硬约束；违反时产生显式终态，绝不静默继续 |
| C6 | **约束钉扎** | 目标/完成标准/硬约束/安全策略以 pinned 形态常驻上下文，**豁免 gate 降权与分页折叠**——我们自己的压缩管道不得成为安全失败面 |

横切原则：**外部验证阀**（资产固化不能靠 LLM 即时判断，须一次真实复用或评测回放）+ **安全/信任分层**（写入凭证化、来源分级、凭证隔离，见 §5 硬条款）。

---

## 2. 总体架构（五层 + 横切治理层）

```
┌─────────────────────────────────────────────────────┐
│ L5 目标与元认知    目标状态机 / 漂移校准 / 长程规划    │
│                    （元思维库的调用与反思更新）        │
├─────────────────────────────────────────────────────┤
│ L4 任务执行        任务树状态机 / 工作流外部化+执行   │
│                    执行预算·子代理 / 规则引擎         │
├─────────────────────────────────────────────────────┤
│ L3 认知资源(资产库) 能力/工具库 / 知识库·图谱         │
│                    元思维库 / 笔记→技能管道           │
├─────────────────────────────────────────────────────┤
│ L2 记忆层          旋转上下文 / 单事实时间线          │
│                    引力场召回 / 记忆治理              │
├─────────────────────────────────────────────────────┤
│ L1 运行时基座 DSH   Cordis 插件/事件总线/状态管理     │
│  (现有·运行中)      + 自建 Agent Harness / SessionLog │
└─────────────────────────────────────────────────────┘
横切：认知资产卫生层（统一生命周期 / 治理 / 更新维护，穿透 L2–L5）
```

层间通过 DSH Cordis 插件与事件机制通信。**记忆层与任务层解耦**：记忆层只负责"什么信息浮现"，任务层只负责"什么任务推进"，二者经 L3 认知资源层作为中介。

## 3. 逐层需求

### 3.1 L5 目标与元认知层

#### 3.1.1 目标状态机（C1）
- 生命周期：待规划 → 执行中 → 等待 → 验证中 → 完成/失败
- 节点携带可机读权威状态：**目标 / 完成标准 / 当前阶段 / 已确认事实 / 阻塞项 / 子任务 / 剩余预算 / 完成依据**
- 支持动态追加后继目标（排队机制）

#### 3.1.2 目标漂移检测
| 指标 | 说明 |
|---|---|
| 目标持久性评分 | 当前行为与初始目标的对齐度趋势 |
| 状态一致性指数 | 状态报告与实际行为的一致性 |
| 约束保持率 | 初始约束在执行过程中的保留程度 |
| 行动波动性漂移 | 决策模式的渐进变化 |

- 检测到漂移后**温和修正**（目标重述 / 状态回声 / 约束重锚定 / 计划微调），不强制重置，保护连续性
- 安全红线：自进化系统存在对齐漂移风险（孤立 Agent 社会必然偏离），漂移校准须有外部验证阀兜底

#### 3.1.3 长程规划
- 规划与执行**强分离**：规划产物是外部化的可执行编排定义（C3），由 L4 执行器解释运行
- 每个执行单元带 **contract（前置检查 + 后置验证 + 硬边界）**
- **局部重规划而非整体回滚**：在计划偏差预算内度量 `predicted vs actual`，累积超阈值触发单步重规划
- 任务图谱含：分解关系（父子）+ 依赖关系（DAG）+ 替代路径（备选方案）

#### 3.1.4 元思维运用（资产本体在 L3）
- L5 负责**选择/调用/反思更新**元思维库中的推理路径
- 区分**收敛路径**（确定性任务：约束与验证）与**发散路径**（创意/研究任务：跨域关联与类比），按任务类型自动选择或混合
- 目标完成后，流程抽象为**分层模板**（高层策略路径 + 低层操作序列）回写资产库

### 3.2 L4 任务执行层

#### 3.2.1 任务树状态机（C1 落地载体）
任务节点 Schema（一阶属性）：
- 主任务 / 派生任务；父子与依赖关系
- 起止日期；一次性 / 周期性参数
- 优先级；执行记录；进展；属性状态
- **执行预算**：token / 工具调用 / 时间 / **人类注意力配额**——与漂移检测互补：漂移管方向，预算管资源
- **任务本地路径**：中间产物、日志、笔记锚定任务专属目录
- 生命周期同 §3.1.1

额外能力：**Agent 自主提议周期性任务**——基于任务上下文自主生成监控/跟进任务，带"Agent 提议"标记 + 轻量审批（自主性级别可配）。

#### 3.2.2 工作空间语义理解
- 任务本地路径是起点；需从文件系统状态**动态构建局部知识图谱**
- 识别：文件显性/隐性依赖、版本演化脉络、"可信度层级"（哪个是权威源、哪个是草稿）

#### 3.2.3 执行预算与硬约束（C5）
- 预算接近阈值 → 收敛范围、停止新委派、优先完成可交付部分
- 预算耗尽 → **明确终态 + 未完成清单**，而非悄然截断
- 硬约束：文件读取边界、工具调用前置条件、预算上限；违反时 Harness 产生显式终态

### 3.3 L3 认知资源层（资产库）

#### 3.3.1 三库分离
- 能力/工具库、知识库·图谱、元思维库
- 均通过 L3 与记忆/任务解耦，作为二者的中介
- 知识库形态待定（见 §6 决策点）

#### 3.3.2 元思维库（资产本体）
- 存"推理拓扑结构"而非语言内容——应对语言表达边界的抽象需求
- 新模式须经回放验证才缓存为"元路径"；失败模式降权
- 生命周期与治理走 §3.6 统一管道

#### 3.3.3 自成长闭环（C4 核心落点）
| 阶段 | 机制 |
|---|---|
| 生成 | 注入**元技能先验**（meta-skill authoring prior），生成时自带质量意识 |
| 验证 | **轨迹回放（rehearsal）**：重放真实执行轨迹，通过才允许固化；至少一次真实业务复用后才晋升 |
| 维护 | registry + 版本 + 写时冲突检测 |
| 退役 | 连续 N 次失败 / 被更优替代 / N 天未用 → 降权或退役；活跃容量上限强制淘汰 |

- 双环结构：**coach 元进程**（观察、复盘、重放、试错、调整资产与策略）与 **athlete 执行进程**解耦；coach 学到的优化**跨模型可迁移**
- 技能从**执行轨迹**提炼（非仅从笔记文本）
- Elo 式能力评分，通过才进入正式能力库

#### 3.3.4 学习笔记系统
- 笔记类型：记录、学习、工作、实践、总结
- 笔记复用 §3.6 统一主生命周期；"已归档"是固化前中间标记（字段），"提炼去向"记录升格目标（字段），不另立状态链
- **提炼评分**：复用频率 / 验证次数 / 跨任务关联度达阈值才触发技能/知识条目生成——不是所有笔记都值得归档
- 可从执行轨迹**反向追溯**（Chunk Schema 含轨迹链接）

#### 3.3.5 召回双路索引
- **内容召回**（知识，走 L2 语义召回）
- **能力召回**（技能，走 L3 能力索引）

### 3.4 L2 记忆层

#### 3.4.1 单一事实时间线（回应"多会话是败笔"）
- 单条连续"生命记录"作为最终事实——无论多少前端、多少窗口，Agent 只有一条时间线
- 各写入来源（任务执行日志 / 对话摘要 / 学习笔记）经 **PIPE/Channel** 汇入统一时间线

#### 3.4.2 运行中旋转的上下文
上下文不是"选定后固定"的分层加载，而是**运行时逐段动态重排**：
- 模型生成时，按当前 token 与各 memory chunk 关系实时计分，决定放大/降权/换页
- **perplexity gate**：对当前预测可被推断（低困惑度）的 token 压掉对应上下文，把预算留给真正不确定的推理点
- **降级策略（必须）**：gate 依赖模型 logprobs；黑盒 API 不可得时，降级为"预算内优先级排序 + 静态截断"的上下文精简，机制不失效；**替代不确定性源 = 轨迹预测器 mismatch 信号**（见 §3.4.5）
- **约束钉扎（C6）**：目标 / 完成标准 / 硬约束 / 安全策略以 pinned 形态常驻，豁免 gate 降权与分页折叠
- **KV-cache 友好**：上下文转换必须段可分解（前缀转换独立于未来 token），否则吃掉 DSH 缓存命中红利、TTFT 爆炸；预算按百分比配比而非绝对 token
- 这使"单次交互不要给太多分散信息"成为**每 token 生效的注意力预算分配器**

统一上下文分页树：
- 轻量 memo 常驻 + 完整 page 按需加载
- **会话切换 = 任务切换**（切任务换"页"，底层时间线不变）
- "只显示当天上下文"是默认折叠策略；权威状态不得只靠当天上下文（C1）

#### 3.4.3 引力场记忆召回（分阶段实现）
- Chunk Schema：内容 / 类型（事实·方法·反思·技能）/ 来源（任务·对话·学习）/ 时间戳 / 情绪权重 / 置信度 / 关联任务 ID / 语义向量 / 轨迹链接
- **P1 最小版（可施工）**：三元召回 = 任务状态相关 + 时间衰减 + 被动语义相关
- **P2+ 完整版**：引入动量/情感权重的引力场——读取当前注意力潜空间邻域，拉取动量高的 chunk；叠加**主动策略相关**（Agent 基于任务状态主动问"我现在需要回忆什么"）
- **provenance gate**：低凭证记忆即使语义相关也不浮现（记忆投毒 proximity dependence：目标邻近查询高率召回中毒记忆，见 §5）

#### 3.4.4 记忆治理（C4）
- 生命周期同 §3.6 主生命周期
- 固化需**外部验证**：至少一次真实任务成功复用
- 未被复用的记忆主动降权；过期记忆主动遗忘
- **信任分层**：写入凭证化（用户原始 > 执行验证 > 模型自产）；工具返回内容与系统指令凭证隔离，防提示注入；证据回链可溯源

#### 3.4.5 轨迹资产（三态消费）
轨迹不是只用于回放，它是**一态资产、三种消费方式**：
- **回放**：DSH Trajectory 原生 resume/fork/search/replay → 决策审计、技能 rehearsal、失败归因
- **预测**：从历史轨迹检索相似 transition，预测下一步状态 / 工具结果 / 风险（WorldEvolver / MCP-Cosmos / Hybrid-WM 模式）；**预测-观测 mismatch 是 coach 元进程的核心信号**（mismatch 模式 → 提炼启发式规则进元思维库/技能库）；低置信预测不注入主上下文
- **辅助召回**：历史轨迹即情景记忆——召回"当时怎么做的"（子目标级示例、技能组合、高层捷径）；Chunk Schema 的轨迹链接字段支撑从技能/知识反向追溯轨迹

### 3.5 L1 运行时基座 DSH（现有增量）
- 复用：Cordis 插件/状态管理、事件总线、Session Log
- 自建（以 DSH 插件形态）：**Agent Harness**（主循环：目标状态机驱动、预算/终止界、上下文组装、子代理派发、契约强制）、**工作流执行器**、**常驻进程/定时/事件触发**（否则"Agent 主动排任务"无法跨会话活）
- 新增**独立调研 Agent**：定期扫描插件生态，多维评分（工程规范/兼容性/安全性/社区活跃度），S/A/B/C 分级 + 质量徽章 + 沙箱运行时测试

### 3.6 横切：认知资产卫生层（C4 统一落地）

所有资产（技能/记忆/知识/思维/流程）**共享一条统一治理管道**，环境带入差异通过类型字段表达。

**统一主生命周期**：`草稿 → 验证中 → 已固化/已发布 → 已退役`

**统一元数据**（每条资产）：来源凭证（用户原始/执行验证/模型自产）、置信度、复用次数、验证次数、跨任务关联度、时间戳、轨迹链接、版本、上游冲突标记。

**脏资产处理**：

| 资产 | 脏信号 | 处理机制 |
|---|---|---|
| 技能 | 幻觉生成/一次失效/被替代/长期未用 | 回放验证→真实复用一次才晋升；连续N次失败/被替代/N天未用→退役；写时冲突检测；活跃容量上限强制淘汰 |
| 记忆 | 投毒/过时/重复 | 凭证分阶，验证后才固化；主动遗忘；工具输出与系统指令凭证隔离；证据回链 |
| 知识 | 脱节/无权威源/被覆盖 | 蒸馏→互链(Wiki模式)；出库需复用/审查；版本可回滚；工作空间可信度层级 |
| 思维 | 推理模式失效 | 存拓扑骨架；收敛/发散双路径；回放后缓存；失败模式降权 |
| 流程模板 | 过具体/过抽象 | 分层模板(策略层/操作层)；回放验证；参数化控制抽象度 |

**资产更新维护闭环**（资产生命周期内的流动与升值）：
- **升格**：复用频率/验证次数/跨任务关联度达阈值 → 草稿→固化、局部笔记→知识条目、单任务技能→通用技能
- **降级/退役**：连续失败/被替代/N天未用/容量超限 → 降权→归档→删除
- **协调/同步**：写入冲突/版本漂移/跨资产矛盾 → 冲突检测、证据回链裁决、版本合并/回滚
- 维护引擎 = coach 元进程（见 §3.3.3），周期性后台运行；维护本身设吞吐上限，不侵蚀主任务执行

## 4. 人机监督与可观测性

- **决策轨迹可审计**：AgentState 序列化（对话缓冲 / 滚动摘要 / 任务子上下文 / 工作区产物元数据）写入事实时间线，可回放
- **风险分级 + 审批节点**：任务编排显式声明"何时需要人在场 → 给人看什么 → 如何恢复执行"
- **人类注意力配额作为一等预算**：与 token/工具调用并列，计入 §3.2.1 执行预算
- **对抗性审查**：高风险任务的子代理报告前互审发现 / 多角度起草计划并权衡（critic 模式）
- 落点：以上均挂在 L1 自建 Harness 的预算与审批节点上

## 5. 安全与信任分层（硬条款）

1. **约束钉扎（C6）**：目标/完成标准/硬约束/安全策略 pinned 常驻，豁免 gate 降权与分页折叠（实证：上下文压缩致违规 0%→30%，~47 token 钉扎恢复 0%）
2. **记忆写入检疫**：工具输出/外部内容/网页/邮件进隔离区，永不直接固化；固化 = 外部验证阀 + 凭证等级双条件（MINJA：仅正常对话即可注入）
3. **来源凭证 + 溯源链**：Chunk Schema provenance 可验证（借鉴 MemoryGraft 密码学溯源）；召回侧 provenance gate——低凭证不浮现（Sleeper：注入率最高 99.8%，中毒记忆召回后 60–89% 操纵行为）
4. **控制流/数据流分离（C3 安全面）**：子代理返回结论 = 数据流；任务定义/编排 = 控制流；任何检索/工具内容不得改写任务定义（PTE：ReAct 的动作选择暴露即注入直通路径）
5. **审计基线**：上下文注入/记忆写入/技能晋升全落 DSH Trajectory，可回放溯源（投毒溯源的基础设施）

## 7. 落地优先级

- **P0 最小可用闭环**（一任务跟到底、跨会话不丢）：目标状态机 + 任务树持久化(SQLite) + 单事实时间线 + 旋转上下文(分页+pinned约束区+gate降级版) + 子代理隔离(Lead+Sidekick初版) + 工作区语义理解初版 + 轨迹资产接入(Trajectory 审计/replay)
- **P1 记忆与能力**（第二次做事显著更优）：引力场最小召回(含 provenance gate) + 记忆治理管道(检疫/验证/退役) + 元思维库初版 + 目标漂移检测 + 轨迹预测器 v1(相似 transition 检索预测 + mismatch 记录)
- **P2 自成长与编排**（能力自我治理）：coach 元进程(mismatch→规则提炼) + 资产更新维护闭环 + 技能生命周期(回放/晋升/退役) + 引力场完整版 + 工作流外部化+执行器 + 插件调研 Agent
- **P3 长程与信任**（90 天不漂移、可审计）：分层知识图谱(Wiki 蒸馏) + 人类监督/审批/审计 + 跨模型身份持久化 + 安全加固
