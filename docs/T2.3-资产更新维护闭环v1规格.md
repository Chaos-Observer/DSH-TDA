## 1. 设计裁定

| J9 | **学习笔记字段落治理投影**（§3.3.4）：笔记 chunk 的"已归档"（固化前中间标记）与"提炼去向"（升格目标：资产类型+目标 id）两个字段记在 `gov_states` memory 分区扩展，**不动时间线条目**（append-only 铁律，同 T1.2 J2）；提炼评分=J2 三信号同款 | §3.3.4"已归档是固化前中间标记（字段），提炼去向记录升格目标（字段），不另立状态链"原文；字段进投影=零侵入权威 |

## 2. 状态模型

```
信号汇聚：recall_log(T1.1) / skill_usage_log+rehearsal_runs(T2.2) / gov_actions(T1.2)
          / conflict 记录(T1.2·T2.2) / coach 候选(T2.1) / drift_scores(T1.5 交叉参考)
   ▼ scan（周期 6h 默认 / coach review 触发 / manual；与 T1.2 scan 合并单周期，J5）
提议生成（纯函数：升格阈值 J2 / 退役优先级 J3 / 协调检测 J4）
   ▼ 风险分级（J8）
   ├─ low ──► 自动执行（经 ctx.governance / 资产 supersede）──► executed + 双写留痕
   └─ high ─► queued ──(人类一次性 token)──► approved ──► executed
                 └──(人工拒 / 审批超时)──► rejected / expired
   ▼
MaintenanceReport（append-only：scanned/proposed/executed/pendingApproval/capacityZone）
```

- **主任务活跃期**（J7）：high 中属紧急项（容量超限/安全待审）执行；其余提议排队下周期；
- 提议状态机：`queued → approved → executed` / `queued → rejected` / `queued → expired`（审批超时，U7）；
- 无"维护中"挂起态——执行是同步调用治理原语，失败即记 failed 进报告 unfinished（C5 显式终态）。

## 3. 数据模型

### 3.1 `MaintenanceProposal` / `MaintenanceAction`（append-only）

```ts type-equiv
/** 维护提议。signals 明细=可解释性依据（不变量 3）。 */
interface MaintenanceProposal {
  readonly id: ProposalId                    // branded，mp-<n>
  readonly kind: 'promote' | 'demote' | 'coordinate'
  readonly assetKind: 'memory' | 'meta-thinking' | 'skill'
  readonly assetId: string                   // EntryId | MetaPathId | SkillId（弱引用）
  readonly action: {                         // 拟执行的原语描述（执行时翻译为治理调用）
    readonly primitive: 'consolidate' | 'retire' | 'restore' | 'propose-invalidate' | 'supersede'
    readonly reason: { kind: string; detail: string }   // kind 含升格三信号/退役四信号/协调三子型
    readonly supersedeDraft?: unknown        // kind=coordinate 合并时的新版草稿引用
  }
  readonly signals: {
    readonly reuseCount: number              // recall_log / skill realUse
    readonly verifyCount: number             // rehearsal pass / gov verifiedBy
    readonly associationSpread: number       // relatedTaskId 跨任务分散度
    readonly eloNorm?: number                // skill Elo 归一（J6）
    readonly thresholds: { reuse: number; verify: number; association: number }   // 当时阈值快照
  }
  readonly risk: 'low' | 'high'              // J8：容量淘汰/invalidate/冲突合并=high
  readonly status: 'queued' | 'approved' | 'executed' | 'rejected' | 'expired'
  readonly govActionId?: GovActionId         // 执行后回填（对账，§5.5）
  readonly source: { kind: 'scan' | 'coach'; ref?: ReviewId }
  readonly createdAt: number
  readonly resolvedAt?: number
}

/** 提议的执行/审批记录。 */
interface MaintenanceAction {
  readonly id: MaintenanceActionId           // ma-<n>
  readonly proposalId: ProposalId
  readonly op: 'auto-execute' | 'approve' | 'reject' | 'expire'
  readonly actor: WriterRef                  // { sessionId, actor: 'human'|'coach'|'scheduler', at }
  readonly approvalToken?: string            // J8 一次性 token 引用（只用不存全文）
  readonly result?: 'ok' | 'failed'
  readonly at: number
}
```

### 3.2 `MaintenanceReport`（周期报告，append-only）

```ts type-equiv
interface MaintenanceReport {
  readonly id: ReportId                      // mr-<n>
  readonly trigger: { kind: 'periodic' | 'coach-review' | 'manual'; at: number }
  readonly stats: { scanned: number; proposed: number; autoExecuted: number; pendingApproval: number; rejected: number; deferredActive: number }
  readonly capacity: { perKind: Record<'memory'|'meta-thinking'|'skill', { active: number; cap: number; zone: 'normal'|'pressure'|'over' }> }
  readonly proposalIds: ProposalId[]
  readonly unfinished?: string[]             // failed 时未完成清单（C5）
  readonly at: number
}
```

### 3.3 SQLite schema（`ctx.storage` sqlite domain，DomainSpec）

| 表 | 键 | 值 | 说明 |
|---|---|---|---|
| `maintenance_proposals` | ProposalId | MaintenanceProposal 全量 | append-only 提议史 |
| `maintenance_actions` | MaintenanceActionId | MaintenanceAction 全量 | append-only 执行/审批史 |
| `maintenance_reports` | ReportId | MaintenanceReport 全量 | append-only 周期报告 |
| `maintenance_params` | `'singleton'` | { cycleMs, caps: { maxActions, maxScanned }, promoteThresholds: { reuse, verify, association }, scoreWeights: { elo: 0.3, reuse: 0.3, recency: 0.2, verify: 0.2 }, demotePriority: ['capacity','use-fail','rehearsal-fail','superseded','unused-days'], approvalTimeoutMs } | 参数权威；layout `single` |

## 4. 不变量与服务 API

### 4.1 不变量（加载即校验 / 运行时强制）

1. **编排非权威**：不存在绕过 `ctx.governance`/资产服务的状态变更路径；每次 executed 提议必回填 `govActionId` 或资产服务 accepted 变更 id（服务端断言+对账）；
2. **无第二退役判据**：退役提议的 reason.kind 必属既有检测器产出集合（T1.2 四信号/T2.2 stats）或显式 manual（白名单断言）；
3. **升格可解释**：promote 提议必带三信号数值+当时阈值快照（缺一拒绝生成）；
4. **高风险人类审批**：容量强制淘汰/invalidate 提议/冲突合并三类无一次性 token 不得执行（服务端断言，token 一次性消费）；
5. **渐进降级不跳级**：retired 前不得 propose-invalidate（服务端断言；降权→归档→删除顺序，J3）；
6. **合并即新条目**：coordinate 合并=supersede 新条目/新版本，旧条目保留可溯，无删除路径（J4）；
7. **吞吐帽+让位**：单周期动作≤`caps.maxActions`、扫描≤`caps.maxScanned`；主任务活跃期非紧急提议 defer（`deferredActive` 计数进报告）；
8. **可重放**：同信号快照+同 params⇒同提议序列；replay maintenance_actions 重建 proposals 状态零差异（T0.7 replay-equivalence 扩展）；
9. **留痕**：提议/执行/审批双写 log-only session event `maintenance/change`（P2 扩展事件族，承 T0.7 J2：log-only/JSON 无损/稳定业务 id=proposalId）+ 入 `audit_index`（entityKind='maintenance'）。

### 4.2 `ctx.maintenance` 服务方法

```ts type-equiv
interface MaintenanceService {
  cycle(trigger: { kind: 'periodic' | 'coach-review' | 'manual'; ref?: ReviewId }): MaintenanceReport   // 跑一轮维护
  proposals(filter?: { status?; kind?; risk?; assetKind? }): MaintenanceProposal[]
  approve(proposalId: ProposalId, token: ApprovalToken): MaintenanceAction    // 高风险审批执行（J8）
  reject(proposalId: ProposalId, reason: string): MaintenanceAction
  scoreboard(): GovernanceScoreboard                                        // 跨资产统一治理分排名（J6）
  enqueueFromCoach(candidateIds: CandidateId[]): MaintenanceProposal[]       // T2.1 coach 候选直入队列（J5①）
  reports(limit?: number): MaintenanceReport[]
  params(): MaintenanceParams
  setParams(patch: Partial<Omit<MaintenanceParams, 'revision'>>): MaintenanceParams
}

interface GovernanceScoreboard {
  readonly entries: { assetKind: string; assetId: string; score: number; parts: { elo: number; reuse: number; recency: number; verify: number } }[]
  readonly capacity: MaintenanceReport['capacity']
}
```

- `cycle` 内部序：读水位→扫信号（recall_log/skill_usage_log/rehearsal_runs/gov_actions/conflict 记录，≤帽）→ 生成提议（升格阈值/退役优先级/协调检测，纯函数）→ 分级执行（low 自动/high 入队；主任务活跃期 defer 非紧急）→ 逐条落盘+双写 → 产报告；
- `approve` 内部序：校验 token（一次性）→ 翻译 primitive 为治理调用 → 执行 → 回填 govActionId；
- `enqueueFromCoach`：T2.1 review 的 submitted 候选（已过验证阀）转为本引擎 low 风险提议（目标固化）或 high（控制流面，承 T2.1 J10）；
- 与 T1.2 scan 关系：**单周期双消费**（J5/U6）——T1.2 `scan()` 检出脏信号，本引擎 `cycle()` 同一 scan 窗口内编排执行；实现上共用 `gov_scan_state` 水位。

## 6. 验收标准（对 Gate G2 的贡献项）

1. **升格闭环（G2-① 维护侧）**：memory chunk 跨 3 个不同任务被复用且验证次数达阈 → cycle 产出 promote 提议（带三信号数值+阈值快照）→ 自动执行 → gov_actions 可查 consolidate → T1.1 浮现；笔记的 archived/promoteTarget 字段落 gov_states 而 chunk 字节不变（J9 自检）；
2. **技能通用化**：单任务技能（applicability 窄）跨 taskClass 复用达阈 → coordinate/supersede 提议 → 新版 applicability 扩大 → 旧版 retire[superseded] → 新版仍走 rehearsal+真实复用双条件（不变量 1 对账：无绕过治理的迁移）；
3. **渐进降级不跳级**：对 consolidated 资产直接 propose-invalidate 被服务端拒绝（不变量 5 自检）；容量超限 → scoreboard 跨资产统一分排名淘汰最低者（带 parts 明细）；
4. **协调收敛**：构造 near-dup 对 → 合并提议（high）→ 无 token 被拒 → token 审批 → supersede 新条目 → 旧条目 history() 可溯（Mem0 add-only 自检）；版本悬挂态（旧 retired 新未 consolidated）检出并提议补动作；跨资产矛盾只标不裁（人工队列可见）；
5. **高风险审批**：容量强制淘汰/invalidate/冲突合并三类无 token 拒绝+留痕；token 一次性消费（重复使用被拒）；
