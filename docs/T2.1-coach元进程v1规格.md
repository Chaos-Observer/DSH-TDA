## 2. 状态模型

```
触发（periodic 24h / mismatch-surge / manual）
   │
   ▼ scan（增量水位 coach_scan_state，六路只读数据源 J2）
review run: requested → scanning → analyzing → proposing → recorded
                                              └──→ failed（显式终态 + unfinished 清单）
   │ proposing：模式→候选（J3）→质量门（J12）→物化 draft（J4）
   ▼
candidate: proposed → rehearsing → validated → transfer-verified → submitted
                 ├─→ rejected（质量门/rehearsal 失败/人工拒）
                 └─→ deferred（kind=skill，等 T2.2 seam）
   │ submit：low/medium 自动 / high 需人类一次性 token（J10）
   ▼
资产侧既有管道：draft → validating → consolidated（ctx.governance）→ T0.4 注入池浮现
```

- **双环**：athlete=主执行循环（Harness）；coach=本规格。coach 产物**只经资产库间接**影响 athlete（J11 禁直通）；
- candidate 的 rehearsal/transfer 是**异步**子状态机（跨 review 轮次推进），不属于单次 review run——review run 只负责"产出候选并物化 draft"与"汇总历史候选的验证结果进报告"；
- 回放确定性：review/candidate 的全部判定输入（log 前缀+params+水位）落盘，报告可复算（不变量 4）。

## 3. 数据模型

### 3.1 `CoachReview`（复盘 run，append-only）

```ts type-equiv
/** 一次复盘运行记录。report 全结构化（零自然语言长篇，J8）。 */
interface CoachReview {
  readonly id: ReviewId                       // branded，cr-<n>
  readonly trigger: { kind: 'periodic' | 'mismatch-surge' | 'manual'; at: number }
  readonly window: { fromSeq: number; toSeq: number; fromAt: number; toAt: number }   // 扫描窗口（水位推进依据）
  readonly status: 'requested' | 'scanning' | 'analyzing' | 'proposing' | 'recorded' | 'failed'
  readonly stats: {
    readonly mismatchesScanned: number
    readonly patternsFound: number
    readonly candidatesProposed: number
    readonly candidatesRejected: number
    readonly rehearsalsRun: number
    readonly humanApprovalsRequested: number
  }
  readonly patterns: PatternSummary[]         // 报告主体（结构化）
  readonly candidateIds: CandidateId[]
  readonly govActionRefs: GovActionId[]       // 本轮 submit 产生的治理动作引用
  readonly unfinished?: string[]              // failed 时未完成清单（C5）
  readonly at: number
}

/** 模式摘要：聚类键+分布+证据引用。无原文（J3）。 */
interface PatternSummary {
  readonly key: string                        // 聚类键（分类键拼接，如 "executing|write-op|edit"）
  readonly condition: HeuristicCandidate['condition']
  readonly deltaKinds: Record<'action' | 'outcome' | 'risk-materialized' | 'none', number>
  readonly topErrorClasses: { errorClass: string; freq: number }[]
  readonly count: number
  readonly evidence: { mismatchIds: MismatchId[]; transitionIds: TransitionId[] }
}
```

### 3.2 `HeuristicCandidate`（候选，append-only）

```ts type-equiv
/** 启发式规则候选。零原文泄漏：分类键+引用+数字+拓扑（J3）。 */
interface HeuristicCandidate {
  readonly id: CandidateId                    // branded，hc-<n>
  readonly kind: 'meta-path' | 'skill' | 'method-memory'     // 分流目标（J4）
  readonly risk: 'low' | 'medium' | 'high'                   // 控制流面=high（J10）
  readonly condition: {                                          // 适用条件（分类键，非原文）
    readonly taskClasses: string[]
    readonly stages: TaskNode['stage'][]
    readonly problemFeatures: string[]
    readonly actionPattern?: string            // 触发动作模式（分类串）
  }
  readonly rule: {                                             // 规则体（结构化）
    readonly expect?: string                  // 预期动作/结果模式（分类串）
    readonly avoid?: string[]                 // 规避的 errorClass/失败模式
    readonly prefer?: string[]                // 优先动作模式
    readonly shape?: MetaPath['topology']     // kind=meta-path：拓扑（引用 T1.4 schema）
  }
  readonly evidence: {                                          // 证据=引用不拷贝
    readonly mismatchIds: MismatchId[]
    readonly transitionIds: TransitionId[]
    readonly sessions: { sessionId: SessionId; seqFrom: number; seqTo: number }[]
  }
  readonly confidence: number                  // 证据强度 0-1（样本数×一致性，J3 聚合）
  readonly status: 'proposed' | 'rehearsing' | 'validated' | 'transfer-verified' | 'submitted' | 'rejected' | 'deferred'
  readonly draftRef?: { kind: 'meta-path' | 'skill' | 'timeline-entry'; id: string }   // 物化落点
  readonly transfer?: { verified: boolean; modelProfiles: string[] }                   // J6 迁移验证
  readonly reviewId: ReviewId
  readonly createdAt: number
  readonly updatedAt: number
}
```

### 3.3 SQLite schema（`ctx.storage` sqlite domain，DomainSpec）

| 表 | 键 | 值 | 说明 |
|---|---|---|---|
| `coach_reviews` | ReviewId | CoachReview 全量 | append-only 复盘史；报告主体 |
| `coach_candidates` | CandidateId | HeuristicCandidate 全量 | append-only 候选史（staging，非资产） |
| `coach_scan_state` | `'singleton'` | { lastSeq, lastAt, lastReviewAt, surgeWindow: { sinceAt, nonNoneCount } } | 增量水位 + surge 窗口计数 |
| `coach_params` | `'singleton'` | { periodMs, surgeThreshold, surgeWindowMs, maxMismatchScan, maxCandidatesPerReview, maxRehearsalConcurrent, reviewBudgetMs, minEvidenceCount, minConfidence, approvalRequiredRisk: ['high'] } | 参数权威；layout `single` |

- domain version=1；**四表全 `invalidRecords:'backup-and-skip'`**——coach 是认知资产非权威，全表丢失=同 log+同 params 重扫重建（J8），不阻断系统；
- **lifecycle 不在本 domain**：候选固化/退役状态单一权威在 `ctx.governance`（J5），本 domain 只记 coach 侧工作流状态。

## 4. 不变量与服务 API

### 4.1 不变量（加载即校验 / 运行时强制）

1. **零直接资产写权**：coach 只经三路径物化——①目标库 propose（draft 态）②`ctx.governance` 动作 ③PIPE append（method-memory，凭证 model-produced）；服务端断言 coach 不产生任何资产的治理态变更与已固化内容修改；
2. **未验证零固化**：candidate 未经 rehearsal pass（meta-path/skill）或达 `minConfidence`+质量门（method-memory）不得 submit；`risk='high'` 无人类 token 不得 submit（服务端断言）；
3. **零原文泄漏**：`coach_candidates`/`coach_reviews` 字段白名单断言（分类键+引用+数字+拓扑）；grep 自检：库内无构造注入的原文句（承 T1.3 不变量 2/T1.4 不变量 2）；
4. **复盘确定性**：同 log 前缀 + 同 params + 同水位 ⇒ 同 CoachReport（模式聚类与候选生成纯函数；replay-equivalence 同 T1.3 不变量 5）；
5. **吞吐帽**：单 review 扫描≤`maxMismatchScan`、候选≤`maxCandidatesPerReview`、rehearsal 并发≤`maxRehearsalConcurrent`、耗时≤`reviewBudgetMs`；主任务活跃期 rehearsal 让位（J9）；
6. **高风险人类审批**：`risk='high'` 候选 submit 需一次性 token，token 一次性消费、拒绝留痕（J10）；
7. **无注入直通**：coach 不写 T0.4 injection 区；非 consolidated 资产零浮现（服务端断言，J11）；
8. **fail-open**：复盘/聚类/物化任何异常→该轮 review 记 `failed`+unfinished，不阻断主任务链路（承 T1.3 不变量 7）；
9. **留痕可审计**：review/candidate 全动作双写 log-only session event `coach/change`（P2 扩展事件族，承 T0.7 J2 规范：log-only/JSON 无损/稳定业务 id=reviewId/candidateId）+ 入 `audit_index`（新 entityKind `coach-review`/`coach-candidate`）。

### 4.2 `ctx.coach` 服务方法

```ts type-equiv
interface CoachService {
  review(trigger: { kind: 'periodic' | 'mismatch-surge' | 'manual' }): CoachReview   // 跑一轮复盘（含物化 draft）
  candidates(filter?: { status?; kind?; risk?; reviewId? }): HeuristicCandidate[]
  rehearseCandidate(candidateId: CandidateId, taskId: TaskId): RehearsalRun          // 委托目标库 rehearse（T1.4/T2.2）
  verifyTransfer(candidateId: CandidateId, modelProfile: string): TransferResult     // 跨模型迁移验证（J6）
  submit(candidateId: CandidateId, approval?: ApprovalToken): GovAction              // 提请固化（经 ctx.governance；high 需 token）
  reports(limit?: number): CoachReview[]
  params(): CoachParams
  setParams(patch: Partial<Omit<CoachParams, 'revision'>>): CoachParams
}

interface TransferResult { candidateId: CandidateId; modelProfile: string; verdict: 'pass' | 'fail'; rehearsalId: RehearsalId }
```

- `review` 内部序：读水位→扫 mismatches/transitions（≤帽）→模式聚类（纯函数）→质量门（J12）→产候选（≤帽）→物化 draft（propose/PIPE；skill 记 deferred）→汇总历史候选验证结果→写 CoachReview+`coach/change`；
- `rehearseCandidate`：读 candidate.draftRef → 委托 `ctx.metaThinking.rehearse(draftRef.id, taskId)`（T1.4；skill 类 T2.2 同构 seam）→ 回写 candidate.status；
- `submit`：断言不变量 2 → `ctx.metaThinking.requestConsolidate` / T2.2 晋升 / method-memory 无需 submit（PIPE 落库即入既有管道，此处仅记录）→ 返回 GovAction；
- 与 T2.3 边界：升格/降级/协调三动作编排归 T2.3 维护引擎，T2.1 只提交候选与证据（J13）。

## 6. 验收标准（对 Gate G2 的贡献项）

1. **G2-③ coach 提炼规则跨模型可迁移（主项）**：构造 mismatch 流（"stage=executing + 写操作 → errorClass=timeout"模式 3 次）→ `review` 产出 meta-path 候选（evidence 引用 3 条 mismatch）→ `rehearseCandidate` 通过（模型 A）→ `verifyTransfer`（模型 B）pass → `transfer.verified=true` → `submit` → 治理 consolidated → **模型 B 配置的会话注入池可见该元路径**（跨模型迁移闭环）；
2. **mismatch→候选链路**：模式聚类正确（同分类键聚一类、deltaKind/errorClass 分布与构造一致）、候选 schema 完整（condition/rule/evidence/confidence）、质量门拦截（证据<`minEvidenceCount` 的候选 rejected 不入 rehearsal）；
3. **零直接写权自检**：候选 `proposed` 态时 `meta_paths`/`gov_states` 零变化；物化只产 draft；未 submit 前 `gov_actions` 无 consolidate 记录（自动断言）；
4. **双触发**：周期到期与 surge 超阈（窗口内 `deltaKind≠'none'` ≥ `surgeThreshold`）各触发一次增量复盘，`coach_scan_state` 水位正确推进、不重复扫描同一 mismatch；
5. **回放确定性**：删 coach 四表 → 同 log+同 params 重跑 → CoachReview 逐字段一致（模式/候选/证据引用/stats）；
6. **吞吐帽**：构造 1000 条 mismatch → 单 review 扫描≤帽、候选≤帽、rehearsal 并发≤2、耗时≤帽；主任务 round 活跃期间 rehearsal 排队不抢占（计时断言，J9）；
7. **高风险审批**：`risk='high'` 候选无 token `submit` 被拒且留痕；token 一次性消费（重复使用被拒）；
8. **留痕审计**：review/candidate 全动作 `coach/change` 事件可 `locate`（T0.7 auditView），与物化落点（`metaPath/change`/`timeline/write`）经业务 id 交叉对账一致。
