## 1. 设计裁定

## 2. 状态模型

```
request(requester, kind, riskLevel, subject, whatToShow, resume)
   │
   ▼
pending ── token 签发 + attention 计费（J7）──────────────────────────────┐
   ├─ approve(id, token)   → approved  → ResumeTicket → 调用方续跑
   │                         （T2.5 resumeFrom / T0.5 starting / 治理 execute / T2.2 adoptExternal）
   ├─ reject(id, token, note?) → rejected → 显式终态（调用方取消/补偿；已 done 保留）
   ├─ cancel（调用方撤销：条件消失/任务取消）→ cancelled（不计响应）
   └─ token 过期            → pending（回池可重签；**无任何自动 resolved 路径**，J5）

digest（免审执行项的批量人类面）：medium/low 动作执行即入 digest 池
   → flushDigest（窗/容量触发，聚合计费 J7）→ 人类浏览 + veto(项, reason)
   → 否决=事后回滚入口（仅可逆动作可入 digest；不可逆最低 high=J2 元规则）

注意力预算三区（承 T0.2 J6 口径，J8）：
  [0, 80%)    正常：high 逐项推送，入队即计费
  [80%, 100%) 压力：medium/low 转 digest；high 逐项+预算告警标注
  [100%, ∞)   exhausted 免打扰：新请求全入 digest 排队不推送+显式告警；
              任务侧按 T0.2 J6 显式终态/挂起；digest 是人类回到循环的入口
```

- 审批项是**挂起的状态机快照+恢复句柄**（resume.handle），监督服务不持有执行逻辑（J5）；
- 状态迁移全部双写 `supervision/change`（append-only 事件权威），`approval_requests` 表记录当前态（CAS `expectedRevision` 同 T0.2 模式）；
- 回放确定性：token/计费/迁移输入全落盘，`approve` 判定可复算（不变量 6/12）。

## 3. 数据模型

### 3.1 `ApprovalRequest`（审批项本体）

```ts type-equiv
/** 人类审批项。whatToShow 面向人类（可含必要片段）；模型面只见 resolution（不变量 10）。 */
type ApprovalKind = 'task-proposal' | 'dispatch' | 'governance' | 'coach-submit' | 'maintenance' | 'workflow-node' | 'adoption-candidate'
type RiskLevel = 'low' | 'medium' | 'high'

interface ApprovalRequest {
  readonly approvalId: ApprovalId              // branded，apr-<n>
  readonly kind: ApprovalKind
  readonly riskLevel: RiskLevel                // J2 规则表查定（禁 LLM 判级）
  readonly requester: { service: string; ref: string }   // 调用方服务名+业务 id（dispatchId/govActionId/run#step…）
  readonly subject: string                      // ≤120 字符一句话（禁正文）
  readonly whatToShow: {
    readonly summary: string                    // ≤200 字符结构化摘要
    readonly impact: { target: string; change: 'create' | 'update' | 'invalidate' | 'execute'; reversible: boolean }[]
    readonly riskReasons: string[]              // 定级理由=规则命中项（可解释）
    readonly evidence: { kind: 'timeline-entry' | 'session-log' | 'assessment' | 'drift-score' | 'transition'; ref: string }[]
    readonly excerpts?: { ref: string; text: string }[]   // 必要原文片段 ≤3×500 字符（人类呈现+审计重建，J6）
    readonly critiques?: string[]               // critic 互审结论（T0.5 J6 消费）≤3 条
    readonly alternatives?: { label: string; tradeoff: string }[]   // 多方案权衡（alternativeOf 消费）
  }
  readonly resume: { from: string; handle: string }        // 恢复句柄（J5：监督服务只发票不代跑）
  readonly status: 'pending' | 'approved' | 'rejected' | 'cancelled'
  readonly token: { nonce: string; issuedAt: number; expiresAt: number; consumedAt?: number }   // 当前有效 token（单签，J4）
  readonly resolution?: { decision: 'approve' | 'reject'; by: 'human'; note?: string; at: number; tokenNonce: string }
  readonly attention: { units: number; chargedAt: number; respondedAt?: number }   // J7（digest 项 chargedAt=flush 时）
  readonly taskId?: TaskId                      // 计费落点（至少与 goalId 其一，不变量 7）
  readonly goalId?: GoalId
  readonly createdAt: number
  readonly updatedAt: number
}
```

### 3.2 `AttentionCharge`（注意力记账，append-only 旁路）

```ts type-equiv
/** 一次人类注意力事件。units=纯函数可复算（不变量 6）。 */
interface AttentionCharge {
  readonly chargeId: AttentionId                // branded，att-<n>
  readonly approvalId?: ApprovalId              // 关联审批项（digest 批电荷无单项）
  readonly kind: 'approval' | 'digest' | 'escalation'   // escalation=漂移升级/容量告警等非审批注意力事件（T1.5 J5/T1.2 J12 消费）
  readonly units: number
  readonly taskId?: TaskId
  readonly goalId?: GoalId                      // 至少其一（服务端断言）
  readonly at: number
}
```

### 3.3 `SupervisionEvent`（事件权威，append-only）/ `SupervisionParams`

```ts type-equiv
/** log-only session event supervision/change 的领域形态（第十事件族，承 T0.7 J2 规范）。 */
interface SupervisionEvent {
  readonly eventId: string                      // 稳定业务 id=approvalId#eventKind#seq
  readonly kind: 'requested' | 'token-issued' | 'token-expired' | 'approved' | 'rejected' | 'cancelled'
             | 'attention-charged' | 'digest-flushed' | 'digest-vetoed' | 'params-changed'
  readonly approvalId?: ApprovalId
  readonly payload: Record<string, unknown>     // JSON 无损（禁大正文，excerpts 走 whatToShow 存档）
  readonly at: number
}

interface SupervisionParams {
  readonly autonomyLevel: 'full-auto' | 'high-risk-only' | 'full-approval'   // J2，默认 high-risk-only
  readonly riskTable: Record<string, RiskLevel>           // 动作类型→档位（结构化规则表，可配）
  readonly baseUnits: { low: number; medium: number; high: number }         // 默认 1/3/5
  readonly volumeFactorCap: number                        // 呈现项数系数封顶（默认 3）
  readonly tokenTtlHours: number                          // token 有效期（默认 24；过期回 pending 不 resolved）
  readonly zoneThresholds: { pressure: number }           // 压力区阈值（默认 0.8，承 T0.2 J6）
  readonly maxDigestItems: number                         // digest 窗容量（触发 flush）
  readonly digestWindowHours: number                      // digest 时间窗（默认 24）
  readonly maxExcerpts: number                            // whatToShow 片段帽（默认 3）
  readonly requestRateLimitPerHour: number                // 审批请求洪水帽（默认 50）
}
```

### 3.4 SQLite schema（`ctx.storage` sqlite domain，DomainSpec）

| 表 | 键 | 值 | 说明 |
|---|---|---|---|
| `approval_requests` | ApprovalId | ApprovalRequest 全量 | **人类决策权威**；CAS expectedRevision 状态迁移（同 T0.2）；`invalidRecords:'reject-open'`——人类决定丢失=审计断裂（G3-②），不可静默跳过 |
| `supervision_events` | eventId | SupervisionEvent | append-only 事件权威；与 DSH session log 双写，`backup-and-skip` 可经 log 重放重建 |
| `attention_ledger` | AttentionId | AttentionCharge | append-only 旁路（同 T1.1 recall_log 模式）；units 确定性可复算，`backup-and-skip` |
| `supervision_params` | `'singleton'` | SupervisionParams | 参数权威；layout `single`；`backup-and-skip`（回默认） |

- domain version=1；
- **lifecycle 不在本 domain**：审批项不是认知资产（同 T2.6  scout 评估定位），不登记 `ctx.governance`；治理动作的审批请求只是 requester='governance' 的呈现入口，执行仍归 T1.2/T2.3；
- digest 不建表：digest 视图=pending/免审池的聚合查询（派生），flush/veto 落事件+ledger。

## 4. 不变量与服务 API

### 4.1 不变量（加载即校验 / 运行时强制）

1. **审批状态单一权威**：状态以 `approval_requests` domain 为准；DSH User Approval 侧记录与 domain 双写对账（断言：两侧 id 集相等，DSH 断连时 domain 侧 pending 不丢）；
2. **一次性 token 单次有效**：`approve/reject` 消费即焚（服务端断言 `consumedAt` 已置则拒绝）；token 过期只回 pending 不 resolved；`audit_index` 对账零二次消费；
3. **无超时自动通过**：枚举全部状态迁移函数，不存在时间参数驱动的 `pending→approved` 路径（CI 断言；唯一 resolved 路径=人类 token 动作或调用方 cancel）；
4. **恢复凭票**：`approve` 产出 ResumeTicket 单次有效；监督服务无续跑/执行代码路径（职责边界，J5）；
5. **显式终态可审计**：`rejected/cancelled` 必带 reason；已 done 步骤/已完成写入保留，不静默回滚（整体回滚仅经治理 invalidate，同 T2.5 J6）；
6. **注意力计费确定性**：`units=base(riskLevel)×min(volumeFactor,cap)` 纯函数，同请求同 params⇒同 units，可逐条复算；
7. **计费落点必填**：`taskId`/`goalId` 至少其一（服务端断言）；ledger 只追加，不改 T0.2 `consumed.attentionUnits` 以外的任何任务/目标字段；
8. **不可逆动作最低 high**：规则表元规则服务端断言（`impact[].reversible=false` 的动作 riskLevel='high'）；digest 只收可逆项；
9. **仪表盘/审计面零写权**：只读 API 白名单断言（同 T1.5 J1 纪律）；`replayView` 回写路径不存在（回放=派生子会话只读消费）；
10. **呈现与模型面分离**：`whatToShow`（含 excerpts/critiques）不进任何注入/召回路径（服务端断言+grep 自检）；模型侧仅见 `resolution.decision+note`（经 PIPE user-original，J9）；
11. **留痕双写**：一切迁移双写 `supervision/change`（log-only/JSON 无损/稳定业务 id）+`audit_index`（entityKind='approval'\|'attention'）；
12. **参数即策略**：autonomyLevel/riskTable/baseUnits/帽全部经 params 可审计；setParams 双写 params-changed 事件（同 T1.1 params 模式）。

### 4.2 `ctx.supervision` 服务方法

```ts type-equiv
interface SupervisionService {
  request(input: ApprovalRequestInput): ApprovalRequest      // 唯一入队口（各调用方服务端发起，J1/J12）
  cancel(approvalId: ApprovalId, reason: string): ApprovalRequest          // 调用方撤销（不计响应）
  approve(approvalId: ApprovalId, token: string): ResumeTicket             // 一次性 token 消费（J4/J5）
  reject(approvalId: ApprovalId, token: string, note?: string): ApprovalRequest   // 显式终态（J5）
  pending(filter?: { riskLevel?; kind?; taskId?; goalId? }): readonly ApprovalRequest[]   // 人类查询面
  digest(range?: { from: number; to: number }): DigestView    // 免审项聚合+否决入口（J8）
  veto(digestItemRef: string, reason: string): void           // 事后否决=回滚入口（仅可逆项）
  flushDigest(): DigestView                                   // 窗/容量触发，聚合计费（J7）
  attentionStatus(goalId?: GoalId, taskId?: TaskId): AttentionStatus       // 四维+曲线+待审深度+响应分位
  dashboard(range?: { from: number; to: number }): DashboardView           // 只读聚合（J10）
  auditView(query: { entityKind?; entityId?; taskId?; goalId?; from?; to? }): AuditView   // J11
  trace(entityKind: string, entityId: string): TraceView      // provenance 反查=投毒溯源（§5.5）
  replayView(sessionId: SessionId, seqRange?: { from: number; to: number }): ReplayView   // 只读回放（DSH Trajectory 消费）
  params(): SupervisionParams
  setParams(patch: Partial<SupervisionParams>): SupervisionParams
}

interface ApprovalRequestInput = Omit<ApprovalRequest, 'approvalId' | 'status' | 'token' | 'resolution' | 'attention' | 'createdAt' | 'updatedAt'>
interface ResumeTicket { readonly approvalId: ApprovalId; readonly nonce: string; readonly from: string; readonly handle: string; readonly consumedAt?: number }
```

- `request` 内部序：规则表查定 riskLevel（J2，禁调用方自定高档绕过）→ 校验计费落点 → 预算三区判定推送方式（J8）→ 落 domain+签发 token+计费 → 双写事件 → DSH seam 推送（逐项）或入 digest 池（批量）；
- `approve/reject` 内部序：校验 token（存在/未消费/未过期）→ 迁移状态+消费 token → 双写事件 → PIPE 回写时间线（user-original，J9）→ 返回 ResumeTicket/终态记录；
- 与调用方的续跑契约：调用方订阅 `supervision/change`（approved/rejected）或轮询，按 `resume.handle` 自续——监督服务不 import 任何调用方模块（依赖倒置，防 supervision 长成总编排器）；
- `attentionStatus`/`dashboard`/`auditView`/`trace`/`replayView` 全部只读组装既有 domain（T0.2 consumed/T1.5 drift_scores/T0.4 AssembleRecord/T0.7 audit_index/T2.6 assessments），无新权威。

## 6. 验收标准（对 Gate G3 的贡献项）

1. **G3-② 主项-审批链路**：高风险 dispatch 全链路（服务端 request→规则表定级 high→DSH seam 呈现→人类 approve(token)→ResumeTicket→T0.5 approved→starting 续跑→audit_index 对账）；决策链 `auditView` 回放=同 log+同 params⇒同视图（承 T0.7 J4 确定性）；
2. **无超时自动通过**：pending 项 7×24h 自愈测试零 resolved；token 过期回 pending 可重签；CI 断言迁移函数枚举无超时分支；
3. **token 防重放**：重复 approve/reject 服务端拒绝+事件流零二次消费对账；
4. **reject 显式终态+工作流恢复**：rejected 带 reason、已 done step 保留可审计；串联 T2.5——approvalNodes 审批后 `awaiting-approval→running` 从 resumeFrom 精确续跑（T2.5 验收 4 的人类侧闭环）；
5. **注意力计量与三区**：units 复算逐条相等；80% 压力区 medium/low 转 digest；100% exhausted 免打扰+显式告警+任务侧显式终态/挂起；digest flush 聚合计费+veto 回滚（仅可逆项）；
6. **仪表盘零写权**：只读 API 白名单断言+写入尝试拒绝自检；四维对比/注意力曲线/待审深度/响应分位数据面与各权威域对账一致；
7. **投毒溯源（§5.5）**：构造中毒 chunk→T1.1 recall→注入→决策→`trace` 反查写入 session/seq+召回记录+消费链完整呈现；
8. **跨会话持久化**：kill-9 恢复后 pending 项+ledger 完好（`approval_requests` 拒绝打开校验通过）；DSH seam 断连重连后双写对账相等。
