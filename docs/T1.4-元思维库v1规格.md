## 1. 设计裁定

| # | 裁定 | 理由 |
|---|---|---|
| J1 | **元思维 = 统一治理管道的第三种资产实例**：lifecycle 全部登记 `ctx.governance`（T1.2，assetKind=`'meta-thinking'`），本服务只定义元思维特有的 schema 与 rehearsal 验证机制，**不造第二治理服务、不存第二 lifecycle 状态** | §3.3.2 明文"生命周期与治理走 §3.6 统一管道"；T1.2 J1 预埋 assetKind 维度正是为此——P1 内即验证管道通用性（memory→meta-thinking 两实例），T2.2 技能第三实例同构；治理状态投影与 memory 同表（kind 分区，T1.2 memory_gov_states 视为其 memory 分区命名，实现时并为 gov_states） |

| J6 | **"回放验证才缓存"= 未验证候选零注入**：draft 候选不进注入池；rehearsal 通过 → 提请治理 `consolidate`（§3.6 固化阀）；失败 → `stats.rehearsalFail++`，**失败模式降权**=连续失败达阈值自动退役（J8），未达阈值则该路径排序分按失败率折减 | §3.3.2 原文"失败模式降权"；缓存闸与治理固化闸合一（J1），不另立缓存状态 |

| J8 | **连续 rehearsal 失败自动退役**（与 T1.2 J7 记忆口径的差异裁定）：`consecutiveRehearsalFail≥N` → 自动 `retire(kind='rehearsal-fail')`——**这是直接证据不是弱归因**，不适用记忆的保守纪律 | T1.2 J7 对"连续失败"保守是因为任务失败归因到单条记忆证据弱；rehearsal 失败是拓扑本身的受控实验证伪，§3.6"失败模式降权"的直接落地 |
| J9 | **双环中的位置**：coach 元进程（观察/复盘/试错/调整）= T2.1（P2），athlete=主执行；T1.4 只建资产库+验证机制，coach 驱动留 `actor:'coach'` WriterRef 位（同 T1.2 J11/T1.3 J10 模式），Elo 式评分占位（stats.realUse/rehearsal 通过率先行） | §3.3.3 双环原文；Elo 归 T2.2/T2.3 能力评分体系统一（U3），v1 不预造 |

## 2. 状态模型

元路径无自有 phase——lifecycle 归治理管道（J1）。本服务的"状态"= **rehearsal 验证循环**：

```
propose（coach/人/轨迹抽取辅路）──► draft（治理态）
   │
   ▼ rehearse(mp, task)（T0.7 fork + 子会话试错）
判定 success ∧ coverage≥θ_cov？
   ├─ 是 ──► stats.rehearsalPass++ ──► 提请 consolidate ──► consolidated ──► 注入池（J7 结构提示）
   └─ 否 ──► stats.rehearsalFail++（连续失败≥N → 自动 retire[rehearsal-fail]）
consolidated ──真实使用/新 rehearsal──► stats 更新（realUse/pass 率）──► 治理分重排（J10）
consolidated ──被更优拓扑替代──► supersede 新版 + 旧版 retire[superseded]（治理管道，同 T1.2 J7）
```

- `rehearsal_runs` 是 append-only 验证史（coach 复盘/T2.1 的模式挖掘输入）；
- 回放确定性：rehearsal 判定所需的输入（seed 前缀+拓扑+params）全部落盘，判定可复算（T0.7 replay-equivalence 同款）。

## 3. 数据模型

### 3.1 `MetaPath`（资产本体）

```ts type-equiv
/** 推理拓扑骨架。非语言内容（J2）：节点=推理动作类型，边=控制流。 */
type ReasoningStepKind = 'observe' | 'hypothesize' | 'decompose' | 'analogize' | 'verify' | 'refute' | 'synthesize'

interface MetaPath {
  readonly id: MetaPathId                    // branded，mp-<n>
  readonly topology: {
    readonly nodes: { id: string; kind: ReasoningStepKind; label?: string }[]   // label≤24 字符类型助记标签（禁自然语言正文）
    readonly edges: { from: string; to: string; kind: 'seq' | 'cond' | 'loop' }[]
    readonly entry: string
    readonly exits: string[]
  }
  readonly mode: 'convergent' | 'divergent'                      // J3
  readonly applicability: {                                        // 适用条件（分类键，非原文）
    readonly taskClasses: string[]
    readonly stages: TaskNode['stage'][]
    readonly problemFeatures: string[]
  }
  readonly stats: {
    readonly rehearsalPass: number
    readonly rehearsalFail: number
    readonly consecutiveRehearsalFail: number
    readonly realUse: number
  }
  readonly source: {
    readonly kind: 'trajectory-extract' | 'coach-author' | 'human'
    readonly refs: { sessionId: SessionId; seqFrom: number; seqTo: number }[]   // 来源轨迹（T0.7 audit_index 同模式）
  }
  readonly version: number                   // §3.6 统一元数据
  readonly supersedes?: MetaPathId           // 版本替代链（同 T0.3 supersede 精神）
  readonly createdAt: number
  readonly updatedAt: number
}
```

### 3.2 `RehearsalRun`（验证史，append-only）

```ts type-equiv
/** 一次 rehearsal 试跑记录。判定输入全落盘=可复算。 */
interface RehearsalRun {
  readonly id: RehearsalId                   // reh-<n>
  readonly metaPathId: MetaPathId
  readonly taskId: TaskId
  readonly childSessionId: SessionId         // T0.7 fork 子会话
  readonly boundary: { sessionId: SessionId; eventKind: string; seq: number }   // 显式 fork 边界（禁开放轮次）
  readonly verdict: 'pass' | 'fail'
  readonly coverage: number                  // stepCoverage（拓扑步骤在子会话 transition 链的覆盖率）
  readonly outcome: 'success' | 'failure'    // 子任务终态
  readonly at: number
}
```

### 3.3 SQLite schema（`ctx.storage` sqlite domain，DomainSpec）

| 表 | 键 | 值 | 说明 |
|---|---|---|---|
| `meta_paths` | MetaPathId | MetaPath 全量 | 资产本体；append-only 语义（supersede 不改旧版，同 T0.3） |
| `rehearsal_runs` | RehearsalId | RehearsalRun | append-only 验证史 |

- domain version=1；**两表均 `invalidRecords:'backup-and-skip'`**——元路径可经轨迹+治理日志重建（认知资产非权威，同 T1.3 J7）；
- **lifecycle/退役不在本 domain**：治理状态单一权威在 `ctx.governance`（J1，assetKind='meta-thinking'）。

## 4. 不变量与服务 API

### 4.1 不变量（加载即校验/运行时强制）

1. **拓扑无环**：entry 可达全部 exits，edges 无环（loop 边仅允许回到标 `cond`  guard 的祖先，禁无护栏回边）；
2. **非语言内容**：MetaPath 字段白名单断言——`label`≤24 字符且不含句号/换行（自然语言启发式），其余字段全为类型标签/分类键/数字/引用（grep 自检：库内无构造注入的原文句）；
3. **未验证零注入**：`injectCandidates` 只返回治理态 consolidated 的元路径（draft/validating/retired 一律过滤，服务端断言）；
4. **rehearsal 判定确定性**：同 fork seed + 同拓扑 + 同 params ⇒ 同 verdict（承 T0.7 J6 seed 不变量）；
5. **连续失败自动退役**：`consecutiveRehearsalFail≥N`（P0 默认 3）触发自动 retire(kind='rehearsal-fail') 且 pass 不清零历史（fail 清零连续计数）；
6. **治理单一**：本服务无 lifecycle 字段、无 retire 本地实现——一切状态迁移经 `ctx.governance` 动作；
7. **注入即结构提示**：注入文本=拓扑序列化（类型标签序列），token≤K（P0 默认 120），grep 自检无自然语言句；
8. **版本链完整**：supersede 产新版，旧版保留可查（`history()` 同 T0.3 精神）。

### 4.2 `ctx.metaThinking` 服务方法

```ts type-equiv
interface MetaThinkingService {
  propose(draft: MetaPathDraft): MetaPath                       // 候选入 draft（coach/人）
  extractFromTrajectory(refs: TrajectoryRef[]): MetaPathDraft   // 辅路：transition 链→shape 参考（J4）
  rehearse(metaPathId: MetaPathId, taskId: TaskId): RehearsalRun        // fork+试跑+判定（J5）
  requestConsolidate(metaPathId: MetaPathId): GovAction         // rehearsal 通过→提请治理固化（经 ctx.governance，J6）
  injectCandidates(session: Session, round: number): MetaPath[] // consolidated only（J7，T0.4 注入池同池竞争）
  paths(filter?: { mode?; stage?; taskClass?; lifecycle? }): MetaPath[]
  supersede(oldId: MetaPathId, draft: MetaPathDraft): MetaPath  // 版本替代（经治理 retire[superseded]）
  history(id: MetaPathId): readonly MetaPath[]                  // supersede 链
}

interface MetaPathDraft = Omit<MetaPath, 'id' | 'stats' | 'version' | 'createdAt' | 'updatedAt'>
```

- `rehearse` 内部序：读拓扑（validating/draft）→ 选任务（taskId 必填、applicability 匹配或人工指定）→ `ctx.sessions.fork(source=该任务会话, boundary=任务边界)` → 子会话注入结构提示执行 → 从子会话 log 抽 transition 链（T1.3 extract 同款确定性）→ 算 coverage+outcome → verdict → 落 rehearsal_runs → 更新 stats → 达阈值动作（consolidate 提请/自动退役，J6/J8）；
- `injectCandidates` 与 T1.1/T1.3 候选同池进 T0.4 injection 区（预算统一裁决）；
- 治理动作（consolidate/retire/restore）全部委托 `ctx.governance`（不变量 6）。

## 6. 验收标准（对 Gate G1 的贡献项）

1. **拓扑 schema 落地**：构造候选（decompose→hypothesize→verify→refute DAG，mode=divergent）→ propose → rehearse（fork 子会话执行）→ coverage≥θ ∧ success → requestConsolidate → 治理 consolidated → 注入池可见；
2. **回放验证才缓存**：draft/validating 候选 `injectCandidates` 零返回（不变量 3 自检）；rehearsal fail 的候选同样零返回；
3. **失败降权与自动退役**：连续 3 次 rehearsal fail → 自动 retire(rehearsal-fail) 且 gov_actions 留痕；中途一次 pass 清零连续计数；
4. **双路径路由**：planning stage 查询返回 divergent 优先、verifying 返回 convergent 优先（applicability+mode 过滤自检）；
5. **非语言自检**：grep meta_paths 全表无构造注入的自然语言原句（白名单断言+label 启发式）；
6. **结构提示注入**：注入文本为节点类型标签序列（如 `decompose → hypothesize → (verify | refute)`），≤120 token；
7. **fork 合规**：rehearsal 用显式 boundary，开放轮次内边界被拒（T0.7 J6 拒绝用例）；子会话 seed 不变量 4 条全过；
8. **治理一致性**：元路径的 consolidate/retire 在 gov_actions 可查，与 memory 资产同管道同判据（T1.2 不变量 8 的重放扩展到 meta-thinking 分区）。
