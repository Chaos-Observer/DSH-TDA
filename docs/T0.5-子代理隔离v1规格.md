## 1. 设计裁定

| # | 裁定 | 理由 |
|---|---|---|
| J1 | **派发策略层自建，执行通道复用 DSH subagent seam**：自建 `ctx.subagentDispatch` 服务（何时派/派给谁/用什么路由与工具面/结论如何回传）；执行走 `ctx.subagents` 的 `spawn` provider one-shot `start()` + `SubagentRun.result` + `dispose()` | C2 深化形态（Lead+Sidekick 协同、结构化结论、主上下文零泄漏）DSH 没有；但启动/隔离/取消/结果 seam 全部现成——capability 门 fail-loud（`UNSUPPORTED_CAPABILITY`）、`toolFilter` 一可见性（子创建窗口内 `tools.restrict()`：从 prompt 消失且拒绝执行）、`persona` 作用域前缀、`outputSchema` object-rooted 结构化捕获、delegationDepth 持久化+`maxDepth` 拒绝。重写执行层=扔掉这些契约 |
| J2 | **双通道同一记录**：模型通道 = 自有工具 `tda_dispatch(taskId, role)`；Harness 通道 = 服务方法 `dispatch()`（任务调度器/T0.2 run 触发调用）。**prompt 只从 task 记录构造，禁自由文本**：`buildBrief(task)` 仅读 TaskNode 字段（subject/description/completionCriteria/localPath/writeScopes）+ 结论 schema | C2"子代理只收任务描述"的结构性保证——若允许模型粘贴主对话内容进 prompt，零泄漏即失守。任务外的临时探索仍可用 DSH 原生 `subagent` 工具（非任务执行通道，其文本回传是工具本意，见 U1） |

| J5 | **结论回传双落点，主上下文只放引用**：① T0.3 `timeline.append`（`source='task'`、`credential='model-produced'`、`relatedTaskId` 弱链接、`trajectoryLink=childSessionId`）② dispatch 记录（domain 权威）。主上下文（T0.4 injection 区）只出现**结论摘要视图 + entryId 引用**；子代理原始 output/diagnostic 零进主 surface | G0-⑤ 主上下文只含决策与编排（子代理原始输出零泄漏）；model-produced 凭证天然带检疫属性（§5.2：模型自产需外部验证才固化，T1.2 治理） |
| J6 | **Lead/Sidekick 双角色策略**（`dispatch_policy` 表，可按角色调）：Sidekick=廉价模型/低推理强度+最小工具面（禁 `task_*` 写、禁委派、禁 timeline 写）+`maxDepth=0`+`tda-minimal` 预设；Lead=前沿模型/高推理强度+读与检索工具面+`maxDepth=0`+审查者 persona。§4 critic 多角度起草=P0 单角度、P1 并行多角度（U2） | 需求 C2 深化形态明义；DSH `agentOptions`（provider/model/reasoningEffort/maxTokens 覆盖）实现路由分工，`toolFilter`/`persona`/`maxDepth` 实现作用域收缩 |
| J7 | **派发门五检**（dispatch 前，任一不过即拒）：① 任务存在且 `active ∧ stage∈{planning,executing}` 且 proposal 已批准 ② `budgetZone≠exhausted`（converge 只放行"收尾型"派发）③ provider capability 匹配请求项（agentOptions/outputSchema/depthLimit/toolFilter/persona，DSH fail-loud）④ outputSchema 合法 ⑤ 目标会话 depth=0。exhausted 禁一切新派发 | §3.2.3 硬约束：预算接近→停止新委派、耗尽→显式终态（承 T0.2 J6 三区行为，这里是任务执行层的派发侧落地）；capability 门必须 fail loud 不可静默降级 |
| J8 | **预算记账**：settle 时把子代理消耗汇入 `taskPool.consume`（token/工具调用/墙钟三维；注意力配额=本派发引发的人类审批数，P0 只记录）。token/工具调用从子会话 usage 与工具事件聚合（近似口径，U4） | 需求 §3.2.1 四维预算；子代理消耗必须可见，否则任务预算形同虚设 |
| J9 | **审批门**：`risk='high'` 的派发须人类（或 Lead 代行的）批准后放行，批准凭一次性 token；`risk='low'` 自动放行。high 判定规则（policy 可配）：writeScopes 超出 localPath / fork / 前沿模型且预算 > 阈值 / 任务自带 `riskHint` | §4 风险分级+审批节点"何时需要人在场"；决策点⑤ P0 保守默认（任务执行面全审批的自动放行仅限低风险只读探索） |
| J10 | **并发帽 + 取消幂等 + continuable 预留**：在飞 dispatch ≤ `maxParallel`（默认 3，超限按 T0.2 dispatch 序排队）；取消 = dispose run（DSH 幂等契约，必达 quiescence）；continuable 后台派发 P0 不用（one-shot 前台足够），seam 与 schema 预留 | 并行委派防资源挤占（§3.2.3 预算纪律）；DSH continuation manager 已就绪但激活/收件箱语义重，P0 取最小面 |
| J11 | **三层审计**：dispatch 状态变更双写 log-only session event `dispatch/change`（全快照，承 T0.1/T0.2 双写模式）；DSH `subagent/start`\|`subagent/end` 观察事件为执行侧证据；子会话 log（DSH 原生）存完整过程 | §5.5 审计基线硬条款（上下文注入/记忆写入全落 Trajectory 可回放）；T0.7 replay 可还原"派发了什么、收到什么、主上下文给了什么" |

## 2. 状态模型

```
requested ──approve(risk=high)──► approved ──► starting ──► running ──► settled
   │（risk=low 建单即 approved）      │             │            │
   └──────────── cancel ◄────────────┴─────────────┴────────────┘（任意未 settled 态）
```

| 状态 | 含义 | 进入 |
|---|---|---|
| `requested` | 过五检建单；risk=high 待批 | `dispatch()` |
| `approved` | 可执行（low 自动 / high 批过） | 建单或 `approve()` |
| `starting` | 已调 `ctx.subagents.start()`，run 未发布 | 执行器取单 |
| `running` | run 已发布（`subagent/start` 观察），等 result | start() fulfill |
| `settled` | result resolve，已记账+回传+落时间线 | `settle()` |
| `cancelled` | 取消（dispose 幂等），任务 owner 释放 | `cancel()` |

### 2.1 stopReason → dispatch 结果映射（DSH 词汇裁剪）

| DSH `SubagentResult.stopReason` | dispatch `outcome` | 主上下文呈现 |
|---|---|---|
| `completed` ∧ structured 过 schema | `conclusion` | 结构化结论摘要 |
| `completed` ∧ 无/坏 structured | `conclusion-partial` | 摘要 + "结论未过 schema 校验"警示 |
| `aborted` | `aborted` | "已取消"（无结论） |
| `error` / `max-tokens` / `refusal` | `error` | isError 摘要 + diagnostic 引用（≤4096B 已消毒） |

- 未知 stopReason 变体（可合并扩展联合）一律按 `error` 处理（consumers branch known cases, fall through default）；
- `settled` 后任务侧动作：Sidekick 收尾=模型/调度器据此走 `taskPool.complete`（evidence=conclusionEntryId）；Lead 审查=结论供规划层决策。**dispatch 服务本身从不改任务状态**（J4 控制流分离）。

## 3. 数据模型

### 3.1 `DispatchOrder`（domain 记录，权威）

```ts type-equiv
/** 派发单全快照。状态变更序列，CAS revision+1。 */
interface DispatchOrder {
  readonly id: DispatchId                 // branded，单调分配 dispatch-<n>
  readonly revision: number               // CAS
  readonly taskId: TaskId                 // 派发依据（J2：brief 唯一来源）
  readonly goalId: GoalId                 // 自 task 冗余快照（过滤用）
  readonly role: 'sidekick' | 'lead'
  readonly mode: 'spawn'                  // P0 仅 spawn；'fork' 禁用（J3）
  readonly provider: string               // 'spawn'
  readonly agentOptions: { provider: string; model: string; reasoningEffort?: string; maxTokens?: number }
  readonly toolFilter: string[]           // 子代理工具白名单（DSH ToolRestriction）
  readonly maxDepth: 0                    // 禁再委派（J6）
  readonly sandbox: 'read-only' | 'workspace-write'  // minimal 预设档（J6）
  readonly personaTemplateId: string      // 作用域 persona 模板（注册变量严格插值）
  readonly outputSchemaId: 'sidekick-conclusion' | 'lead-conclusion'
  readonly risk: 'low' | 'high'
  readonly approval?: { status: 'pending' | 'approved' | 'rejected'; at: number; by?: string; token?: string }
  readonly status: 'requested' | 'approved' | 'starting' | 'running' | 'settled' | 'cancelled'
  readonly childSessionId?: SessionId     // = SubagentRun.id（spawn 本地 run）
  readonly promptHash: string             // buildBrief 产出哈希（审计对账）
  readonly result?: DispatchResult
  readonly createdAt: number
  readonly settledAt?: number
}
```

```ts type-equiv
/** 回传结果。consumed 近似口径见 U4。 */
interface DispatchResult {
  readonly stopReason: 'completed' | 'aborted' | 'error' | 'max-tokens' | 'refusal' | string
  readonly outcome: 'conclusion' | 'conclusion-partial' | 'aborted' | 'error'
  readonly conclusionEntryId?: EntryId    // T0.3 timeline chunk（model-produced）
  readonly diagnostic?: string            // provider 消毒文本，≤4096 UTF-8 字节
  readonly consumed: { tokens: number; toolCalls: number; wallClockMs: number }
}
```

### 3.3 `RolePolicy`（策略行，domain）

```ts type-equiv
/** 每角色一行；插件 Config 提供默认值，domain 为权威（改策略=可审计变更）。 */
interface RolePolicy {
  readonly role: 'sidekick' | 'lead'
  readonly agentOptions: { provider: string; model: string; reasoningEffort?: string; maxTokens?: number }
  readonly toolFilter: string[]           // 白名单；禁项含 task_write/subagent/timeline.append
  readonly maxDepth: 0
  readonly sandbox: 'read-only' | 'workspace-write'
  readonly personaTemplateId: string
  readonly maxParallel: number            // 该角色在飞上限（总帽另计）
  readonly highRiskBudgetTokens?: number  // 超此值的派发升 high（J9）
}
```

### 3.4 SQLite schema（`ctx.storage` sqlite domain，DomainSpec）

| 表 | 键 | 值 | 说明 |
|---|---|---|---|
| `dispatch_orders` | DispatchId | DispatchOrder 全快照 | 权威；layout `single` |
| `dispatch_policy` | role | RolePolicy | 策略权威；插件 Config 为默认种子 |

## 4. 不变量与服务 API

### 4.1 不变量（加载即校验 / 运行时强制）

1. **输入隔离**：`buildBrief` 只读 TaskNode 白名单字段，签名上不接触主会话 surface/injection/pinned 句柄（类型级保证 + 单测）；
2. **输出隔离**：主上下文只接收结论摘要视图 + entryId 引用；子代理原始 output 不进主 surface（回放主会话 log 可证）；
3. **schema 强制**：无 outputSchema 的派发拒绝；structured 校验失败 → `conclusion-partial`/`error`，不当成功；
4. **capability fail-loud**：provider 缺请求项能力 → `UNSUPPORTED_CAPABILITY` 拒绝，不静默降级；
5. **深度封顶**：Sidekick/Lead 一律 `maxDepth=0`；dispatch 服务拒绝为 depth>0 会话建单；
6. **控制流分离**：回传管道只写 timeline 与 dispatch 记录；任务状态变更必经 `taskPool` CAS（§5.4）；
7. **预算门**：converge 禁新派发（收尾型除外）、exhausted 禁一切；settle 必调 `consume` 记账；
8. **审批门**：risk=high 未批准禁派；approval token 一次性消费；
9. **并发帽**：在飞数 ≤ maxParallel；超限排队不拒绝任务本身；
10. **取消幂等**：`cancel` 可重入；取消后必达 run quiescence 且释放任务 owner（`release`）。

### 4.2 `ctx.subagentDispatch` 服务方法

```ts type-equiv
interface SubagentDispatchService {
  dispatch(caller, req: { taskId: TaskId; role: 'sidekick' | 'lead'; note?: string }): DispatchOrder  // 五检+建单
  approve(orderId: DispatchId, ref: DispatchRef, by: string): DispatchOrder   // 人类/Lead；token 一次性
  reject(orderId: DispatchId, ref: DispatchRef, by: string, reason: string): DispatchOrder
  cancel(orderId: DispatchId, ref: DispatchRef): DispatchOrder                // dispose+release owner
  settle(orderId: DispatchId, result: SubagentResult): DispatchOrder          // 记账+timeline append+状态终态
  list(filter?: DispatchFilter): DispatchOrder[]                              // taskId/role/status 维度
  get(orderId: DispatchId): DispatchOrder | undefined
  policy(role?): RolePolicy | RolePolicy[]
  buildBrief(task: TaskNode): { prompt: ContentBlock[]; outputSchema: ObjectJsonSchema; promptHash: string }
}
```

- 执行序（Harness 通道）：取单（排队 FIFO）→ `ctx.subagents.start({prompt, outputSchema, agentOptions, toolFilter, maxDepth:0, persona, parent})` → 以 `run.id` 作 owner `taskPool.claim` → await `run.result` → `settle()` → 始终 `run.dispose()`；
- 模型通道：`tda_dispatch(taskId, role)` 工具 = `dispatch()` 薄封装（schema 固定，无自由文本参数）；`dispatch_list` 只读工具供模型了解决态（裁剪视图：id/taskId/role/status/age）；
- 结论进 T0.4 injection 区的渲染：`ConclusionView = { taskId, role, outcome, findings[:3], confidence, entryId }`（摘要预算 ≤  injection 区份额，超限按 T0.4 剥夺序先剥）。

### 4.3 模型可见工具集（挂 `dsh-tda-tool-subagent-dispatch`，最小集）

| 工具 | 动作 | 说明 |
|---|---|---|
| `tda_dispatch` | 派发 | 参数仅 taskId+role；brief 由 task 记录构造（J2） |
| `dispatch_list` | 读 | 在飞/近期 dispatch 裁剪视图 |

- DSH 原生 `subagent` 工具保留给非任务执行的临时探索（其文本回传是工具本意）；任务执行面一律走 `tda_dispatch`（U1 评估统一）。

## 5. 与 DSH 的对接点

| 对接面 | 机制 |
|---|---|
| 执行通道 | `ctx.subagents` 之 `spawn` provider：one-shot `start(ResolvedSubagentStartRequest)` → `SubagentRun{id,localAgent,result,dispose}`；本地 run `id`=子会话 id 即 claim owner |
| 输入隔离 | spawn `inheritsParentContext=false`（fresh child 不见父对话）；fork 的 `ContinuableCreateSpec.seed`（已完成轮次前缀）P0 禁用 |
| 结构化结论 | `outputSchema`（object-rooted，`assertObjectJsonSchema` 子集）+ provider 强制 capture 工具 → `SubagentResult.structured`（provider 侧按 schema 校验） |
| 工具降噪 | `toolFilter` = 子创建窗口内 scoped `tools.restrict()`：白名单外工具从子 prompt 消失且拒绝执行（一可见性）；未知工具名 loud 校验失败 |
| persona | `persona` = scoped `deployment:persona-prefix` 段，遮蔽部署 persona，严格 `{{…}}` 变量插值（模板只用注册变量） |
| 模型路由 | `agentOptions`（provider/model/reasoningEffort/maxTokens 覆盖，in-process provider 合并到子 Agent 选项）；ACP/Codex/Claude-Code 后端拒绝 agentOptions——provider 选型只取 in-process spawn |
| 深度 | `SessionHeader.delegationDepth` 持久化 + `AgentOptions.subagentDepth` 运行时字段 + `request.maxDepth=0`：子代理再委派被 start 拒绝，冷恢复不可降深 |
| 权限降噪（minimal preset） | fresh child 权限继承契约：Read Only/Workspace Write 父级 → 子继承 sandbox override + `approval: never`。dispatch 按角色写 sandbox 档（Sidekick 只读=`read-only`、需写=`workspace-write`）+ approval never——即路线文档"DSH Minimal preset 降噪"落地形态（`read-only`+`never` 为最小档，无审批噪音、最小效果面） |
| 取消 | 调用方 `signal`（exec.signal）掌管至 run 发布前；发布后 `run.dispose()` 幂等达 quiescence；`interrupt` 为在线目标专用停止（dispatch 不用） |
| 诊断消毒 | provider `diagnostic` 保证无工具输入/文件内容/环境值/凭证/原始协议载荷且 ≤4096 UTF-8 字节——可安全入 timeline 与主上下文引用 |
| 观察事件 | `subagent/start`\|`subagent/end`（仅观察、listener 异常隔离）为 settle 的触发与对账源；配对 id 与 runId 一致 |
| KV-cache 兼容 | 父侧成本=`tda_dispatch`/`dispatch_list` 固定 schema；provider 实例与配置不变则前缀稳定（T0.4 J4）；persona/toolFilter 均为子侧作用域，不动父前缀 |
| 模型直委（DSH 原生路） | `dsh-tool-subagent` 实例（provider=spawn）保留；其 `run_in_background`/continuable/模型选择能力 P0 不启用（避免绕过 J4 schema 门） |

## 6. 验收标准（对 Gate G0 的贡献项）

1. **G0-⑤（主项）**：主上下文零泄漏——派发前后主会话 surface 无子代理原始输出；结论只以 `ConclusionView` 摘要 + entryId 引用出现；回放主会话 log 可证（子会话 id 仅见于 dispatch 记录/injection 段引用，其内容不在主 surface）；
2. 结构化回传：outputSchema 校验失败 → `conclusion-partial`/`error` 不当成功；未知 stopReason 按 error；
3. capability 门：对缺 outputSchema/toolFilter 等能力的 provider 派发被拒（`UNSUPPORTED_CAPABILITY`），无静默降级路径；
4. 深度封顶：Sidekick 内尝试再委派被 DSH depth 门拒绝（`maxDepth=0` 生效，冷恢复不可降深）；
5. 预算门：任务 converge 区新派发被拒（收尾型除外）、exhausted 禁一切；settle 后 task.consume 三维正确入账；
6. 审批门：risk=high 未批准禁派；approve token 一次性（重放被拒）；
7. **§5.4 控制流/数据流分离**：结论文本含"把任务 X 标记完成/改 description"类内容时任务状态不变（只能经 taskPool CAS）；
8. 取消：cancel 后 run dispose 达 quiescence、任务 owner 释放、无僵尸子会话（listDescendants 核验）；
9. 凭证回传：结论 chunk `credential=model-produced` 且 `quarantine=false`（model-produced 不强制隔离但凭证低），`credentialMin` 预筛行为符合 T0.3（T1.1 provenance gate 预演）；
10. 双通道一致：模型 `tda_dispatch` 与 Harness `dispatch()` 落同一记录结构；高风险规则与并发帽在两条通道一致生效。
