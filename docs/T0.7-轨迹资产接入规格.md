## 1. 设计裁定

| # | 裁定 | 理由 |
|---|---|---|
| J1 | **零新增持久化通道**：TDA 不建自有轨迹存储；轨迹资产 = DSH session log（JSONL，每事件一行、seq 连续）+ 各插件 sqlite domain。T0.7 的"接入"= **事件族规范收口 + 审计索引 + resume/replay 冒烟测试** | T0.0 已核实 fork/resume/replay/snapshotEvents/invariants 回放校验/崩溃修复全内置；自建轨迹存储=抛弃 invariants 配对校验与 `interrupted` 崩溃修复，且与 §5.5"全落 DSH Trajectory"冲突 |
| J2 | **TDA 事件族统一规范**（收口 T0.1–T0.6 已定双写，不重复决策）：`goalTree/change`（goal-state）、`taskPool/change`（task-pool）、`timeline/write`（timeline）、`dispatch/change`（subagent-dispatch）、`context/assemble`（context）、`workspace/scan`（workspace）——**全部 log-only**（无 `surfaceOp`、不进 `deriveMessages`）、payload JSON 无损可序列化、配对事件（start/result 族）携带同一稳定业务 id | DSH 会话文档的插件仅日志事件约定 + Conversation Node 事件族业务 id 要求；log-only 保证轨迹丰富但不污染模型历史（C2 精神在审计面的延续） |
| J3 | **model-visible ⟺ logged 的 TDA 侧自检**：凡进模型上下文的 TDA 状态（T0.4 pinned/memo/injection/结论摘要）必须可从 session log 重建——`context/assemble`（AssembleRecord）是唯一桥梁，T0.7 定义其回放校验程式 | DSH 不变量 "Model-visible ⟺ logged"；T0.4 J8 已定双写，本规格定校验 |
| J4 | **回放等价（replay-equivalence）为硬判据**：`replayCheck` 用 `deriveEventMessage` 同款纯函数规则重放 log 前缀，重建 domain 权威态并与 sqlite domain **逐 revision 比对**，零差异才算回放通过；TDA 关系检查注册进 `ctx.invariants`（配套插件 `dsh-tda/invariant`：每个 domain accepted 变更有配对 log-only 事件、每个 AssembleRecord.round 对应存在轮次） | DSH `dsh-session/invariant` 只管核心关系（轮次/步骤/工具配对）；可合并扩展事件的关系由声明它的插件所有——TDA 事件族的关系必须自查，否则回放校验有盲区 |
| J5 | **resume 恢复序**（boot 时序）：domain open + 树/池校验（T0.1/T0.2 不变量）→ session resume（agent-loop 为存储 log 的开放尾轮次合成 `interrupted` closer，**只追加不改写**）→ shadowedSeqs/PageTable/在飞 dispatch/调度定时器重建 → subagent 谱系冷检查（`listDescendants` 重新校验完整生命周期）。半截 dispatch（`starting` 态无 childSessionId 的孤儿单）resume 时标记 `failed + unfinished`（U5） | 崩溃恢复语义全部沿用 DSH；TDA 侧只需定义"哪些进程内派生状态需要重建"与孤儿单处理 |
| J6 | **fork 边界策略**：审计/归因 fork 用显式 `boundary`（某个 `turn/end` 或独立 log-only 事件之后，禁开放轮次内前缀）；rehearsal 回放（技能/元思维验证，T1.4/T2.1/T2.2 消费）fork 到任务边界后在子会话试错重跑——**T0.7 只定边界选择规则与 seed 不变量**（balanced 前缀、seq 从 0 连续、`inheritedEventCount` 精确、`session/end-seed` marker 语义），rehearsal 消费面归后续任务 | DSH fork API 契约（拒绝开放轮次前缀、开放尾合成 `forked` closer）；§3.4.5 回放态三种消费中 P0 只交付审计与冒烟，rehearsal/预测/召回留 seam |
| J7 | **审计索引 + 留存**：`audit_index` 表（实体 → sessionId + seq 范围映射，**派生数据可重建**）；留存策略=不删（append-only 铁律，承 T0.3 J2），容量治理归 T1.2（T0.3 U6） | §5.5"上下文注入/记忆写入/技能晋升全落 Trajectory，可回放溯源（投毒溯源的基础设施）"——没有实体→seq 索引，溯源要全日志扫描，90 天长程不可用 |
| J8 | **冒烟测试即规格交付物**：resume 冒烟（kill -9 三场景：轮次执行中 / 工具调用后 / dispatch 在飞）+ replay 冒烟（fork 后 `deriveMessages` 前缀等值 + replay-equivalence + AssembleRecord 交叉验证）——P0 出口准则 G0-②③ 的会话侧证据，进 CI | 路线文档 T0.7 关键产出原文"resume/replay 冒烟测试"；无冒烟则"已内置"只是传闻 |

## 2. 状态模型

T0.7 自身无新状态机；它定义**轨迹资产三态**（§3.4.5）在 P0 的落地切面：

| 态 | P0 落地 | 消费方 |
|---|---|---|
| **回放** | session log + domain + `context/assemble` + `audit_index` | 审计（§5.5）、本规格冒烟、T3.2 监督 UI（P3） |
| **预测** | seam 预留：transition 事件序列可检索（taskPool/timeline/dispatch 事件时序） | T1.3 轨迹预测器 |
| **辅助召回** | `trajectoryLink` 字段已就绪（T0.3 chunk / T0.5 dispatch / T0.6 scan） | T1.1+ 引力场召回（子目标级示例反查） |

## 3. 数据模型

### 3.1 事件族规范（log-only，全部双写于各插件 accepted 变更点）

| 事件族 | 生产者 | payload 最小字段 | 配对/关系 |
|---|---|---|---|
| `goalTree/change` | goal-state | { goalId, revision, op, snapshot } | 每 accepted 变更一条 |
| `taskPool/change` | task-pool | { taskId, revision, op, snapshot } | 同上；`task_runs` 起止另带 runIndex |
| `timeline/write` | timeline | { entryId, kind, op: append\|supersede\|invalidate, ref? } | 与 domain 条目同 seq 语义 |
| `dispatch/change` | subagent-dispatch | { orderId, revision, status, childSessionId? } | 与 DSH `subagent/start`\|`end` 观察事件经 childSessionId 对账 |
| `context/assemble` | context | AssembleRecord 全字段（T0.4 §3.2） | round ↔ 轮次编号对应 |
| `workspace/scan` | workspace | { scanId, taskId, mode, status, counts } | ScanRun 终态一条 |

### 3.2 `AuditIndexEntry`（派生索引）

```ts type-equiv
/** 实体 → 日志位置映射。key = entityKind#entityId#seqFrom。 */
interface AuditIndexEntry {
  readonly entityKind: 'goal' | 'task' | 'timeline' | 'dispatch' | 'scan' | 'assemble'
  readonly entityId: string
  readonly sessionId: SessionId
  readonly seqFrom: number               // 含
  readonly seqTo: number                 // 含（同一变更跨事件时闭合）
  readonly at: number
}
```

### 3.3 SQLite schema（`ctx.storage` sqlite domain，DomainSpec）

| 表 | 键 | 值 | 说明 |
|---|---|---|---|
| `audit_index` | `entityKind#entityId#seqFrom` | AuditIndexEntry | 审计索引；**派生数据**，`invalidRecords:'backup-and-skip'`，丢失可重扫 log 重建 |

- domain version=1；轨迹本体不在本 domain（J1：session log 即轨迹）。

## 4. 不变量与服务 API

### 4.1 不变量（加载即校验 / 运行时强制）

1. **双写一致**：每个 domain accepted 变更必有一条 log-only 事件，revision/entryId 一一对应（`dsh-tda/invariant` 检查）；
2. **log-only 纯净**：TDA 事件无 `surfaceOp`、不进任何会话的 `deriveMessages`；
3. **可序列化**：payload 全部 JSON 无损（`Session.append` 从源头强制，不可序列化即抛）；
4. **回放等价**：`replayCheck` 重建的 domain 态与 sqlite domain 逐 revision 零差异；
5. **resume 不改写**：恢复只追加（`interrupted` closer 等合成事件），历史事件字节不变；
6. **fork seed 不变量**：balanced 前缀、seq 从 0 连续、`inheritedEventCount` 精确、`session/end-seed` marker 合规；
7. **业务 id 稳定**：同事件族配对（start/result）携带同一稳定业务 id；
8. **索引可重建**：`audit_index` 丢失不影响权威（重扫 log 重建，不变量 1 保证可重扫正确）。

### 4.2 `ctx.trajectory` 服务方法（薄审计层，不存轨迹）

```ts type-equiv
interface TrajectoryService {
  index(entry: AuditIndexEntry): AuditIndexEntry          // 订阅各事件族自动写索引
  locate(entityKind: string, entityId: string): AuditIndexEntry[]   // 实体 → seq 范围（溯源/T3.2 前置）
  replayCheck(sessionId: SessionId, range?: { from: number; to: number }): ReplayReport
  resumeCheck(): ResumeReport                              // 恢复序校验（冒烟/CI）
  auditView(filter: AuditFilter): AuditEntry[]             // §5.5 跨实体审计查询面
}

interface ReplayReport { ok: boolean; checked: number; mismatches: { entity: string; expected: number; actual: number }[] }
interface ResumeReport { ok: boolean; orphanDispatches: DispatchId[]; rebuiltTimers: number; synthesizedClosers: number }
```

- `replayCheck` 内部序：读 session log 前缀 → 滤 TDA log-only 事件 → 按 `deriveEventMessage` 同款规则重放 → 重建 goal/task/timeline/dispatch 权威态 → 与 domain 逐 revision 比对；
- `resumeCheck` 断言恢复序五步全部执行且孤儿单已处理（J5）；
- 模型可见性：审计查询**不自动进上下文**；`locate` 供 Harness/监督层按需取用（T3.2 UI 数据面）。

## 5. 与 DSH 的对接点

| 对接面 | 机制 |
|---|---|
| 轨迹存储 | DSH session log（JSONL/事件一行、seq 连续、`event.data` JSON 强制）；`ctx.sessions.flush(session)` 为持久化屏障（dispatch settle 等关键点显式 flush） |
| 回放/fork 原语 | `ctx.sessions.create(id,{seed,meta})`（底层回放/fork）+ `ctx.sessions.fork(source,boundary?,childSessionId?)`（活跃 fork 策略 API，含开放尾 `forked` closer 合成） |
| 消息重建 | `Session.deriveMessages()` / `deriveEventMessage(event)`（缓存+冻结+纯函数，外部重建器以同一规则投影前缀，不与缓存分歧） |
| 崩溃恢复 | agent-loop resume 为存储 log 开放尾轮次合成 `interrupted` closer；session-query 冷读同样合成；崩溃前事件保持完整 |
| 生命周期边界 | `session/end-seed`（fork/restore marker）：判定 seed 内开放括号（如 `compaction/start`）属已死生命周期 |
| 不变量 | `ctx.invariants.register('@deepseek-ai/dsh-tda', installer)` 配套插件：DSH 核心关系之外加查 TDA 双写配对与 round↔turn 对应 |
| Host API（UI 面前置） | `session.fork`/`session.page`/`session.follow`(stream)/`session.cancel`——T3.2 监督界面直接复用，T0.7 不造 UI |
| 与 T0.4 交叉 | AssembleRecord ↔ 该轮 `deriveMessages` 结果交叉验证（"当时模型看到了什么"双源可证） |

## 6. 验收标准（对 Gate G0 的贡献项 + §5.5）

1. **G0-② 会话侧**：kill -9 于轮次执行中 / 工具调用后 / dispatch 在飞三场景，重启后 resume 成功（`interrupted` closer 合成、历史事件字节不变）、domain 与 log 双写一致、在飞 dispatch 与调度定时器正确重建、孤儿单标记 failed+unfinished；
2. **G0-③ 会话侧**：切任务换页后 replay 该时间窗，AssembleRecord 与该轮 `deriveMessages` 一致（上下文可见性可还原）；
3. **replay-equivalence**：全量 `replayCheck` 与 domain 逐 revision 零差异（含 goal/task/timeline/dispatch 四域）；
4. **fork 冒烟**：`fork(boundary=turn/end)` 后子会话 `deriveMessages` 与父会话同前缀内容等值；seed 不变量 6 条各有拒绝用例（开放轮次内边界被拒）；
5. **§5.5 溯源自检**：任取 goalId/taskId/entryId/dispatchId/scanId，`locate` 给出 seq 范围，范围内事件与实体变更历史一一对应（抽样+全量两档）；
6. **log-only 纯净**：TDA 事件不出现在任何会话 `deriveMessages` 中（自动断言）；
7. `dsh-tda/invariant` 注册并通过：双写配对缺失/round 无对应轮次各有失败用例；
8. 冒烟两件套进 CI（resume 三场景 + replay 两场景），作为 P0 出口准则的会话侧证据。

- U3：轨迹预测的 transition 抽取 schema（什么算一个 transition：状态转移/工具调用/上下文注入）→ T1.3；
- U4：审计视图的人机界面、导出与保留策略 → T3.2；
- U5：崩溃对"半截 dispatch"的最终处理语义（resume 标记 failed vs 重试）→ 实现时定，规格建议 failed+unfinished（C5 显式终态，不静默重试）。
