## 1. 设计裁定

| # | 裁定 | 理由 |
|---|---|---|
| J1 | **建统一治理服务 `ctx.governance`，P1 只实例化 memory 资产类型**：方法带 `assetKind` 参数（P1 仅 `'memory'`，其他返回 `UNSUPPORTED_ASSET` fail-loud），T2.2 技能生命周期作为同服务第二实例扩展，不新立服务 | §3.6 明文"所有资产共享一条统一治理管道，环境带入差异通过类型字段表达"；P1 只做记忆但 schema 必须预埋 kind 维度，否则 T2.2 又会造第二套管道（C4 败笔） |
| J2 | **治理是旁路层，权威永在 T0.3**：任何治理动作不改时间线条目；内容层更正只经 `supersede`/`invalidate`（T0.3 J2），资产层淘汰只记治理状态 | append-only 铁律 + 单事实原则；治理表=投影与动作日志，不是第二权威（同 T1.1 recall_log 旁路模式） |
| J3 | **写入检疫承 T0.3 已硬落地部分**（credential∈{tool-output,external-content} 服务端强制 quarantine，§5.2），T1.2 补三件 T0.3 未做的事：① 转正流（T0.3 U3 关闭）② 隔离区治理视图 ③ 重复脏信号检测标记 | 不重复写路径拦截（避免双闸双腐）；T0.3 J5 已判"检疫治理归 T1.2"，本节就是履约 |

| J5 | **固化 = 外部验证阀 ∧ 凭证双条件**（§5.2 硬条款）：① 外部验证=≥1 次真实任务成功复用（任务 `complete(success)` 且该 chunk 在该任务执行期被 `recall_log` 记 injected，证据链落 gov_actions）② credential≥`execution-verified` ③ ¬quarantine——三条全满足才 `consolidated` | §3.4.4"固化需外部验证：至少一次真实任务成功复用"+§5.2"外部验证阀+凭证等级双条件"；缺一不可，防模型自产记忆自我固化 |

| J7 | **退役触发四信号**（§3.6 降级/退役行）：`superseded`（被新版本取代，消费 T0.3 supersede 链）/ `unused-days`（recall_log 无 injected 超 N 天）/ `capacity`（活跃集超上限强制淘汰最低治理分）/ `manual`（人工/coach）；**"连续失败"P1 不自动判**——失败归因到单条记忆的证据强度不足，信号留 T2.2 技能退役统一（T2.2 依赖 T1.2 同款管道） | 四信号中三个可机读；"连续失败"若自动判=把弱归因当强证据，违背"宁缺毋滥"（承 T1.1 J6 纪律）；保守不动作好过错误退役 |
| J8 | **容量上限双维**（T0.3 U6 关闭）：活跃集（T0.3 `current()`）条目数 + 估算 token 双帽；80% 压力区→提议退役未用条目，100%→强制淘汰治理分最低者；治理分 = `reuseCount·w_reuse + credentialRank·w_cred + recencyScore·w_rec`（P0 权重 0.5/0.3/0.2） | §3.6"活跃容量上限强制淘汰"；90 天长程条目增长无帽=检索噪声稀释+context 注入质量劣化（T1.1 minScore 也救不了总量）；淘汰必须可解释（不变量 5） |
| J9 | **冲突只检测标记、不隐藏裁决**（T0.3 U4 关闭）：scan 发现同一目标存在分叉 supersede 链 → 建 `conflict` 记录（with 列表+证据回链）；**不改 T0.3 `current()` 的机械定义**（减去被 supersede/invalidate 的），收敛动作=再发一条 supersede/invalidate（经 PIPE 漏斗），由人工或 coach（T2.1）执行 | 治理层若自行裁决=隐藏写路径，破坏单漏斗（T0.3 J6）与可回放；§3.6"协调/同步=冲突检测、证据回链裁决、版本合并/回滚"中裁决是显式动作，检测归治理、执行归管道 |
| J10 | **数据分层**：`gov_actions`（append-only 动作日志）= 治理权威（含人工 retire/恢复/冲突裁决等不可推断记录）；`memory_gov_states` = gov_actions 的**投影缓存**（可重放重建）；`gov_scan_state` = 扫描水位+吞吐帽状态 | replay-equivalence 模式（T0.7 J4）：投影可重建、动作日志不可重建；崩溃后 replay gov_actions 重建 states，与 T0.7 `dsh-tda/invariant` 同一判据 |
| J11 | **吞吐帽与宿主**（§3.6"维护引擎=coach 周期性后台运行；维护本身设吞吐上限，不侵蚀主任务执行"）：scan 由 L1 Harness 常驻进程周期调度（T0.2 J8 daemon 宿主，DSH schedule session-local 不够——T0.0 缺口），单次 scan 治理动作数 ≤ cap（P0 默认 20）、扫描条目数 ≤ cap；coach 元进程本体归 T2.1，本规格只定义调度 seam 与帽 | §3.6 明文；P1 无 coach，常驻调度器直接驱动 scan（周期 P0 默认 6h，U5） |
| J12 | **高风险治理动作人类审批**：`invalidate` 提议与容量强制淘汰触发的 retire 走人类审批（一次性 token，同 T0.5 J9 机制）；低风险动作（validating 迁移、superseded/unused-days 退役提议）P0 自动执行+留痕 | 决策点⑤保守默认（承 T0.2 J9/T0.5 J9）：作废内容与强制淘汰影响面大，宁审勿错；纯信号型退役可逆（软态），自动无害 |

## 2. 状态模型

### 2.1 记忆治理生命周期（J6）

```
T0.3 append ──► draft ──promote──► validating ──consolidate──► consolidated
                 │                     │                          │
                 │                     │                          │
                 └──retire(superseded/unused-days/capacity/manual)──┴──► retired
                                                                        │
                                                                   restore(人工) ──► consolidated
任何态 ∧ 内容层 invalidate ──► 治理标记 archived（条目可溯，current() 已不含）
```

- `draft`：新写入 chunk 的默认治理态（**惰性建状态**——scan/治理动作首次命中才落 `memory_gov_states` 行，避免为全量时间线建镜像；扫描时无状态条目按 draft 规则处理）；
- `validating`：候选固化中（已满足凭证条件，待外部验证证据；或隔离条目转正出的新条目待验证）；
- `consolidated`：J5 三条件全过；
- `retired{archived?}`：软退役（不浮现经 T1.1 消费）；`archived=true` 表示内容层已被 invalidate（终局，保留可溯）；
- **状态迁移全部经 `gov_actions` append-only 落盘**，states 表只是投影（J10）。

### 2.2 scan 周期流程（J11）

```
due（常驻调度器，周期 6h 默认）
 → 取 gov_scan_state 水位 → 增量扫 T0.3 current() + recall_log + supersede/invalidate 链
 → 检测四信号（superseded / unused-days / near-duplicate / conflict 分叉）
 → 容量压力判定（J8 双维 80%/100%）
 → 生成治理提议（proposals）→ 按风险分级执行/送审（J12）
 → 动作逐条落 gov_actions（≤ cap）→ 更新水位
 → 产 GovScanReport（供监督仪表盘/T3.2）
```

## 3. 数据模型

### 3.1 `GovAction`（权威动作日志，append-only）

```ts type-equiv
/** 治理动作。一切状态迁移、提议、审批、裁决的唯一记录。 */
interface GovAction {
  readonly id: GovActionId                // branded，单调分配 gov-<n>
  readonly assetKind: 'memory'            // P1 唯一；T2.2 起扩展
  readonly assetId: EntryId               // 指向 T0.3 时间线条目（弱引用，无级联）
  readonly action: 'propose' | 'approve' | 'promote' | 'consolidate' | 'retire' | 'restore' | 'flag-conflict' | 'propose-invalidate'
  readonly from?: MemoryLifecycle
  readonly to?: MemoryLifecycle
  readonly reason?: { kind: GovRetireKind | 'verify-pass' | 'verify-fail' | 'dup' | 'conflict' | 'manual'; detail: string }
  readonly evidence?: VerifyEvidence      // J5 外部验证证据链
  readonly actor: WriterRef               // { sessionId, actor: 'agent'|'human'|'coach'|'scheduler', at }
  readonly approvalToken?: string         // J12：人类审批一次性 token 引用（只用不存全文）
  readonly at: number
}

type MemoryLifecycle = 'draft' | 'validating' | 'consolidated' | 'retired'
type GovRetireKind = 'superseded' | 'unused-days' | 'capacity' | 'conflict' | 'manual'

interface VerifyEvidence {
  readonly taskId: TaskId
  readonly runIndex: number
  readonly taskOutcome: 'success'         // 只认 success（J5）
  readonly injectedAt: number             // recall_log 中该 chunk 被注入的时刻（复用证据）
  readonly checkedAt: number
}
```

### 3.2 `MemoryGovState`（投影缓存，可重建）

```ts type-equiv
interface MemoryGovState {
  readonly assetKind: 'memory'
  readonly assetId: EntryId
  readonly lifecycle: MemoryLifecycle
  readonly archived: boolean              // 内容层已被 invalidate（终局标记）
  readonly retiredReason?: { kind: GovRetireKind; detail: string }
  readonly credential: TimelineEntry['credential']   // 镜像（治理查询/容量排名用）
  readonly verifiedBy: VerifyEvidence[]   // 外部验证记录（可多次，累加 verifyCount）
  readonly conflict?: { with: EntryId[]; detectedAt: number; resolution: 'pending' | 'merged' | 'human-ruled' }
  readonly dupOf?: EntryId                // near-duplicate 标记（U4：只标不并）
  readonly reuseCount: number             // 聚合自 recall_log（缓存，扫时刷新）
  readonly lastUsedAt?: number
  readonly updatedAt: number
}
```

### 3.3 SQLite schema（`ctx.storage` sqlite domain，DomainSpec）

| 表 | 键 | 值 | 说明 |
|---|---|---|---|
| `gov_actions` | GovActionId | GovAction 全量 | **治理权威**；append-only；layout `single` |
| `memory_gov_states` | `'memory'#EntryId` | MemoryGovState | 投影缓存（replay gov_actions 重建） |
| `gov_scan_state` | `'singleton'` | { lastScanAt, cursor, cycleMs, caps: { maxActions, maxScanned } } | 扫描水位+吞吐帽（J11） |

- domain version=1；**`invalidRecords` 分级**：`gov_actions` 拒绝打开（权威丢了不可推断）；`memory_gov_states`/`gov_scan_state` = `backup-and-skip`（投影，重放即重建——同 T0.7 replay-equivalence 判据）；
- 容量统计所需的 `reuseCount`/`credential` 从 T0.3/T1.1 只读聚合，**不复制内容**（J2）。

## 4. 不变量与服务 API

### 4.1 治理不变量（加载即校验/运行时强制）

1. **治理不动权威**：不存在任何改 T0.3 条目的代码路径；内容更正必经 `append`（supersede/invalidate）；
2. **固化三条件**：`consolidated` 必满足 externalVerify≥1 ∧ credential≥execution-verified ∧ ¬quarantine（服务端断言，缺一拒绝）；
3. **转正即新条目**：quarantine 解除必伴随一条 `supersedes→原条目` 的新 chunk（gov_actions 与 timeline 双写可对账）；
4. **退役可逆、作废终局**：retired→consolidated 恢复只能人工触发；archived（invalidate）后治理侧不再动作，条目保留可溯；
5. **容量淘汰可解释**：每次 capacity 退役必带治理分排名证据（当时候选集的 reuseCount/credential/recency 明细进 reason.detail）；
6. **动作全留痕**：每次状态迁移/提议/审批必落 gov_actions + 双写 log-only session event `memoryGov/change`（§5.5）；
7. **吞吐帽**：单次 scan 产出治理动作数 ≤ `caps.maxActions`、扫描条目数 ≤ `caps.maxScanned`，超限余量移交下次周期（不侵蚀主任务）；
8. **投影可重建**：replay gov_actions 必须逐一还原 memory_gov_states（T0.7 `dsh-tda/invariant` 扩展判据）。

### 4.2 `ctx.governance` 服务方法

```ts type-equiv
interface GovernanceService {
  scan(opts?: { limit?: number }): GovScanReport              // 周期入口（常驻调度器驱动，J11）
  promote(assetId: EntryId, evidence: VerifyEvidence): GovAction    // 转正/进 validating（J3/J4）
  consolidate(assetId: EntryId): GovAction                     // 固化（J5 三条件服务端断言）
  retire(assetId: EntryId, reason: { kind: GovRetireKind; detail: string }): GovAction
  restore(assetId: EntryId, actor: WriterRef): GovAction       // 人工恢复（J6，T3.2 入口）
  proposeInvalidate(assetId: EntryId, reason: string): GovAction     // 遗忘提议（J12 需人类审批）
  conflicts(): MemoryGovState[]                                // 待裁决冲突清单（J9）
  capacity(): CapacityReport                                   // 双维容量+压力区（J8）
  state(assetId: EntryId): MemoryGovState | undefined
}

interface GovScanReport {
  readonly scanned: number
  readonly proposals: GovAction[]
  readonly executed: GovAction[]
  readonly pendingApproval: GovAction[]
  readonly conflictsFound: number
  readonly capacity: CapacityReport
  readonly nextCursor: string
}

interface CapacityReport {
  readonly activeEntries: number
  readonly activeTokensEst: number
  readonly caps: { maxEntries: number; maxTokens: number }
  readonly zone: 'normal' | 'pressure' | 'over'                // <80% / 80–100% / >100%（J8）
}
```

- `promote` 内部序：校验证据（task complete(success) ∧ recall_log 有该条目 injected 记录）→ 若原条目 quarantine：经 T0.3 append 新 chunk（credential 按验证结果定，`supersedes→原条目`）→ 新条目建 validating 状态；否则原条目迁 validating；
- `consolidate` 内部序：读 state（validating）→ 断言 J5 三条件 → 迁 consolidated，evidence 入 verifiedBy；
- `scan` 的 superseded 检测：T0.3 `history()` 中出现更新的 supersede 链尾 ≠ 本条目 → 提议 retire(superseded)（自动执行，J12 低风险）。

## 6. 验收标准（对 Gate G1 的贡献项）

1. **G1-② 投毒闭环（主项）**：构造 `tool-output` 中毒 chunk → 服务端强制 quarantine（T0.3）→ scan 不转正、recall 不浮现（T1.1 gate）→ 模拟外部验证通过（任务 success + injected 记录）→ `promote` 出新条目（credential=execution-verified，supersedes 原条目）→ 新条目可按参数浮现，**原隔离条目仍在 `history()` 可溯**（J4 自检）；
2. **固化双条件**：model-produced chunk confidence=0.9 但零真实复用 → consolidate 拒绝；构造一次真实任务成功复用证据 → validating → consolidate 成功；credential<execution-verified 时即使有验证也拒绝（三条件逐一可证）；
3. **superseded 自动退役**：对 consolidated 条目发新版本 supersede → scan 检出 → retiredReason=superseded，治理动作留痕；
4. **unused-days 退役**：条目 recall_log 最后 injected 超阈值 → 提议退役（自动执行+留痕），退役后 T1.1 任何查询不浮现；
5. **容量强制淘汰**：活跃集超 100% → 按治理分淘汰最低者，动作带排名证据明细（J8/不变量 5 自检）；80% 压力区只提议不强制；
6. **冲突检测**：构造分叉双 supersede 同一目标 → conflict 记录含 with+证据链；`current()` 机械定义不变（两新条目均在，收敛留给显式动作）；
7. **审计回放**：任取治理动作可从 session log 对账（双写配对）；replay gov_actions 重建 states 与现库逐字段一致（不变量 8）；
8. **吞吐帽**：构造超量待治理条目，单次 scan 动作数≤cap、扫描数≤cap，余量在下次周期续办（不变量 7）。

## 7. 未决项

- U1：外部验证的证据口径边界——"任务 success 且 chunk 被 injected"是否充分（归因强度：注入≠贡献；更严口径=任务 evidence 显式引用该 chunk）→ 实现后与 T2.1 coach 归因一并标定；
- U2：容量双帽默认值（maxEntries/maxTokens）与治理分权重（0.5/0.3/0.2）、unused-days 阈值 N → 真实语料压测标定；
