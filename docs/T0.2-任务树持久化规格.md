## 1. 设计裁定

| # | 裁定 | 理由 |
|---|---|---|
| J1 | **模式复制 agent-team task DAG 而非依赖 `ctx.agentTeams`**：自建 `ctx.taskPool` sqlite domain，沿用其词汇（全快照事件 / CAS `expectedRevision` / `blockedBy` 无环 / `deleted` tombstone / advisory `writeScopes`） | ① agent-team 是 experimental 包、无稳定承诺（README 明示 contracts can change freely），T0.0 已建议复制而非等待；② task board 绑 `TeamId=SessionId`（单会话、单进程、单 checkout），与 C1 跨会话权威冲突——同 T0.1 J1 的模式复制原则；③ 模式本身简单（全快照+CAS），复制成本低 |
| J2 | **权威源 = ctx.storage sqlite domain**；每次 accepted 变更**双写** log-only session event（`taskPool/change`，全快照） | 同 T0.1 J2：C1 机读权威 + DSH 不变量 "Model-visible ⟺ logged"。任务状态若要进模型上下文必须可从 log 重建 |
| J3 | **任务沿用 T0.1 的 phase×stage 分离模型**（phase 四态 + stage 四子态），agent-team 三态词汇（pending/in_progress/completed）映射为 stage+owner 组合，`deleted` 映射为 tombstone | 需求 §3.2.1 "生命周期同 §3.1.1"；避免两套状态词汇；agent-team 的 "pending=未认领或已释放" 用 `stage=planning ∧ ownerId=undefined` 表达，不新增 phase |
| J4 | **任务必挂目标**：`goalId` 必填，指向 T0.1 目标树节点；任务间支持父子分解（`parentTaskId`）+ 执行依赖（`blockedBy`）双 DAG 边 + 规划期替代标注（`alternativeOf`） | T0.1 J4 已定"目标分解为目标、任务是执行单元 DAG"；需求 §3.1.3 任务图谱三关系在此落地；目标完成标准由任务 complete 的 evidence 汇聚满足（T0.1 J4） |
| J5 | **执行预算四维**：token / 工具调用 / 墙钟时间 / 人类注意力配额（T0.1 目标预算三维 + 工具调用维；round 帽留在目标层，任务不带） | 需求 §3.2.1 明列四维；T0.1 J5 预算三维为目标层口径，工具调用是任务执行层属性，不向上泛化 |
| J6 | **预算三区行为**（normal / converge / exhausted）由 taskPool 派生 `budgetZone` 字段，Harness 消费 | 需求 §3.2.3：接近阈值→收敛范围、停止新委派、优先可交付；耗尽→显式终态+未完成清单，绝不悄然截断（C5） |
| J7 | **任务本地路径 `localPath`** 为一等字段（workspace 相对、规范化、禁逃逸），与 advisory `writeScopes` 并存 | 需求 §3.2.1"任务本地路径锚定中间产物/日志/笔记"；是 T0.6 工作区语义理解的扫描起点；writeScopes 保留 agent-team 的重叠告警语义（只告警不阻断） |
| J8 | **周期触发自建**：任务携带 `schedule`（一次性起止）+ `recurrence`（interval/cron），run 模型 = 单任务记录 + `task_runs` append-only 运行历史；resident 调度 seam 归 `ctx.taskPool`（`due()`/`startRun()`/`completeRun()`），daemon 宿主挂 L1 Harness 常驻进程 | DSH `schedule` 是 session-local（after/at/every≥300s、无 cron、无跨会话池触发），`jobs` 进程退出即失——T0.0 缺口表已判"需进程级 cron 常驻调度器"；需求 §3.5 常驻进程本身是 L1 自建项，本规格只定义任务侧数据模型与调度 seam |
| J9 | **Agent 提议通道**：`proposedBy:'human'|'agent'` + `proposal.status`；P0 默认 agent 提议任务（含周期）未批准不可 claim/dispatch | 需求 §3.2.1"Agent 自主提议周期性任务，带标记+轻量审批（自主性级别可配）"；自主性级别属决策点⑤，P0 取保守默认（全审批），后续可配 auto-approve 规则 |

## 2. 状态模型

### 2.1 phase×stage（沿用 T0.1 §2，任务口径）

```
create ──► active(planning) ──claim──► active(executing) ──┐
   │                                    │                  │
   │                                 wait(dep)          verify
   │                                    ▼                  ▼
   │                              active(waiting) ──► active(verifying)
   │                                                      │
   └── pause/resume/block(code,msg) ◄── 任意 active 态     │
                                                          complete(outcome)
   任意非 complete 态 ──delete(reason)──► tombstone
```

- `active(planning) ∧ ownerId=undefined` = 可认领（agent-team `pending`）；`claim` 写入 owner 并推进 `executing`；`release` 归还该态（agent-team "released" 语义）；
- `blocked` 是唯一 durable stopped-by-problem 态，reason 携带稳定 lower-kebab code（如 `dep-failed`/`budget-exhausted`/`external-timeout`）；
- `complete` 必填 `outcome:'success'|'failed'`（C5：失败也是完成的一种，不可静默）；budget 耗尽触发的 complete 必带 `unfinished` 未完成清单（J6）；
- `delete` 保留 tombstone（TaskRef + reason），历史不丢、id 不复用、不占活跃容量、`blockedBy` 禁引用。

### 2.2 周期任务 run 模型（J8）

| 概念 | 规则 |
|---|---|
| 周期任务 | 单 TaskNode 携带 `recurrence`；每次触发派生一个 run（`task_runs` 追加一条，`runIndex` 单调） |
| run 生命周期 | `due()` 命中 → `startRun()`（stage→executing、开独立预算窗口、owner=dispatch 目标）→ `completeRun({outcome,consumed,notes})` → 按 recurrence 计算 `nextDueAt` 写回任务 |
| 失败计数 | `consecutiveFailures` 累加，success 清零——T1.2/T2.2 退役规则的输入信号（P0 只记录不动作） |
| 一次性任务 | 无 `recurrence`；`complete()` 直接终态，不派生 nextDueAt；其执行记录仍落 `task_runs`（runIndex=0） |
| 补偿语义 | cold/busy 时只补最新一次 due（借鉴 DSH schedule）；dispatch=同步入队，不假设模型应答成功 |

### 2.3 与 agent-team 词汇映射

| agent-team | taskPool | 说明 |
|---|---|---|
| `pending`（未认领/已释放） | `active(planning)` 且无 owner | readiness 派生（blockedBy 全 completed），非 durable 状态 |
| `in_progress`（带 owner） | `active(executing)` 且 owner=SessionId | claim/reassign 均 CAS |
| `completed` | `complete(outcome)` + evidence | 增加 outcome 与验证证据（T0.1 完成标准汇聚点） |
| `deleted` | tombstone + reason | 保留；禁引用；不占 maxTasks |
| `blockedBy` 无环校验 | 同左 + parentTaskId 并入环检查 | 父子+依赖合并图无环 |
| `writeScopes` 重叠告警 | 同左（advisory） | 只告警不阻断；另增 `localPath` 锚定目录 |

## 3. 数据模型

### 3.1 `TaskNode`（domain 记录，权威）

```ts type-equiv
/** 任务全快照。每次 accepted 变更 revision+1。 */
interface TaskNode {
  readonly id: TaskId                    // branded，单调分配 task-<n>
  readonly revision: number              // CAS：每次 durable 变更 +1
  readonly goalId: GoalId                // 必填：挂到目标树节点（J4）
  readonly parentTaskId?: TaskId         // 任务父子分解边
  readonly alternativeOf?: TaskId        // 替代路径标注（规划期， advisory，见 J4）
  readonly subject: string
  readonly description: string
  readonly phase: 'active' | 'paused' | 'blocked' | 'complete'
  readonly stage: 'planning' | 'executing' | 'waiting' | 'verifying'
  readonly outcome?: 'success' | 'failed'      // phase=complete 必填
  readonly blockedReason?: { code: string; message: string }
  readonly ownerId?: SessionId           // 认领者（子代理/主 agent）；planning 态为空
  readonly blockedBy: TaskId[]           // 执行依赖 DAG 边（无环、禁引用已删）
  readonly localPath?: string            // 任务本地路径（J7，workspace 相对）
  readonly writeScopes: string[]         // advisory 路径前缀（重叠告警）
  readonly priority: number              // 调度权重，默认 0，大者优先
  readonly schedule: TaskSchedule        // 起止（notBefore/dueAt）
  readonly recurrence?: TaskRecurrence   // 周期定义（J8）
  readonly runCount: number              // 已执行 run 数（一次性任务 ≤1）
  readonly consecutiveFailures: number  // 连续失败 run 数（退役信号输入）
  readonly lastRunAt?: number
  readonly nextDueAt?: number            // 周期任务下一次 due（durable）
  readonly proposedBy: 'human' | 'agent'
  readonly proposal?: { status: 'pending_approval' | 'approved' | 'rejected'; at: number; by?: string }
  readonly budget: TaskBudget            // 资源预算（J5）
  readonly progress?: string             // 进展备注（人类/模型可读）
  readonly createdAt: number
  readonly updatedAt: number
}
```

```ts type-equiv
/** 一次性起止；周期频率。 */
interface TaskSchedule { readonly notBefore?: number; readonly dueAt?: number }
interface TaskRecurrence {
  readonly kind: 'interval' | 'cron'
  readonly intervalMs?: number           // kind=interval，≥1000
  readonly cron?: string                 // kind=cron，标准 5 字段（最小粒度 1 分钟）
  readonly maxRuns?: number              // 可选：跑满即止（随后按一次性任务收敛）
  readonly endAt?: number                // 可选：到期停排
}
```

```ts type-equiv
/** 执行预算四维 + 消耗账本；每次 run 独立窗口，累计单独记。 */
interface TaskBudget {
  readonly tokens?: number
  readonly toolCalls?: number
  readonly wallClockMs?: number
  readonly attentionUnits?: number
  readonly consumed: { tokens: number; toolCalls: number; wallClockMs: number; attentionUnits: number }
  readonly zone: 'normal' | 'converge' | 'exhausted'   // 派生（J6），随 consume 重算
}
```

### 3.2 SQLite schema（`ctx.storage` sqlite domain，DomainSpec）

| 表 | 键 | 值 | 说明 |
|---|---|---|---|
| `task_nodes` | TaskId | TaskNode 全快照 | 权威状态；layout `single` |
| `task_history` | `TaskId#revision` | 变更记录 | 操作、变更者（human/agent/coach/scheduler）、diff 摘要、sessionEvent seq |
| `task_runs` | `TaskId#runIndex` | { startedAt, completedAt?, outcome?, consumed, notes? } | append-only 运行历史（周期任务每次 run 一条；一次性任务 runIndex=0） |

- domain version=1；`invalidRecords` 默认（拒绝打开）——任务是权威数据；
- 派生索引不建表：`due()` 启动时扫描 `recurrence≠∨ ∧ nextDueAt≠∅` 任务建内存定时器；进程重启后由 domain 权威重建（DSH schedule "cold 只补最新一次" 同款语义）。

## 4. 不变量与服务 API

### 4.1 任务不变量（加载即校验，违反拒绝打开）

1. **图无环**：`parentTaskId` 与 `blockedBy` 合并图无环；`alternativeOf` 不参与（advisory）；
2. **挂靠有效**：`goalId` 指向存在且 `phase=active` 的目标（complete/cleared 目标禁建新任务、禁 edit 改挂）；
3. **引用完整**：`blockedBy`/`parentTaskId` 禁引用 tombstone；
4. **CAS 严格**：mutation 必带期望 revision，不匹配拒绝（不静默重试）；
5. **终态完备**：complete 必填 outcome；blocked 必填 reason；paused/blocked 不可再 block/pause；
6. **认领前置**：claim 要求 `blockedBy` 全部 completed 且目标 `proposal.status≠pending_approval`（J9）；owner 唯一（reassign 仅允许原 owner 释放或人类/Lead 强制）；
7. **预算守恒**：子任务预算之和 ≤ 父任务剩余；根任务预算之和 ≤ 所属目标剩余（分配时检查，`consume` 账本向上汇聚）；
8. **路径安全**：`localPath`/`writeScopes` 规范化 workspace 相对前缀，禁 `..` 逃逸与绝对路径；
9. **周期派生正确**：`completeRun` 后 `nextDueAt` 与 `recurrence` 一致；`maxRuns`/`endAt` 到达即停排。

### 4.2 `ctx.taskPool` 服务方法

```ts type-equiv
interface TaskPoolService {
  create(caller, req: CreateTaskRequest): TaskNode     // goalId 必填；默认继承父任务/目标剩余预算
  edit(id: TaskId, ref: GoalRef, req: EditTaskRequest): TaskNode
  claim(id: TaskId, ref: TaskRef, ownerId: SessionId): TaskNode
  release(id: TaskId, ref: TaskRef): TaskNode          // owner 归还，回 planning
  reassign(id: TaskId, ref: TaskRef, ownerId: SessionId): TaskNode  // 人类/Lead 强制改派
  block(id: TaskId, ref: TaskRef, reason): TaskNode
  resume(id: TaskId, ref: TaskRef): TaskNode
  pause(id: TaskId, ref: TaskRef): TaskNode
  complete(id: TaskId, ref: TaskRef, completion: TaskCompletion): TaskNode
  delete(id: TaskId, ref: TaskRef, reason: string): TaskNode   // tombstone
  consume(id: TaskId, usage: Partial<Consumed4>): TaskNode     // 预算记账 + zone 重算
  get(id: TaskId): TaskNode | undefined
  list(filter?: TaskFilter): TaskNode[]                // goalId/stage/owner/priority/due 维度
  ready(filter?): TaskNode[]                           // 派生：可认领集（blockedBy 全 completed ∧ planning ∧ 无 owner ∧ 已批准）
  runs(id: TaskId): readonly TaskRunRecord[]
  due(now: number): TaskNode[]                         // nextDueAt ≤ now 的周期任务（调度入口）
  startRun(id: TaskId, ref: TaskRef, ownerId: SessionId): TaskNode    // 开 run 窗口
  completeRun(id: TaskId, ref: TaskRef, run: RunCompletion): TaskNode // run 收尾 + 派生 nextDueAt
  propose(caller, req: CreateTaskRequest): TaskNode    // Agent 提议（J9）
  approveProposal(id: TaskId, ref: TaskRef, approve: boolean): TaskNode
}
```

`TaskCompletion = { outcome: 'success'|'failed'; evidence?: string[]; unfinished?: string[] }`——`evidence` 是目标层 verifying 的汇聚输入（T0.1 J4），`unfinished` 预算耗尽时必填。

### 4.3 模型可见工具集（挂 `dsh-tda-tool-task-pool`，最小集）

| 工具 | 动作 | 说明 |
|---|---|---|
| `task_create` / `task_edit` | 建/改 | goalId 必填；agent 调用自动带 `proposedBy='agent'`+待批 |
| `task_list` / `task_get` | 读 | 返回裁剪视图（不含全快照 diff） |
| `task_claim` / `task_release` | 认领/释放 | Sidekick 执行入口（T0.5） |
| `task_complete` | 终态 | outcome+evidence 必填 |
| `task_propose` / `task_approve` | 提议/批准 | J9；approve 仅人类/Lead |

### 4.4 调度与预算行为（Harness 消费面）

- **dispatch 序**：`priority` 降序 → `dueAt` 升序 → `createdAt` 升序；tick 默认 1s（due 精度秒级），cold/busy 只补最新一次；
- **converge 区**（任一维度 ≥80% 消耗）：停止新委派（禁 claim/禁派生新 run）、收敛范围、优先完成可交付部分——Harness 组装派发计划前读 `budgetZone`；
- **exhausted 区**（≥100%）：禁 claim/start；进行中任务允许收尾为 `complete(outcome='failed', unfinished)`；新建任务拒绝并提示提额或人类介入；
- 调度 daemon 宿主 = L1 Harness 常驻进程（需求 §3.5 自建项），本规格交付 seam（`due/startRun/completeRun`）与数据模型，宿主进程模型未列入 P0（见 U1）。

## 5. 与 DSH 的对接点

| 对接面 | 机制 |
|---|---|
| 持久化 | `ctx.storage` sqlite domain（同 T0.1：`defineDomain`+zod，`ctx.storage.domain.table('task_nodes')`） |
| 模型可见性 | 每次 accepted 变更 append log-only session event `taskPool/change`（全快照）；模型上下文经 system-prompt section（`task:state`，紧随 `goal:state`）注入**当前焦点目标下 ready/executing 任务的裁剪视图**（id/subject/stage/owner/priority/due/zone）——主上下文只留决策与编排（C2） |
| 子代理派发 | claim 的 `ownerId`=子代理 SessionId（T0.5 Lead/Sidekick 在此挂接）；任务 `description` 是子代理唯一任务输入，回传仅结构化结论 |
| 目标层联动 | `goal-state` 插件订阅 `taskPool/change`：任务 consume 账本向上汇聚为 `goal.consume`（J5/J7 守恒）；目标 `verifying` 前置校验 = 该目标下无未终态任务（`taskPool.assertSettled(goalId)`，goal 服务调用） |
| 工作区理解 | `task.localPath` 是 T0.6 扫描起点；`writeScopes` 重叠告警数据同源 |
| 常驻调度 | 对照 DSH `schedule`（session-local/every≥300s/无 cron）与 `jobs`（owner fencing、进程退出即失）的缺口自建；dispatch 语义复用其"同步入队、cold 只补最新一次" |
| 轨迹资产 | 任务状态变更经 session log 落盘 → T0.7 fork/resume/replay 回放可直接还原任务推进时序 |

## 6. 验收标准（对 Gate G0 的贡献项）

1. **G0-①**：一个真实任务从 create→claim→execute→complete(success/failed) 全 phase×stage 走通，blocked reason 可路由；周期任务连续 3 次 run 的 due 派生与失败计数正确；
2. **G0-②**：kill -9 后重启，任务池/owner/预算账本/task_runs/nextDueAt 完整恢复，revision 不错乱；
3. 并发 CAS：两个并发 claim 同一任务，恰好一个成功（`TASK_STALE_REVISION`）；
4. 不变量 9 条各有拒绝用例（含注入式环、挂 complete 目标、引用 tombstone、预算守恒违反、`localPath` 逃逸）；
5. **预算三区**：消耗到 80% 触发 converge（新 claim 被拒并提示收敛）、100% 后 complete 必带 `unfinished`；
6. Agent 提议任务未批准不可 claim；批准后可入 ready 集；
7. 任务状态出现在模型上下文（裁剪视图），且可从 session log 重建（model-visible⟺logged 自检）。

## 7. 未决项

- U1（承 T0.1 U2，已关闭）：**多树所有权裁定 = 单工作区单池**——pool 无独立 scope 配置，ctx.storage domain 本身即工作区级权威；多目标树并存允许，任务经 `goalId` 挂属；
- U2：调度 daemon 宿主进程模型（单进程 tick vs 多 worker fencing）→ 归 L1 Harness 常驻进程设计（需求 §3.5 自建项），P0 先单进程 tick；
- U3：Agent 提议的 auto-approve 规则（自主性级别）→ 决策点⑤ / T2.6；P0 默认全审批（J9），schema 已占位；
- U4：`attentionUnits` 计量口径 → 同 T0.1 U3，T3.2 监督设计时定；
- U5：跨目标树的任务依赖（`blockedBy` 指向别树任务）——P0 允许但建议规划层避免，工具层不阻断；是否需要"跨树依赖需人工确认"留 T1.5 评估。
