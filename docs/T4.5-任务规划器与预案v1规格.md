# T4.5 · 任务规划器与预案 v1 规格（tda-planner 插件）

> 上游：《需求描述》v2.1 §3.1.3（长程规划：规划/执行强分离、contract、局部重规划、任务图谱三关系）、§3.2.1（任务树状态机）、《T0.2》（任务 DAG 权威/预算守恒/提议通道）、《T2.5》（工作流外部化/局部重规划范式）、《T4.2》（目标树来源）、《T4.1》（执行环：ready 消费者）、《T4.3》（图谱读模型：规划输入）、T1.4 J3（收敛/发散路由）、T1.3 J5（riskFlags）。
> 定位：P4 产品化第四份规格，补"任务规划、拆解与预案计划"缺口（2026-10-13 缺口对账：拆解边已有但缺规划器服务；`alternativeOf` 仅 advisory 标注，无预案激活语义；任务树编辑无计划快照）。
> 本规格是施工依据；实现后回填验收结果。

## 1. 设计裁定

| # | 裁定 | 理由 |
|---|---|---|
| J1 | **定位=目标→任务 DAG 的规划层**：上游=T4.2 确认的目标树（或人类直建目标），下游=T4.1 执行环（ready 消费者）。产出=`TaskPlan`（任务 DAG 提议+预算切分+预案），经审批后代建。规划器自身**零执行权**（deps 类型级无 claim/complete/dispatch） | §3.1.3"规划与执行强分离"的工程落点：规划产物是外部化可审计的快照（C3 精神），执行归 T4.1；规划器若持执行权=总编排器，违背防影子原则 |
| J2 | **LLM 分解 + 确定性质量门**：分解=Lead 角色派发（schema 白名单 `task-plan-proposal`，无任务指令类字段——同 T0.5 J4/T4.2 J4）；提交前必过 `qualityGate()` 五检查（见 J9）。LLM 是建议，闸门是权威 | 外部验证阀在规划面的落地（Voyager 铁律同款）；§5.4 控制流/数据流分离——规划文本不得携带"执行指令" |
| J3 | **计划快照不可变，与任务树实况分立**：每次提议落盘为不可变 `TaskPlan`（plan-<n>，含完整 DAG+预算切分+criteria 覆盖映射+生成元数据）；后续 `taskPool.edit` 直接编辑不失效快照。**偏差=执行实况 vs 快照预期**，喂 T2.5 J6 局部重规划与 T2.1 coach 复盘 | 缺口对账原状："任务树编辑是直接 CAS 改，无计划快照"——没有快照就没有"计划偏差"可言，局部重规划（§3.1.3）失去基准；快照不可变=回放可解释"当时的规划意图" |
| J4 | **预案状态机（alternativeOf 语义升级）**：每个 alternativeOf 边从 advisory 标注升级为带 `trigger`（触发条件）与 `carveOut`（预算转注比例 0<r<1）的预案；生命周期 `dormant → triggered → activated`（+vetoed/expired）。激活=CAS 切换：备选任务转 ready、主路径任务 `blocked(reason.code='plan-b-activated')`、主路径未耗预算按 carveOut 转注备选。**激活必经人类审批（v1），expired 可自动**（主路径成功=预案作废，低风险清理） | 需求 §3.1.3"替代路径（备选方案）"原只有标注没有语义——"何时切备选、谁裁决、切了怎么续"全无；v1 保守侧（决策点⑤）：结构性切换=人在场；作废=状态清理可自动 |
| J5 | **规划输入三路**：① 目标树（completionCriteria/约束/pinned，来自 T4.2 或人类）② 工作区语义（T4.3 图谱读模型的文件邻域摘要 + T0.6 inventory/hints，**全文不进规划 prompt**）③ 元思维拓扑路由（T1.4 J3：planning 阶段 divergent 优先检索规划拓扑、verifying 阶段 convergent 优先） | §3.1.4 元思维运用在规划面的消费侧落地；工作区输入防上下文毒药（同 T0.6 两层扫描纪律） |
| J6 | **规划提议必经审批后代建**：`confirmRequest`（T3.2 `kind='task-plan'`，v1 medium）→ 凭一次性 ResumeTicket `applyPlan` 按拓扑序（父先子后）`taskPool.create(actor='agent')`，代建任务带 `planId` 溯源（T0.2 v2 扩展字段） | 批量建任务=结构性动作（决策点⑤高风险需审的规划面落点）；代建收敛创建入口同 T4.2 J6 模式；中途失败已建保留+显式终态（C5，同 T4.2 不变量 11） |
| J7 | **触发检测=纯函数 + 双驱动**：`checkTriggers(now)` 确定性判定（task 状态×预算区×attempts×验证结果，同输入同输出）；驱动=订阅 `taskPool/change`（总线快速路径，T4.3 J3 同款裁定）+ tick 对账。检出触发只产 `TriggerEvent`（待批激活提议），**不自动切换** | 触发条件是可机读事实的机械组合，禁 LLM 猜（防"该切备选"被叙述操纵——同 T2.6 J9-③"先评分后叙述"纪律）；v1 激活全人类批（J4） |
| J8 | **局部重规划=supersede 链 + 增量应用**：T4.1 重试帽用尽/验证连续不过/触发条件异常 → `replan(goalId, deviation)` 产新 plan（`supersedes` 指旧 plan）→ 审批 → `applyReplanDiff` 只应用差异（新任务 create + 受影响任务 edit：stage/blockedBy/priority；**禁 edit objective/completionCriteria**（目标层权威）、禁 delete（删除归治理） | §3.1.3"局部重规划而非整体回滚"+ T2.5 J6 同款范式；禁整树重建=保护在飞执行与已耗预算的连续性 |
| J9 | **质量门五检查（确定性，禁 LLM）**：① criteria 覆盖——目标每个 completionCriteria 至少一个任务以其为证据路径（`criteriaRefs` 非空）② 预算守恒——Σ子帽 ≤ 父任务剩余、Σ根帽 ≤ 目标剩余（承 T0.2 J7 口径）、carveOut 转注后不超 ③ 依赖无环（含 alternativeOf 的合并图）④ 叶子可执行——每个无子任务节点 subject 非空 ∧ 有完成路径 ∧ localPath/writeScopes 合法（T0.2 既有校验复用）⑤ 预案覆盖——高风险任务（writeScopes 超 localPath 或 riskHint=high）必有 alternativeOf 或显式 `no-contingency` 理由 | 五查全覆盖 §3.1.3 的规划质量维度：覆盖性/资源性/一致性/可执行性/韧性；⑤是预案制度的执行保障——高风险无预案=无韧性规划，禁提请 |
| J10 | **与 T2.5 的分工**：规划器产任务级 DAG（C1 任务树权威）；workflow 产定义级 run（挂靠任务）。`PlannedTask.suggestedWorkflowDefId` 是**建议字段**，T4.1 路由时消费（匹配 consolidated def 优先）；规划器不创建 workflow 定义 | 防影子编排器（T2.2 J10 同款双向边界）；规划器→任务的建议通道 vs 工作流→步骤的执行通道，两层职责互不越界 |
| J11 | **立第二十二事件族 `planner/change`**：plan/contingency 为权威域记录（调度与切换决策不可由他域重放重建，按 P1 纪律 #12 判权威）；双写配对；entityKind=`plan`/`contingency`，businessId=planId/contingencyId | 同 T4.1 J9/T4.2 J9 裁定逻辑；预案激活是审计链关键节点（T3.2 auditView 需可定位"为何切备选"） |
| J12 | **规划器零注入直通、v1 零模型工具面**：规划结论不进主上下文（任务树经 T0.2 `promptSection` + T4.3 图谱既有面浮现）；模型面不发起规划（人/服务端入口，同 T4.2 J10） | 全局纪律 3；规划是低频高后果动作；防模型自规划自执行的闭环失控面 |

## 2. 状态模型

```
Plan:      draft ──qualityGate──► pending-approval ──approve+token──► applied ──(replan supersede)──► superseded
                                        │                              └── reject ──► rejected
                                        └── cancel ──► cancelled
Contingency: dormant ──trigger检出──► triggered ──approve+token──► activated
                 │                      │
                 │                      └── reject/veto ──► vetoed（reason 必填）
                 └──(主路径 completed)──► expired（自动，低风险清理）
```

| 状态 | 含义 | 进入 |
|---|---|---|
| `draft` | 计划已生成，质量门未过或未提请 | `plan()`/`replan()` |
| `pending-approval` | 已过质量门，审批中 | `confirmRequest()` |
| `applied` | 已审批并代建任务树 | `applyPlan()` |
| `superseded` | 被 replan 新计划取代（链指针） | 新 plan applied |
| `rejected`/`cancelled` | 人类驳回/取消（带 reason） | `reject()`/`cancel()` |
| `dormant` | 预案待命（触发条件未满足） | applyPlan 建 contingency |
| `triggered` | 触发条件满足，待批激活 | `checkTriggers` 检出 |
| `activated` | 已切换（备选 ready + 主路径 blocked + carve-out 记账） | `activate()` |
| `vetoed` | 人类否决（reason 必填） | `veto()` |
| `expired` | 主路径成功，预案作废（自动） | `checkTriggers` 检出 |

## 3. 数据模型

### 3.1 `TaskPlan`（domain 记录，权威）

```ts type-equiv
/** 计划快照：不可变（除状态/CAS revision）。 */
interface TaskPlan {
  readonly id: PlanId                     // branded，单调分配 plan-<n>
  readonly revision: number               // CAS
  readonly goalId: GoalId                 // 规划目标（v1=单焦点目标）
  readonly status: 'draft' | 'pending-approval' | 'applied' | 'rejected' | 'cancelled' | 'superseded'
  readonly kind: 'initial' | 'replan'     // J8
  readonly tasks: readonly PlannedTask[]  // 拓扑序（父先子后）
  readonly coverage: CoverageReport       // 质量门结果（J9；离开 draft 前必 passed）
  readonly generation: GenerationMeta     // provider/model/schemaHash/at（裁决随记录落盘）
  readonly deviation?: DeviationReport    // replan 必填（触发重规划的偏差证据）
  readonly supersedes?: PlanId
  readonly appliedTaskIds?: readonly TaskId[]   // applyPlan 后回填（tempId→真实 id 映射另存）
  readonly approval?: { approvalId: string; at: number; by?: string }
  readonly createdAt: number
  readonly settledAt?: number
}
```

```ts type-equiv
interface PlannedTask {
  readonly tempId: string                 // 't1' / 't1.1' …
  readonly parentTempId?: string
  readonly subject: string
  readonly description?: string
  readonly completionCriteria: readonly string[]      // 非空（质量门④）
  readonly blockedByTempIds: readonly string[]
  readonly alternativeOfTempId?: string               // 预案边（T0.2 v2 结构，见 §3.4）
  readonly contingency?: { trigger: PlanTrigger; carveOut: number }  // 0<carveOut<1
  readonly budget?: TaskBudgetCaps
  readonly priority?: number
  readonly localPath?: string
  readonly writeScopes?: readonly string[]
  readonly suggestedWorkflowDefId?: string            // J10 建议字段（T4.1 路由消费）
  readonly riskHint?: 'low' | 'high'
  readonly criteriaRefs: readonly string[]            // 覆盖的目标 completionCriteria 索引（质量门①）
  readonly noContingencyReason?: string               // 高风险无预案时的显式理由（质量门⑤）
}
type PlanTrigger =
  | { kind: 'task-failed'; taskTempId: string }
  | { kind: 'task-blocked'; taskTempId: string }
  | { kind: 'budget-zone'; zone: 'converge' | 'exhausted' }
  | { kind: 'verify-failed'; attempts: number }
/** 质量门报告（确定性，禁 LLM）。 */
interface CoverageReport {
  readonly passed: boolean
  readonly checks: readonly { id: 'criteria-coverage' | 'budget-conservation' | 'dag-acyclic'
                            | 'leaf-executable' | 'contingency-coverage'; passed: boolean; detail: string }[]
}
/** 重规划偏差证据（T4.1/执行侧产生， planner 只消费）。 */
interface DeviationReport {
  readonly kind: 'retry-exhausted' | 'verify-failed' | 'budget-zone' | 'trigger-anomaly'
  readonly taskId: TaskId
  readonly detail: string
  readonly at: number
}
```

## 4. 不变量与服务 API

### 4.1 不变量（加载即校验 / 运行时强制）

1. **质量门**：plan 状态离开 `draft` 前 `coverage.passed=true`（五查全过；任一不过禁提请）；
2. **审批门**：`applyPlan`/`activate` 必经对应 kind 批准 + 一次性 ResumeTicket；v1 无自动路径（`activationAutonomy='human-only'`）；
3. **拓扑序**：`applyPlan` 父先子后；中途失败已建节点保留 + plan 落 `cancelled`+unfinished 清单，禁静默回滚半棵树（同 T4.2 不变量 11）；
4. **零执行权**：deps 无 `taskPool.claim/complete/startRun`（类型级）；规划器只经 `create/edit`（受审批门约束）+ 只读面；
5. **溯源**：代建任务必带 `planId`（T0.2 v2 加载期断言对偶：`planId` 存在 ⇒ plan.status='applied'）；
6. **预案引用完备**：`alternativeOf.taskId` 存在 ∧ `contingencyId` 与 `planner_contingencies` 对账（planner loadChecks）；legacy 边（无 contingencyId）禁入状态机；
7. **预算守恒**：质量门②承 T0.2 J7 口径（Σ子帽 ≤ 父任务剩余、Σ根帽 ≤ 目标剩余）；carve-out 转注后备选任务帽不超主路径未耗余额；
8. **supersede 单向**：`replan` 只产新 plan（`supersedes` 指针）；旧 plan 的 applied 任务编辑只经 `taskPool.edit` CAS（stage/blockedBy/priority 三类，禁 objective/completionCriteria）；
9. **触发检测确定性**：`checkTriggers` 纯函数（task 状态×zone×attempts×验证结果），同输入同输出（单测逐分支）；
10. **expired 自动、activated 需批**：`autoExpire=true` 时主路径 completed ⇒ dormant 预案自动 expired（带 reason）；activated 永需人类 token；
11. **双写配对**：plan/contingency accepted 变更 ↔ `planner/change` 逐一配对。

### 4.2 `ctx.taskPlanner` 服务方法

```ts type-equiv
interface TaskPlannerService {
  initialize(): Promise<void>                                    // 启动重建 + 对账（先于不变量注册）
  proposePlan(goalId: GoalId, inputs?: PlannerInputRefs): Promise<TaskPlan> // 生成+质量门（J2/J5；§4.2 原稿 plan(goalId) 与 plan(id) 同名重载在对象字面量实现不可行——TS 重复键，按仓库惯例生成器定名 proposePlan）
  qualityGate(planId: PlanId): CoverageReport                    // 纯函数（可单测）
  confirmRequest(actor: IntakeActorLike, planId: PlanId): Promise<{ approvalId: string }>  // T3.2 kind='task-plan'
  applyPlan(planId: PlanId, token: string): Promise<readonly TaskId[]>    // 凭票拓扑序代建（J6）
  replan(goalId: GoalId, deviation: DeviationReport): Promise<TaskPlan>   // J8 supersede 链
  applyReplanDiff(planId: PlanId, token: string): Promise<DiffReport>     // 增量应用（新 create+受影响 edit）
  contingencies(planId?: PlanId): readonly PlanContingency[]
  checkTriggers(now: number): readonly TriggerEvent[]            // 纯函数检测（J7）
  runTriggerScan(now: number): Promise<readonly TriggerEvent[]>   // 扫描+autoExpire 自动清理（tick 挂点，不变量 10 的"自动"落点）
  requestActivation(contingencyId: ContingencyId): Promise<{ approvalId: string }>  // kind='plan-activation'
  activate(contingencyId: ContingencyId, token: string): Promise<PlanContingency>   // 切换+carve-out 记账（J4）
  veto(contingencyId: ContingencyId, reason: string): Promise<PlanContingency>
  plans(filter?: PlanFilter): readonly TaskPlan[]
  plan(id: PlanId): TaskPlan | undefined
  params(): PlannerParams
  setParams(actor: 'human' | 'lead', patch: Partial<Omit<PlannerParams, 'revision'>>): Promise<PlannerParams>
}
```

- **LLM 工序通道**：`plan`/`replan` 的分解走 T4.2 J6 同款独立 intake/planner seam（内部=DSH subagents one-shot 复用 T0.5 隔离契约；不经 task 记录——规划期任务尚未存在）；收敛评估随 DSH 真装配（T4.2 U6 同款）；
- **激活切换序（activate）**：① CAS 备选任务 `stage→planning`（转 ready 候选，owner 不预设）② CAS 主路径任务 `block({code:'plan-b-activated', message})`——**已终态主路径跳过**（task-failed 触发时主路径已 failure 终态，T0.2"终态不可变"禁 block 也无必要；该标记仅对活着的主路径，IT15 装配期裁定）③ `taskPool.consume` 对主路径未耗余额按 carveOut 转注备选任务预算帽（`edit` 提升帽）④ contingency→activated 双写。全程 CAS，任一步 STALE 即整体重试由调用方决定（禁部分切换后静默继续——切换是结构性动作，失败必显式）；
- **装配层接线**：`checkTriggers` 挂 `runtime.tick()`（同 T4.1/T4.3 tick 扩展）；`taskPool/change` 总线订阅置脏；
- **无模型工具**（J12）。

## 6. 验收标准（对 Gate G4-② 的贡献项）

1. **质量门**：五类坏提议被确定性拒——criteria 无覆盖 / 预算切分不守恒 / 合并图成环 / 叶子不可执行（无 subject 或 localPath 非法）/ 高风险无预案且无显式理由；过闸才可 `confirmRequest`；
2. **代建溯源**：批准后按拓扑序建任务树，每个任务 `planId` 非空（T0.2 v2 加载期断言）；`appliedTaskIds` 回填；任务树过 T0.2 全部既有不变量；
3. **预案触发**：主路径任务 failed/blocked/预算进 converge/验证不过 → `checkTriggers` 检出对应 `TriggerEvent`（纯函数同输入同输出）；触发只产待批提议不自动切换；
4. **预案激活**：人类 token → 切换四步（备选转候选/主路径 blocked[plan-b-activated]——已终态主路径按 IT15 裁定跳过/carve-out 转注记账/contingency→activated）全部落定；任一步 STALE 失败⇒显式终态禁部分切换；
5. **预案否决/过期**：vetoed 带 reason；主路径 completed ⇒ dormant 预案自动 expired（带 reason，无需审批）；
6. **局部重规划**：T4.1 deviation（retry-exhausted）→ `replan` 产 supersede 新 plan → 审批 → `applyReplanDiff` 只建新任务+edit 受影响任务（禁动 objective/completionCriteria、禁 delete）；在飞任务执行不中断；
7. **双写与回放**：plan/contingency 变更 ↔ `planner/change` 逐一配对；`replayCheck` 覆盖 planner 族零违规；kill -9 于 pending-approval 恢复（token 过期回 pending 可重签，T3.2 J4）；
8. **零执行权**：规划器全生命周期内零 `claim/complete/startRun/dispatch` 调用（对账测试：deps 注入面无这些方法）；
9. **legacy 兼容**：v1 存量裸 `alternativeOf` 行迁移后打 `legacy-advisory`，不参与状态机、不出现在 `checkTriggers` 结果。
